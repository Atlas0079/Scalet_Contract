# 阿利贝地图数据定义

本约定定义单层地下城市的空间、物件、灾后状态、容器、照明与供电数据，供生成器、地图查看器及 Godot 漫游共同读取。地图使用 version 22，重新生成当前数据；不读取旧版本地图。实现验证另见本地验证记录。

## 空间与归属

每格1米；x、y 为水平面米格左上角，w、h 为整数格占地；Godot 的水平面对应 x、z。worldOrigin 保存本图左上角的世界坐标。tiles 保存地面用途，edges 保存格边墙门，buildings、rooms、roads、openSpaces、station、tram、portals 保留既有城市结构。

室内物件保存在 rooms[].objects，室外物件保存在 streetObjects；位置和占地仅保存一次。全部物件具有全图唯一且可引用的 id，以及 roomId、buildingId 或 spaceId。runtime.objects 是派生的运行时索引，不重复导出。纯装饰保存在 decorations，可以与实体、灯具投影重叠，不进入阻挡索引。

## 场景物件与移动属性

场景物件包括家具、设备、车辆、掩体、尸体堆和落石。记录 id、type、name、family、x、y、w、h、rotation、bottom_m、height_m、classification、origin、condition，以及三类阻挡。height_m 是竖直总高度，h 是水平占地。位置与占地在载入时换算为现有 SCEntity 的 position_m、footprint_m。

installation 为 anchored 或 free；mobility 为 none、push_drag 或 carry；pickup_mode 为 none 或 inventory；mass_kg 为本体质量，内容物质量由现有物品目录另外计算。固定安装、能否移动本体、能否收入物品栏和容器能力分别定义。固定物件 classification 为 fixed，可移动或散落物为 dropped；origin 独立记录 scene、unit_death 或 dropped。尸体堆没有锚固但 mobility 为 none，归 fixed。移动属性为现有系统提供条件数据，本轮不新增推拉和拖拽交互。

## 结构与遮挡

structure.kind 为 solid、slab、frame 或 pile，parts 保存少量轴对齐盒子。每个部件有 id、offset_m、size_m、protection、blocks_sight、blocks_projectile。offset_m 相对于物件占地左前角及底部，轴顺序为水平x、竖直y、水平z；size_m 为宽、高、深。部件必须位于物件的总体范围内，单位为米，允许小于1米。总占地仍按米格布置，移动按整件占地保守处理，视线和动能弹道按实际部件检查。

桌子由薄桌板和桌腿组成，空隙不命中；空货架由立柱和层板组成；柜台用封闭实体；尸体堆与落石使用堆积实体。物件高度不把内部空隙填成实心。光线、视线和弹道使用相同结构，但部件的光学遮挡与弹道相交能力分别定义。纯装饰不参与物理查询。灯具锚定墙或顶板，不占地面通路。

## 耐久与简化防护

damageable、max_durability、durability 和 destroyed 沿用 SCEntity 的耐久与受损接口。场景物件防护使用统一游戏数值，不换算真实材料、厚度或角度。防护在一个状态内保持固定，耐久归零后切换 destroyed 定义的高度、结构、防护和阻挡，保留同一实体与 contents。残骸可以继续存在。

部件 blocks_projectile 表示参与弹道命中候选，最终是否截停取决于穿透值P与部件防护R。R大于0且P不高于R时截停；P高于R时继续飞行，剩余穿透为P−R，伤害按剩余穿透与进入前穿透的比例保留。R为0时子弹直接通过，穿透与伤害不衰减。命中的可破坏物件先承受本次入射伤害；打坏物件不会追溯取消本次原状态的防护。每颗子弹对同一部件只结算一次，跨帧仍在部件内部时不重复扣除；同一时间步内允许穿过多个部件，不跳过剩余飞行时间。自动开火及候选射击位置使用同一防护比较；预测不扣耐久，并保守按当前结构判断，不预先假定障碍被打坏。

弹药穿透40、伤害35命中防护10的部件后，剩余穿透30、伤害26.25；再命中防护30的部件时截停。这些是说明规则的游戏数值，物件初始数值属于待校准原型参数。岩体、地面与现有格边结构墙继续保守截停；本轮实现动能弹丸对场景物件及尸体的穿透；角色护甲继续使用既有防护结算，命中活体后弹丸结束。角色护甲耐久和多层贯穿的进一步调整不纳入本轮。

## 容器与两种尸体

可搜刮场景物件增加 loot（kind、searched），contents 以物品唯一id为键，记录 id、kind、quantity。物品类型引用现有目录，内容允许为空。搜索和拿取复用 SCLoot；搜空只改变物品内容，不移除几何或掩体。

地图预置尸体 origin 为 scene，classification 为 fixed，mobility 为 none，附带 container。它无需创建一个活体单位。尸体堆同样属于固定场景物件，可同时附带容器和按实际高度计算的掩体结构。

单位死亡尸体 origin 为 unit_death，通过 SCLoot.corpse 保留原角色实体、身份、位置和装备；作为 dropped 物件记录可拖动属性，实际拖拽交互另行接入。弹道检查其死亡后的低矮实体，不再次按活体结算伤害，也不复制出另一份身体或装备。

## 灾后场景与房间

正常用途及合理密度先生成，再应用灾后事件。scenes 记录 id、kind、name、位置范围和关联房间；sceneId 将撤离、翻找、临时占用、检查站、收殓、车辆弃置和坍塌等组合联系起来。同一建筑的状态有相关性，局部保留变化。

room.condition 保存当前状态，room.usable 表示是否仍可使用。整间坍塌仅选取不承担公共交通、无外门的末端房间；房间原用途和占地保留，内部家具移除，落石实体表达不可通行范围。未坍塌房间保留正常家具和操作空间。街道障碍优先沿路缘布置，保留完整绕行空间。必要路网、快速旅行点、中央站换乘及可用房间继续检查连通；被明确封闭的坍塌房间单独统计。

城市发展年份描述建城历程，灾后场景描述同一灾后时点。二者分别记录，不将城市发展年份解释成灾后经历年数。大停电后约30天的环境以近期断供、战斗、搬迁、搜刮和局部维护为主。

## 灯具与供电

灯具仍是空间物件，附带 light。light 记录 mount（wall、ceiling）、方向向量 direction（三维 x、竖直y、平面z）、range_m、energy（相对强度）、color、cone_degrees、powerZoneId、source（grid、battery）、switchedOn、health（intact、damaged、broken）。墙灯记录实际锚定格边，x、y 为所属锚定格；发光点由格边和朝向推导到墙内侧0.12米。顶灯的发光点在所属格中心，记录空间上方高度。灯位依房间用途、街道、路口、公共空间和地质边界生成。

powerZones 保存 id、name、供电状态 powered、供电来源 sourceId 与建筑关联。区域照明具有连续性，独立电池可在区域断电时继续供电。最终发光由电源可用、开关打开和灯具未损坏共同决定，恢复区域供电不修复坏灯、不打开关闭的灯。地图保存初始状态；预览通断电仅修改预览状态，明确恢复初始状态后可还原。导出仍为生成的初始数据。

所有灯具在全图生成。lighting 保存 ambient、sampleHeight_m、darkRecognition_m、maxRecognition_m、最低识别亮度等本轮原型参数。由同一组灯具和遮挡几何派生照度，不导出第二份独立灯光位置。门开闭应参与重新计算。灯光不能穿透岩体、墙或高于光线的障碍；低物件按实际高度截光。查看器为直接照明近似，Godot 读取相同灯具记录渲染实际光源；近似照度不以物理勒克斯标示。

## 查看与可见性

查看器叠加层包含场景物件、战术障碍、纯装饰、灯具；照明视图显示实际明暗，供电视图显示区域归属及状态。物件所属图层不决定其能力。每个物件均可检查空间、阻挡、容器、场景和供电属性。

视野预览设置观察位置和观察高度，使用墙门、岩体、实体高度检查几何视线，再按目标处照度和距离计算识别。编辑全览、几何可见与能够辨认分别展示。观察距离和低照度参数为可调试原型值；角色传感器、夜视及完整战斗平衡待后续确定。生成与查看本轮打通数据和预览，现有战斗角色感知不得用独立的装饰亮度冒充已接入全城照明。

## 状态与校验

初始地图只保存生成时状态。游玩中容器内容、受损状态、灯开关与供电状态更新同一对象；禁止重复生成第二份尸体或容器。

校验全图 id、归属引用、物品类型、供电引用、锚点、量纲及边界；检查可用房间、物件操作面、公共路网和快速旅行点。纯装饰及悬挂灯具允许叠加，不作为地面占用冲突。可见性与照明另外检查穿墙、方向、遮挡高度、区域通断电、坏灯与关闭灯的差异。自动检查和视觉验看分别记录。
