# 阿利贝：单泡地形与城市生成原型

运行 `python3 serve.py`，打开 http://127.0.0.1:8770/?view=tiles 。地图每格1米，所有建筑只有地面层。原型尚未接入 Godot 的角色、战斗、经济或阵营系统。

## 查看

“规划与自建”用蓝色显示统一设施及规划沿街建筑，土黄色显示居民自建。自建部分没有预先分配的街块。

“原始地质”显示宽度变化的天然洞道、少量较大洞室和更多孤立小空腔。“开发范围”显示实际采用的天然空腔和人工开凿；滑杆按开凿成本顺序分段展示，不表示真实建设年代。未使用的小洞穴仍保留在原始地质中。

“开凿与街块”查看规划用地；“建筑用途”比较用途；“交通网络”查看街道电车和预览出口。“中央车站”定位偏中心的车站。“1米格”查看墙门、房间及图标。目录可以搜索机加工、精密零件、翻修、医院等设施；选择设施后可以查看布局、人员与物流关系、多个外部入口，点击房间进一步放大。

“勘测范围”包含城区以外的岩体和空腔。更换种子重新生成；JSON 导出完整数据，PNG 保存当前地图画面。

## 地质与开发机会

先生成岩性，再分布多个互相隔离的小洞系。每个洞系通常包含4–7个局部节点，用一棵短连接树组织分叉，少量洞系增加一个回环。天然连接不会跨洞系，通道和洞室加宽时也保留洞系之间的岩层。另生成更多孤立小空腔。

原始地质与人工建设分别统计连通性。城市可以在建设阶段打通邻近洞系，原始地质层仍保留开发前的隔离关系。
原始地质独立保存。岩体分为可开凿、高成本和保留三类，保留岩体不得挖穿。当前主洞道半径参数为5–8米，支洞为3–5米，实际轮廓有局部变化。孤立小空腔按勘测尺度提出数量目标，受净距和岩性限制，未强制保证固定数量。

从中部有足够净空间的天然洞室选取初始落脚点，按洞道利用、岩层厚度、硬度和距离评估扩挖。计算约30%勘测面积的开发机会范围，作为当前原型的规模上限。机会范围不等于已经挖开的地面：自建区域只有住户及其通道确实落位时才提交新增开凿；失败的候选通道恢复原状态。未被建设连接的空腔不标为已建城区。

该预算尚未由人口或设施供需推导。地质与建设是玩法结构生成，不是现实地质或工程模拟。

## 两种建设过程

### 统一建设区

先确定主街、中央站与预览接口，再为大型设施提出功能体量候选。候选由不同大小、位置和方向的工作厅、附属空间及连接通廊组成。选址检查实际体量占地，不要求把包围长方形挖空。

建筑、入口及作业区作为一个建设项目共同验证。候选位置必须能从每个外部门接到现有主街网络；检查时已将候选建筑作为障碍，避免门外有空地却被建筑与岩体夹死。不成立的位置换址或调整规模。

接入道路优先并入已有路网，每段记录服务的项目和入口。人员入口设置出入通路，收发货门设置局部作业区。取消固定外围环路；墙外无用途的地面不因处于包围框内就自动成为院落。

规划范围沿实际体量、入口和服务道路建立，大型设施及其入口周边不允许居民自建侵入。周边生活街与支街在规划范围内组织，剩余区域再参与居民扩挖。
### 居民自行扩挖区

从已有通路边缘提出住户或作坊候选。候选可以直接沿通道增建，也可以先提出一段短的直行或折角出入巷。只有对应建筑能够落位，通道与房间才一起保留。后续住户从已有共用通道继续增建，形成深巷、分叉、尽端、共享入口及未挖穿的岩体。

通道使用正交格子段，不以随机斜线表达混乱。每条新增出入巷记录其服务的建筑和生成顺序，自建建筑的 blockId 为空。自建区不先切成矩形地块，也不把剩余岩体统一清空。

## 街道与电车

街宽范围为3–8米：居民共用巷主要3–4米，规划支街3–5米，生活街4–6米，公共联络街5米，承载双向电车的主街8米。偶数宽度按实际格子带处理。

轨道是街道路面上的叠加结构。双向两线的轨道通道共宽4米，中心分别偏离共享中心线1米，全部轨道占格依旧属于 STREET。电车主街与其他交通使用同一条街道，并接入支街；建筑不得占用轨道扫过的范围。

路线先去除细小折返，再用相切圆弧连接直线段，预留完整转弯范围。这里的曲线参数用于原型表现，尚未验证具体车辆尺寸、动力学、道岔或调度。

每张单泡地图有一座偏中心的车站。当前西、东两个接口均标记为 preview-fixture，作为单泡预览条件；邻接泡、出口数量及方向的正式提供者是未来的殖民地生成器。本原型未实现殖民地拓扑。

## 大型设施与内部结构

当前尝试生成宿舍、医院、物流综合体和三种生产设施。工业设施先组织收货 / 材料、加工 / 仓储、装配 / 整备、成品暂存等体量，再附接人员服务翼。各体量可以直接相接，也可以由短的室内通廊连接；部分加工厅段无墙贯通。尺寸、附接方向、错位和连接长度参与变化，外轮廓由这些部分形成。

宿舍与医院采用公共中枢和长短不同的功能翼，分别组织主通廊、翼部通廊和房间。所有空间仍在同一地面层。

门根据实际外墙及门外净空选择，材料入口接收货道路，成品出口接发货作业区。机器与货物布置前预留通行空间，宽货运门后的路径加宽。装配和检验区使用工作台及检测设备，与加工区的机床和切割设备区分。

包围范围与实际室内面积分别统计。未占用的部分不自动清成院落，收发货作业区只在具体货门外安排。
## 格子、墙门与内容

普通墙和所有门位于格子边界；显式指定的特殊厚墙占整格。宽门由连续的格边组成，记录同一开口、宽度和用途。房间净面积按地板格计算，物件用整数格占地和图标表示。

机器人私营维修、配件、电源和拆件业务与仿生人维修分开。仿生人设备只出现在医院管制房间及符合条件的少量隐蔽诊所。设施数量和服务范围尚未按人口平衡；不能落位的设施保存在 unplacedServices 中。

## 文件与数据

- planning.js：岩性、洞道、开发机会范围、规划范围、主街及电车、设施选址和规划街块。
- generator.js：蓝图编译、沿街落位、居民扩挖、格边墙门、家具、导出与通行验证。
- complexes.js：大型设施的多种布局、人员和货物流线、专业服务蓝图。
- blueprints.js / content.js：基础平面与房间连接、建筑和物件目录。
- viewer.js / viewer.css / index.html：分层查看器。
- icons.js / ICON_LICENSE.txt：本地缓存的 Lucide 图标及许可。

JSON version 11 新增或细化 developmentEnvelope（开发机会范围）、plannedMask / informalMask（建设方式范围）、growthSummary、station、tram 的连续曲线和占格、设施布局及门用途。规划项目还保存 plan（功能体量组合）、outline（真实外轮廓）、accessRoadIds（接入与入口道路）；terrainStats 保存小洞系数量、实际连通部分和最大连通部分占比。cityMask 表示当前已连接的建设空间。excavation 的1/2/3/4分别为规划扩挖、综合体用地、交通建设、居民扩挖。

命令行：`node generate.cjs SEED 960 output.json`。源码与使用说明纳入版本管理。测试脚本、验证记录、截图、运行日志及导出数据仅保留本地。
