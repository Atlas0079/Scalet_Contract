# 阿利贝：地下城市生成器

运行 `python3 .art-preview-local/bubble-generator/serve.py`，打开 http://127.0.0.1:8770/?view=tiles 。每格1米，当前只生成地面层。

## 生成顺序与空间目标

原始岩体 → 中央车站选址 → 初期政府街坊 → 居民持续建设与后续政府规划循环。

同一张地图同时呈现岩体内开凿、天然空腔内建设、共用洞厅内建设和沿洞壁混合扩挖。规整的规划街道与曲折的居民小路并存；建筑、房间及其内部连接具有明显的尺度与组织差异。

第0年表示初期政府规划建设完成。每个街坊作为完整项目选择位置：道路、地块、内部房间和公共空间共同安排，预算能够完成整个项目时才施工。初期街坊围绕车站分布，车站位置由天然落脚点、站场条件、周边可开发空间共同决定。选址比较完整站场和周边可用空腔，优先选择能承接城区的天然空间，不要求车站落在原始地形的几何中心。

政府街坊从同一套街道节点与边界道路选址，相邻街坊引用同一条路。规划区可以分离，相邻关系作为成本偏好；独立项目需接入已连通的公共路网，新增连接街与街区一并检查占地和预算。共享路口结合周边地质选位，街道在整体方向约束下比较空腔利用和开凿成本，允许轻微转折；整段道路和两端都检查占地净空。规划选址不再预设四个独立矩形环路，也不为生产街坊指定天然空腔占比。

街坊边界由实际道路围合，内部按通路和可建范围布置不同规模的功能单元。较大街坊预先安排内部街道，避免产生没有临街面的深处空地。生产与公共设施先安排主要功能，再填充配套建筑；未能容纳所需设施的候选地点不施工。剩余岩体保持未开挖状态，不再将边角普遍铺成院地；天然空腔保留原地质属性。路口广场和公园在建筑填充前作为明确公共项目选址。街坊以实际边界格子统计室内、道路和公共空间，包围矩形只用于显示范围。界面显示建成时的占地比例。

第1年起居民持续扩挖、沿街填充、加建与分户；政府按设定间隔获得新的规划机会。居民比较沿街填充和房屋与接路的联合方案：先提出完整房屋占地及入口，比较可容纳户型的空腔和岩体，再为候选房屋寻路。房屋、主接路、侧后出口同时通过占地和预算检查后才施工；失败试算回退，不留下无服务对象的巷道。侧门、装卸门的场内通路不作为新建筑的开发临街面。发展范围由需求、周边配套、实际通行距离和工程量形成。铁路沿线具有通行作用，客运收益来自已启用站点，货运收益来自中央站和物流分拣设施。

## 人口需求与具体用途

输入分为城市设定与高级生成参数。城市设定包含泡的主要职能、初始人口及年增长率、家庭和流动人口比例、居住宽裕程度、主导产业、就业与客货流需求、公共服务水平、居民活动和政府政策。单身工人人口由其余比例形成。地质、建筑尺度、施工速度和道路等放在高级参数中。

程序按年份计算家庭居住、工人居住、短住、就业、物流、供应、医疗、教育等需求，再与已建空间的规划容量比较。政府考虑下一规划间隔内的需求，居民主要响应当年缺口；政府完成街坊时允许形成住宅储备。规划容量是用于生成比较的近似值，尚未模拟具体居民、实际经营或完整经济。

用途目录区分家庭住宅、集体宿舍、短住旅舍、制造厂、小型加工工坊、维修作坊、机器人检修、物流分拣、沿街货栈、食品杂货、小餐馆、食堂、食品加工、诊所、医院、学校、公共浴室、环境维护、治安消防、行政办事与社区活动。不同用途安排相应的房间、设备、出入口和容量；主导产业影响制造厂的生产空间和维修需求。建筑检查面板显示用途、规划容量、建造时的全城需求和选址依据。

选址距离沿当年的四邻域道路网络计算。周边居住、就业和各用途供应采用96米步行范围、随距离二次衰减的容量估计；与同一范围的需求比较，形成生活服务的供需因素。住宅偏向就业、生活服务和已有聚落，短住偏向客运站点，生产与仓储偏向货运和产业联系，服务设施偏向居民和供需缺口。不同用途采用不同权重，单位面积建设成本和场内接路通行同时参与评分。扩挖方案额外记录新增巷道建设与绕行代价，并与沿街填充比较；近似同价的合理方案通过种子保留变化。居民选址代价过高时可以不建设并保留全城需求缺口。规划项目允许配套随整个街区形成，仍需真实接路和足额预算。

这些因素是生成用的容量与可达性近似，没有分配具体居民或模拟真实经营。选址记录保存建造当时的条件，不随后来的道路和建筑变化重写。

“指定或禁止的设施”支持按用途指定数量或禁止生成。指定项目优先安排，场地与预算不足时显示未满足数量。人口、就业等比例在界面显示为百分数，参数 JSON 保存为 0–1 的份额。

## 政府分期开发与拆迁

默认每 8 年评估一次，允许前后浮动 2 年；间隔、浮动、每期项目上限和公共投入均可调整。每期项目上限设为 0 可关闭后续政府开发。需求已基本覆盖时可以不建设，本期预算不强制转化成新街坊。

候选规划区比较天然空间、用途适宜性、与城市的交通联系、相邻道路复用、连接工程、拆迁工程量及旧区改造倾向。自建房的阻力由居住容量、建成年代、经营或服务影响及居民组织程度共同决定；政府执行力度和安置投入影响清退可行性。难以清退的房屋继续约束道路和新建筑，未建成的路口可以轻微调整。新规划可以保留部分旧房，也可以因无法形成完整项目而延期到后续机会重新评估。已有政府建筑、公共项目和主干基础设施不在自建房清退范围内。

清退减少相应用途容量，人口需求保持不变。受影响住户进入安置统计，新增和已有空余住房容量用于安置；商业服务缺口重新参与用途选择。拆迁记录保存年份、原建筑、影响容量、阻力、工程量与地基坐标。已经开挖的地基不会变回天然岩体：可通行部分作为改建场地，封闭结构残余显示为旧墙基。

年表重现当年状态，早期年份保留当时尚未拆除的房屋。侧栏提供人口与用途需求、政府开发与拆迁记录，并可定位每一期规划区。

## 原始岩体与空腔

岩体占主体，天然空腔只占少部分。地形使用连续的岩性、弱层和两组裂隙方向场，沿弱面形成狭长空隙、交汇分支、局部宽大洞室和不同形状的孤立空间。局部发育条件限制洞系范围，岩体强度变化保留岩脊与岩柱。地质不通过随机圆洞和固定宽度走廊拼接。

这一形态模型参考裂隙、层面与岩性控制洞穴形态的关系，参见 [USGS 地质控制研究](https://www.usgs.gov/publications/geologic-controls-cave-development-burnsville-cove-bath-and-highland-counties-virginia)。它没有模拟完整的水文、化学或地质演化过程，也没有据此给阿利贝指定新的岩层成因。

原始地质按世界坐标稳定采样。预览保留至少约480×480米的原始岩体背景，建设超出范围时再扩展，并保留周边岩体；原始地质视图中浅色是空腔，深色是岩体。天然空腔占比随种子和参数变化。

## 完整街坊与房屋内部

建筑由相连的功能空间组成，外形可以出现退让、折角和不同进深的支翼。住宅通过起居、卧室、生活设施和公共通廊组织大小不同的住户；医院采用候诊、分诊、诊疗支廊、病区、药房及护理准备；厂房采用人员服务带、作业翼与独立收发货区。大作业空间保留大房间，内部容量随用途和可用空间安排。

室内按床位、餐桌组、工作位、储货组和设备组布置，单元包含操作余量。普通功能房间短边至少 3 米，公共及户内过道至少 2 米；主廊按建筑用途与规模选择宽度，默认户内过道 2–3 米、公寓主廊 2–4 米、宿舍及公共主廊 3–5 米，高级参数可调整上限。同一条主廊保持连贯宽度，房间随之适配；厕所、淋浴与杂物储藏等小服务空间按用途保留例外。门口与房间之间预留主要通行带，摆放时检查剩余通行空间和每个物件的可达操作面。室内小服务空间的短开口与末端取物通路按用途处理，家具维持原有米格尺度。分户与加建采用相同尺寸约束。

对外门按建筑用途和入口角色选择1米或2米。当前单户家庭住宅、小型加工及维修作坊在非大型专用建筑、室内面积不超过180㎡时，主门可采用1米；普通侧后出口和后勤副门也可采用1米。两种门宽按种子保留变化。车站、集体宿舍及多户住区的对外门、其他建筑的主要公共入口仍至少2米，装卸门按运输需求保留宽门。主入口、临街门和侧后门按连续格边生成同一组门洞。同一建筑内房间之间的门允许1米，公共通廊与搬运通路按用途保留宽门。普通建筑优先安排至少两个分离的对外出口，集中式宿舍、多户住区和大型设施必须有替代出口。宿舍优先在公共通廊的不同端部接路，侧后出口的连接通路在天然空腔内可为2米，需要挖岩时至少3米。厂房落位时同步为材料区和成品区安排通向街道的短装卸通路；每个门接入实际室内外通路，较宽的装卸口按同一个开口分组，沿用现有墙门数据与漫游交互。

洞厅街坊利用现有洞厅布置房屋；直接开凿的街坊保留建筑之间尚未开挖的岩体。建筑检查面板显示地下空间形态、户型组织、室内面积和工程量。

居民住宅使用独立户、窄面深宅、侧廊家庭户、围院住宅、紧凑户与少量多户住区。较大住区采用紧凑的双侧或折角组织，避免把大部分居民住宅变成长条共廊。

普通墙与门位于格边，特殊厚墙占格。房间和物件保留整数格占地，门后及房间中心留有实际通路。房间连接沿已有墙门编译流程生成，输出继续由现有查看器和 Godot 漫游场景读取。

## 居民改建与工程量

加建增加与原房屋相接的房间；分户增加隔墙和共用通道，形成可到达的出租单间。院落和共用洞厅允许局部加建，同时保留公共通行和外门。街块外的宽居民巷道可被局部占用外缘，但挖岩道路需保留连续3米净宽，完全利用天然空腔的通路至少2米；本来较窄的通道不参与收窄。规划道路、铁路与公共设施不允许这种侵占。

每次改建记录年份、增加面积、院落占用和巷边收窄面积。年份滑杆会重新生成当时的真实状态，原房屋不会提前出现未来的加建。未改建的房间与物件保持世界坐标一致。

天然空腔按低成本整备计入，岩体根据强度和局部弱层计算开凿代价。道路比较整个通行宽度覆盖的地形，建筑比较整个占地；保留硬岩禁止开凿。已开发院地的改建不重复收取挖岩成本。预算为相对工程量，尚未模拟真实财政、人口、能源或施工工期。

## 街道与铁路

规划街道保持整体方向和共享边界，允许随地质轻微形变。居民巷道根据参数提出候选宽度，完全利用天然空腔的通路可以2米；涉及新增挖岩的道路至少3米，优先在选址与寻路时检查完整宽度，并按实际宽度计价。按地形成本绕行岩体和已有建筑，可有多次转折。政府街道、居民巷道、装卸通路和替代出口共用按完整宽度检查的寻路流程，分别设置开挖、通行距离、转弯和总体方向权重。政府街道重视秩序与长期通行，居民巷道更重视施工节约，装卸通路提高距离及转弯代价。装卸通路接入宽度至少3米的公共街道。寻路每一步计算新进入的前缘占地，避免重复累计整个宽度方块；施工与方案比较仍按完整道路并集核算实际工程量。新巷道的完整占地必须通过碰撞检查，包括连接旧街道时的加宽部分。

中央车站作为完整建筑生成，共用站厅连接各线路站台，包含候车、票务站务、卫生清洁、信号控制和动力设备空间。多个对外入口接入公共路网；站台通过站内公共通廊换乘。轨道通道与站台地面分别占地，铁路不穿过站厅或设备房。

铁路出口由输入指定方向、偏移和启用年份。按出口向外方位的较小夹角配对，优先选择最接近相对的两端；夹角至少120°的两端可以组成贯通线，其余出口各自组成中央站终到线。没有出口时保留站台空间。线路先确定各自站台及平直站段，再以满足最小转弯半径的路径接向出口；共用站厅允许不同方向的线路换乘。未来线路预留站台和完整通道，线路按出口年份启用；贯通线仅启用一端时暂按终到运行。每个铁路出口标记作为快速旅行点，城区侧轨道随发展范围延伸，外侧轨道继续到当前地图边缘。地图范围先由城区和岩体背景确定，再裁出边缘端点；外侧轨道不反过来撑大地图。

快速旅行点外侧保留运输隧道，禁止生成房屋、新规划区的开发接路和居民支巷，也禁止后续加建侵入。生成时按空间位置最接近的铁路段，区分城区侧与外侧运输区；无铁路靠近时同时比较中央站位置，避免把无关的城区一并切掉。政府与居民从候选选址开始检查该限制，外侧轨道不提供开发临街面或新增客运站点。外侧隧道工程单独记录为泡间基础设施。

每条线路使用约4米双线轨道，站外轨道铺设在共用道路中。站址同时检查完整站房、站台、轨道净宽、公共入口及周边可开发空间，政府街坊避开预留带。寻路检查连续弯道、曲率和整条通道占地；无法满足地质或转弯条件的出口记录具体失败原因，不穿透保留硬岩。当前只生成同层空间与线路几何，未模拟道岔、列车、调度和运能。

## 公园与路口广场

公园与广场使用现有室外用地结构，作为具名公共项目显示在空间目录中。参数可分别设置规划公园和路口广场数量，设为 0 时不安排该类项目。场地不足时显示实际安排数量；同一路口只安排一个广场。广场只在具备四向通路的路口选址；公园选择有足够临街面的完整用地，安排种植池、座椅和活动空间，并保留公共通行。公共项目不会由剩余边角自动转换而来。

## 灾后场景与照明

地图数据约定见 [地图数据定义](MAP-DEFINITION.md)。正常家具按用途和容量安排后，生成撤离、翻找、临时占用、局部顶板坍塌与街道弃守等场景。尸体、尸体堆、沙袋、路障、废弃摩托和停驶电车具有各自高度及移动、视线、弹道阻挡；预置尸体和尸体堆属于固定场景物件并可附带容器；单位死亡保留原实体与装备。场景物件分别定义固定方式、移动方式、拾取方式和质量；本轮提供属性，不新增拖拽交互。纯装饰独立保存，不参与占地和碰撞。坍塌末端房间保留原用途并标记不可用，其余房间、站内换乘与必要出口继续检查通行。

全城按实际房间、街道和公共空间生成墙灯与顶灯，分别记录强度、范围、三维方向、颜色、安装点、开关和损坏状态。供电区对应城市片区，由中央站或维护设施提供来源关联；当前不模拟电缆网络和供电容量。独立电池与区域电源分开。恢复供电只点亮完好且开关打开的灯，损坏灯保持熄灭，受损灯降低强度。

查看器新增照明、供电区域和视野预览，并允许分别叠加场景物件、战术障碍、纯装饰和灯具。空间目录可定位灾后物件、容器、灯具及场景；检查面板显示高度、三类阻挡、容器内容与供电属性。照明检查完整墙体、门开闭与物件高度；单击门边可预览开关门，视野预览中单击可用地面设置观察点。蓝色区表示几何可见但明暗条件下无法辨认。供电和门状态的预览不会改写导出地图，恢复初始状态可清除预览变化。

Godot 漫游从同一份数据实例化 SCEntity，预生成容器注册到 SCLoot；灯具按同一位置与方向加载真实光源，取消按区块均匀补灯。现有模型复用原素材，尚无对应美术的灾后物件使用明确标注的占地诊断轮廓。预览照度为直接照明近似，不是勒克斯；完整战斗感知、维修供电任务和新物件成品美术另行接入与验看。

## 中空结构与动能穿透

桌子、工作台和空货架使用薄板或框架部件，视线和子弹按部件检查，移动按整件占地保守处理。场景物件保存耐久、简化防护值和破坏后的结构。子弹穿透值高于部件防护时继续飞行，扣除防护值，并按剩余穿透比例保留伤害；防护为零的散落物允许直接穿过。每个部件对同一发子弹只结算一次。同一时间步内可接连命中多个物件，既有射击场和角色战斗共用该过程。活体护甲仍走现有结算并结束该发弹丸。数据细节见地图定义。

## 操作与数据

生成开始后显示进度弹窗，按真实工作阶段更新：地质与车站、铁路接入、逐年建设、地形汇整、房间家具、灾后场景、全城照明、通行检查、准备预览。年度、地形行数、房间等显示本阶段已处理数量与已用时间；阶段耗时不等，不显示推算的总百分比。完成后自动关闭；失败时保留具体原因，可关闭并修改参数重试。生成期间导出禁用，旧预览不用于导出新地图。

参数面板先显示城市设定，高级参数默认折叠；指定设施规则独立列出。可保存、载入参数 JSON；地图导出同时保存种子和参数。浏览器使用当前版本的参数存储。

查看层包括原始地质、规划与自建、路网、街坊、房间和物件。空间目录支持定位建筑及室外用地。施工方式层以蓝灰显示规划建设、土黄显示居民建设、橙色显示后期加建。

JSON version 22 保留 width / height、worldOrigin、tiles、格边墙门、房间、道路及室外空间结构。excavationMode 表示地下空间形态；alterations 保存改建事件；earthwork 保存工程量与地形来源；history 保存年度实际结果及当年需求；settlement 保存当前规划供需与安置统计，planningEvents 保存政府评估结果，demolitions 保存清退记录。建筑的 program、capacity、decision 分别描述具体用途、规划容量和建设依据，siting 保存建造当时的步行距离、当地供需与评分因素，connection 描述与房屋共同评估的新巷道；道路 routing 记录用途权重类别、长度、宽度、转折及建设和通行代价，minimumWidth 保留建设时确定的净宽下限，约束后续加建侵占；规划区的 siting 保存共用边界数量及新连接街工程量。growth 为每格最早建设年份，65535表示尚未建设。blocks.cells 与 outline 保存实际街坊边界；buildableArea 记录建成时扣除道路和指定公共项目的可建面积，fillRatio / developedRatio 保存相对于实际边界面积的建成占地比例。

station.buildingId 指向真实车站建筑，platforms 记录各线路站台与站内房间，trackCells 记录站区轨道用地。tram 按线路输出，共用中央站节点 ST1 并分别引用站台；portals 按实际启用且成功接入的输入出口输出，保留 exitIndex 和 lineId，role 为 fast-travel；trackEnd 为地图边缘的轨道端点，externalPoints 为快速旅行点至边缘的轨迹。tram.points 保存全长线路，internalLengthMetres 单独记录城区内长度。车站元数据同时记录预定线路与接入失败原因。Godot 漫游读取当前 v22 数据。

- options.js：参数与输入校验。
- rail-station.js：线路配对、完整站房、站台布局与满足曲率的铁路接入。
- planning.js：原始地质、车站、用途选择、分期规划、清退与保留、居民建设和年度记录。
- room-layouts.js：适配地块的不同功能平面。
- scene-objects.js：场景物件的移动条件、部件结构、耐久、防护和几何查询。
- environment.js：灾后场景、统一实体属性、容器、灯具供电与高度遮挡的直接照明近似。
- generator.js：墙门编译、物件、数据整合与实际通行校验。
- content.js：完整用途目录、需求与规划容量、物件内容。
- generation-worker.js：后台生成与请求取消。
- viewer.js / viewer.css / index.html：查看、参数和空间检查。

默认32年导出：`node .art-preview-local/bubble-generator/generate.cjs ALYBE-TILES 32 output.json`。第三个参数也可使用参数 JSON 文件路径。
