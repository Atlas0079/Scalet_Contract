# 角色属性、技能与能力架构规范 v3

日期：2026-09-29。状态：确定的实现规范；当前游戏尚未完成此规范的迁移。
2026-09-30 按用户要求纳入 main；文件名保留以维持现有文档链接。v3 完整替代 v2，是角色属性来源、技能成长、能力推导与控制归属的唯一设计依据。
本版新增同步率与机师道具规则，并修订技能渠道。第 5.4 节灵能经验明确属于已记录、未启用的规划机制；它不以临时奖励公式冒充已定稿玩法。

## 1. 强制边界

系统采用三层：

第一层：带来源的基础属性、独立技能、属性修正、当前状态。
第二层：来源解析、技能组合、种族公式、状态结算与能力推导。
第三层：所有角色共用的只读能力结果。

技能是第一层中的独立模块，不是第四层，也不是种族属性的一组别名。
第一层的数据允许因种族不同而不同，第三层的字段及单位必须一致。
射击、移动、感知、操作只读取第三层；它们不得读取肌力、执行器出力、压力或芯片经验，不得按种族分支计算能力。
公式按本规范执行。数值常量在配置中具有唯一存储位置；改平衡只修改其配置，不在调用方添加修正。
新增公式、来源类型、技能来源渠道或叠加阶段必须先修订本规范，再实现代码，禁止在代码中自行补充语义。

本规范定义角色数值架构及下文列出的首版计算规则，不定义灵能招式、治疗用品目录、骇客战斗流程、招募价格或复活剧情。
这些系统尚未实现时不生成虚假功能；它们接入角色数值时必须遵循本规范的来源、状态和能力接口。

## 2. 不变的世界观条件

- 人类拥有灵能潜质，会积累压力并崩溃；普通人便宜，精锐培养昂贵，真正死亡后难以复活。
- 机器人通过人类机师和 SIA（Somatic Integration Architecture）接受控制。机体没有疼痛、压力或肌力属性。
- 机器人损伤的 SIA 痛苦反馈按受伤时同步率等比施加给机师；100% 同步时承受完整反馈。机师意志影响受痛后的表现，不再次减少反馈强度。
- 机器人易受 EMP 和骇客攻击，并存在控制权被夺取的风险。
- 机器人部件可更换、可战地维修；自学习芯片回收后保留自身技能，可装入新机体。
- 仿生人肉体强度远超人类，比常规机器人灵活；依赖人造血，伤后维护昂贵，没有灵能。
- 仿生人自我意识仅在基地切换开启/关闭；关闭后通过 SIA 由机师控制。
- 清醒仿生人的技能归当前意识；SIA 模式由机师提供 70%、本体意识以肌肉记忆提供 30%。后者不恢复自主决策能力。
- 只有人类能担任 SIA 机师；仿生人无论技能等级或当前意识来源如何，均不能担任机师。

## 3. 第一层的数据模块与所有权

### 3.1 数据模块

| 模块 | 保存内容 | 写入规则 |
| --- | --- | --- |
| 基础属性 | 个体、意识或部件的固有数值 | 生成实例时赋值；经验、受伤、药剂均不得改写 |
| 技能 | 持有者的各技能累计经验 | 仅由唯一经验结算入口写入 |
| 修正来源 | 训练、装备、药剂、部件附加功能等贡献 | 获得、启用、过期、卸下时变更 |
| 当前状态 | 疲劳、压力、疼痛、温度、能量、人造血等 | 对应状态系统按模拟时间和事件更新 |
| 部件状态 | 现有 parts 的耐久与损伤 | 伤害、治疗、维修流程写入 |
| 控制关系 | 当前意识、机师、芯片和有效 SIA 连接 | 控制切换事务写入 |
| 配对熟悉度 | 人类机师与特定机体的同步经验、由经验推导的同步上限 | 仅有效 SIA 使用产生经验；不属于基础属性或普通技能 |
| 行为状态 | 瞄准进度、后坐累计、动作进度 | 对应行为系统写入，不属于基础属性 |

每个状态只有一份权威数据。不能同时在角色、芯片和界面中保存可写的同一经验值。
枪械精度、弹药精度和枪械基础后坐继续归装备系统，不进入角色基础属性。

### 3.2 稳定身份

下列对象各自具有稳定且唯一的实例 ID：身体 actor_id、意识 consciousness_id、芯片 chip_id、部件 part_instance_id、物品 item_instance_id、来源 source_id。
类型定义 ID 不得替代实例 ID。两枚同型号芯片具有不同 chip_id 和各自经验。
意识具有且仅具有一个技能账本，芯片同理。技能账本不挂在当前机体的临时控制状态上。
身体引用当前意识、操作者及芯片，不复制它们的账本。
人类意识与本人生物身体绑定；机师远程控制不移动、复制或替换其意识对象。
仿生人引用其当前意识对象；本规范不提供复制意识或通过新建 ID 复制技能的功能。
对象销毁后 ID 不复用。存档保存稳定引用，不保存内存地址或派生能力副本。

### 3.3 来源记录

每条来源记录必须包含：

| 字段 | 精确定义 |
| --- | --- |
| source_id | 该来源实例的唯一 ID |
| owner_kind / owner_id | 实际持有者，类型为 actor、consciousness、chip、part、item |
| origin_kind | 来源类别，见下表 |
| definition_id | 来源定义 ID |
| scope | body 或 controller；规定贡献作用于身体还是当前控制者 |
| active | 当前是否激活；来源存在不等于生效 |
| starts_at / ends_at | 模拟时间秒；永久来源 ends_at 为 null；生效区间为 [starts_at, ends_at) |
| contributions | 该来源声明的贡献列表 |

origin_kind 固定为 innate、structural_part、training、equipment、drug、part_bonus、trait。
“天生”在界面中显示为“固有”，由 innate 与 structural_part 两类组成。
innate 是个体/意识生成时的固有贡献；structural_part 是当前结构部件提供的基础贡献。
training 是后天训练成果；trait 是独立特质；它们不混入固有基础。
装备制造出的能力增强仍归 equipment/part_bonus，不能因长期穿戴改成 innate。

同一来源只登记一次。由多个引用路径指向同一 source_id 时只读取一次；两个不同记录占用同一 ID 则判为数据错误。
持续时间和 active 的更新由来源管理流程完成，能力求值只读取，不负责过期销毁。

### 3.4 贡献记录

每条贡献包含 contribution_id、target_kind、target_id、role、operation、value、stack_group、stack_policy、priority。
contribution_id 在该 source_id 内唯一。

- target_kind 为 attribute、skill 或 capability。目标必须存在于对应注册表。
- role 为 base 或 bonus。base 只允许 innate / structural_part 来源写入 attribute；其他组合非法。
- base 的 operation 必须为 add，由基础属性装配规则收集；它不是附加奖励。
- bonus 的 operation 为 add、percent 或 factor，执行顺序由第 7 节固定。
- attribute 指某种族的内部属性；skill 指技能的有效等级修正；capability 指第三层的数值字段。
- contribution 不允许改 XP、角色 ID、意识 ID、种族、控制模式、生命值、状态值或能力许可标志。
- 修改压力、伤势、温度的药物属于状态事件；若还增加能力，另有一条数值贡献。两者不能写成同一路径的两次惩罚/奖励。
- factor 必须为有限非负数，percent 必须 >= -1，add 必须是有限数。
- 核心能力不能通过 capability 修正获得未具备的动作许可或灵能资格。

stack_policy 固定为 stack 或 exclusive。相同 stack_group 必须指向同一 target_kind、target_id、operation，并使用同一 policy。
stack 将所有有效贡献保留。exclusive 只取 priority 最大的一条；同优先级按 source_id、contribution_id 字典序选最小者。
exclusive 不自动挑“最大数值”，因为误差、延迟与速度的有利方向不同。
落选贡献保留在来源明细中，标记 suppressed_by；卸下胜出来源后重新选取。

## 4. 固有基础、训练与部件替换

基本属性不通过使用或经验成长。基础来源实例的数值不可变。
所谓“当前基础值”，是当前装配的基础来源按角色定义中的 recipe 计算得到的结果；它不是可写字段。
每个属性 recipe 明确列出槽位和权重：B[attr] = Σ(weight[slot] × base_value[slot, attr])。
权重为非负数；所需槽位和权重必须显式配置，不推测未填槽位，不要求权重总和必定为 1。
单一人类固有来源也是一个权重为 1 的 recipe。机械身体使用结构部件槽位。
同一槽位最多装配一个部件；每个必要属性必须有 recipe。缺少声明为必需的部件时，对应物理功能不可用，而非报存档损坏。
缺少必需的 recipe 或部件类型定义是数据错误。可拆卸部件槽位的空缺属于合法损伤/装配状态。

后天训练分两种，必须由训练项目明确指定：

1. 技能训练：增加对应持有者的 XP。
2. 身体/心智训练：提供 training 来源修正，不改基础来源数值。

同一训练项目只能有一个进度记录，升级时替换其贡献值，不累加复制旧等级奖励。
训练成果默认永久，直至明确的训练移除事件；没有自动退化机制。
身体训练 scope=body，跟随身体；认知训练 scope=controller，跟随意识。
每个训练定义必须显式声明 scope，不由名称判断。

一个部件允许同时提供多个 base 与 bonus 贡献。例如机械臂提供基础出力，以及独立稳定器的后坐控制加成。
base 贡献的 origin_kind 为 structural_part；bonus 贡献的 origin_kind 为 part_bonus。两者引用同一 part_instance_id，使用不同 source_id。
部件损伤不改额定值。第二层根据部件状态计算其功能折损。
部件 bonus 必须声明 requires_functional：true 时部件 HP 为零即停用；false 时不受该条件影响。
是否随损伤连续衰减由来源定义的 durability_curve 指定，曲线输入为 hp/max_hp，输出为修正的生效比例 q。
add 与 percent 实际值为 value×q；factor 实际值为 1+(value-1)×q。q 的范围为 [0,1]。
同一路径不得再次以该部件耐久折减此项 bonus；身体基础功能的折损与独立附加模块的折损是不同贡献。

更换部件是原子事务：停用旧部件全部来源 → 替换槽位引用 → 启用新部件来源 → 刷新能力。
事务完成前不得结算行动或发射。旧部件来源不留在新身体上，新部件不继承旧部件耐久。
经验属于独立芯片/意识，更换机械臂不改变技能经验。更换或转移芯片只移动引用，不复制账本。

## 5. 独立技能模块

### 5.1 技能目录与等级

首版技能 ID 固定为 shooting、medicine、repair、hacking、sia_control、psionics。
中文名分别为射击、医疗、维修、骇客、SIA 操控、灵能。
技能账本记录 owner_kind、owner_id 及每项 skill_id 的 xp；等级只由 XP 推导，不单独保存。
所有账本初始化时列齐技能，未训练技能 xp=0。芯片的 psionics 和 sia_control 固定为零，不允许获取经验。

XP 范围 [0,40000]。等级连续取值 L=min(20,sqrt(xp/100))；等级 10 对应 10000 XP，20 对应 40000 XP。
界面显示一位小数，计算使用完整精度。外部加成不增加 XP、不提高学习上限，不改变经验所有权。
有效技能 E=clamp(max(0,L+Σadd)×max(0,1+Σpercent)×Πfactor,0,20)。
技能修正只影响本次有效值；药效结束后恢复原值，已获得的 XP 保留。

### 5.2 技能来源组合

先分别计算各持有者的有效技能，再按固定权重组合；最后应用明确作用于当前机体的 skill 修正一次。
意识自持来源 scope=controller；安装在当前机体的芯片/装备来源 scope=body。
一条贡献不能同时作用于持有者计算与组合后计算，scope 决定唯一结算位置。

来源路由按以下顺序执行：芯片自持来源先由芯片账本计算并从候选列表移除；活动意识及其持有者身上的 controller 来源进入意识技能计算；当前作战身体的 body 来源进入组合后计算。
机师身上 scope=body 的装备、训练不转给远程身体；只有 scope=controller 的来源随该机师参与远程控制。
机器人机体安装的“辅助处理器”属于 body 来源；“芯片自身学习特质”属于芯片自持来源，两者必须使用不同来源实例。
自主模式也执行相同路由；不能因身体和意识属于同一角色而把一条来源结算两次。

| 当前控制模式 | shooting / medicine / repair / hacking | sia_control | psionics |
| --- | --- | --- | --- |
| 人类自身 | 自身意识 100% | 自身意识 100% | 自身意识 100% |
| 机器人 SIA | 机师意识 30% + 当前芯片 70% | 机师意识 100% | 不可用，结果 0 |
| 仿生人自主 | 当前意识 100% | 当前意识 100% | 不可用，结果 0 |
| 仿生人 SIA | 机师意识 70% + 本体意识肌肉记忆 30% | 机师意识 100% | 不可用，结果 0 |

组合后按同一技能修正公式处理 scope=body 的修正，再限制在 [0,20]。
psionics 的资格门控在组合和全部修正之后执行；机器人和仿生人的最终值始终为 0，禁止通过 body 加成绕过。
芯片账本及其自持 trait/training 修正先在芯片有效值中结算，不能再次进入 body 的组合后修正列表。
机器人缺少芯片时，其芯片渠道贡献为 0；机师权重仍为 30%，不重新归一化。缺少有效机师时不能主动行动。
仿生人肌肉记忆只读取当前绑定的本体意识账本的 shooting/medicine/repair/hacking 派生基础等级 L，不读取其心理状态、灵能、SIA 操控或 controller 修正。机师渠道继续使用有效等级 E。
本体意识被关闭不阻止此被动渠道；意识不存在或记忆结构不可读时该 30% 为零，不转给机师。
肌肉记忆不生成独立技能副本，不读取前任意识，不赋予自主决策；更换意识后引用随之变更。身体装备的技能修正仍只在渠道组合后应用一次。
技能来源权重不决定身体强度；身体属性与技能继续独立。

### 5.3 成长与经验事件

SCSkills 是经验唯一写入入口。经验只能来自有效行动或明确训练事件，读取能力和播放动画不产生经验。
经验事件包含唯一 event_id、skill_id、base_xp、学习持有者 ID、分配权重、发生时间和已结算状态。
事件在行为开始时绑定持有者及来源分配，控制切换后不得把此前行为的 XP 发给新控制者。
同一事件最多结算一次。存档保存待结算事件及其状态，已完成事件不能在读档后重新提交。
持续操作在进行中只累计实际完成的基准工作量，在完成或中断时生成一次经验事件；不逐帧提交重复事件。动作实例 ID 与结算序号构成唯一 event_id。
XP 分配使用行为绑定的渠道权重，与当前加成后的技能占比无关；在途子弹的射击经验于合法发射时结算，命中时不再结算。

首版经验单位：

- 射击：向当时有效且存活的敌对目标真实发射一发，base_xp=1；命中不额外加 XP；空放、友军靶和美术测试场不产生 XP。
- 医疗、维修、骇客：每完成 1 个基准工作秒，base_xp=1；不按耗费的墙钟时间计奖。不存在合法工作目标时不结算。
- 训练：每完成 1 个训练工作秒，base_xp=1，只发给训练项目指定的账本。
- 灵能：取消按施放次数固定发放 1 XP 的规则；使用第 5.4 节规划接口，在奖励策略启用前不结算灵能 XP。
- SIA 操控：每个通过 SIA 完成的上述有效行动，额外给机师 sia_control 发放该行动 base_xp×0.25。

机器人工作技能经验按机师 30%、芯片 70% 分配；没有芯片时其 70% 丢弃，不转给机师。
仿生人 SIA 工作技能经验按机师 70%、本体意识肌肉记忆 30% 分配；本体记忆不可读时其份额丢弃。此渠道只增长对应技能 XP，不唤醒意识、不增加其 SIA 操控技能。
自主模式工作技能经验 100% 给当前活动意识。SIA 操控奖励始终只给人类机师，不再按工作渠道权重分配。经验允许小数，累计到上限后截断。
技能达到上限不把溢出经验转给另一个持有者。
训练基本属性只更新训练来源进度，不修改 XP；技能训练只更新 XP，除非训练定义同时显式声明两种独立产出。

### 5.4 灵能经验的规划接口（未启用）

已记录的设计方向：经验由单次施放的实际灵能消耗驱动；在总消耗相同的比较下，一次高消耗施放所得经验要高于分成多次低消耗施放；因施放灵能而崩溃存在额外经验奖励。
以上奖励机制保留为规划，不在本版确定增长曲线、崩溃奖励数额、取消/失败施放奖励或结算时机，不自行采用平方函数或固定奖励。

为实现该方向，灵能系统必须产生施放记录：cast_id、caster_consciousness_id、ability_id、started_at、resolved_at、actual_cost、cost_unit、outcome。
actual_cost 为该次施放净扣除、未退还的消耗，不能读取技能说明中的标称费用。一次持续施放的分段扣费累计在同一个 cast_id 中，不能拆成多个独立施放改变奖励。
如果未来采用多种灵能资源，奖励策略必须定义统一的消耗换算；不得把不同单位直接相加。
崩溃事件必须有 breakdown_event_id 和导致崩溃的 cause_cast_id；其他伤害、压力导致的崩溃不能冒充施法崩溃。每个崩溃事件最多关联一次额外奖励。
记录将来由专门的 psionic_xp_policy 转为经验事件，再交 SCSkills 去重入账。该策略只负责奖励，不改写技能账本。
本版 policy.enabled=false；记录保留，UI 标记“灵能经验机制未启用”，不自动补发历史 XP。策略启用须先修订本节并明确历史记录结算范围。

## 6. 种族属性与状态契约

所有下列内部基础属性使用非负设计评分，100 为人类标准基准，额定定义范围 [0,1000]。
它们不是物理单位；第二层转换为 N、kg、m/s 等实际输出。有效属性受修正后也限制在 [0,1000]。

| 种族 | 身体属性 ID | 意识属性 ID |
| --- | --- | --- |
| human | muscle、endurance、coordination、senses | resolve、psi_potential |
| robot | actuator_output、drive_efficiency、servo_precision、sensor_quality、cooling、em_shielding、control_security | 无；使用机师的意识输入 |
| android | muscle_fiber_output、neural_speed、fine_control、senses、circulation_efficiency、tissue_stability | resolve；不具备 psi_potential |

初始模板默认评分：human 所有属性 100；robot actuator_output=180，其余 100；android muscle_fiber_output=220、neural_speed=150、fine_control=140，其余 120。
具体个体/型号可以在定义范围内有不同固有值；默认模板不是所有个体必须相同的数值。
机器人肌力、压力字段及仿生人灵能潜质字段非法，不补零。

即时状态均在 [0,1]：fatigue、stress、pain、psi_load、heat、electronic_fault、metabolic_load、circulation_fault 为 0 最佳；energy、artificial_blood 为 1 最佳。
human 使用 fatigue、stress、pain、psi_load；robot 使用 heat、energy、electronic_fault；android 身体使用 artificial_blood、metabolic_load、circulation_fault，自主意识使用 stress、pain。
机体损伤反馈生成给控制者的 pain，不在机器人上增加 pain 字段。仿生人 SIA 模式使用机师的心理状态；休眠意识不承担该次行动的心理压力，但按肌肉记忆渠道获得技能经验。
基础属性不随状态变化。状态造成的变化仅存在于当前能力计算结果。
压力/痛苦由事件和时间推进；达到失能/崩溃状态时的动作许可由状态输出提供，不让 UI 或属性求值自行触发 AI 行为。

## 7. 第二层的固定计算过程

### 7.1 顺序

1. 取得身体、控制者、芯片及来源的同一时刻输入快照，验证 ID、控制关系和所属字段。
2. 按 active、时间区间、装配/控制绑定和来源作用范围筛选来源，处理 stack_group。
3. 按 recipe 计算基础属性 B，按统一修正公式算有效属性 A。
4. 由 SCSkills 取得各持有者有效等级，按第 5 节组合有效技能。
5. 先完成第 9.1 节控制阶段，求得 sync_ceiling、sync_current 和 sia_pain_scale；再从现有 parts 算身体功能比例，由种族公式和当前状态算中间量。
6. 按第 8 节生成通用能力，应用直接 capability 修正；控制阶段已消费的 sync_current 贡献不再次应用，控制结果直接发布到快照。
7. 最后执行许可门控、边界检查，发布完整只读快照。门控不能被任何加成绕过。

统一数值修正公式 M(x)=max(0,x+Σadd)×max(0,1+Σpercent)×Πfactor；加法小计和百分比小计各自取非负值，在所有运算结束后按目标字段范围截断。
不按来源遍历顺序交替加乘，不在每条贡献后分别截断。各阶段来源先按 source_id/contribution_id 排序，保证稳定浮点求值顺序。
只有当前阶段允许的贡献进入公式。capability 修正不得回流修改 A 或技能，不允许引用另一个派生能力作为输入。

### 7.2 身体功能与状态折损

复用 bodies.json 现有区域权重，计算 f_move、f_hand、f_sense，范围 [0,1]。
对应功能所需部件全部失效时必须为零，原有 minimum 不得使已完全失去功能的身体继续行动。
非致命损伤的比例计算继续使用现有 region_fraction；致死条件继续使用身体定义。

定义 norm(x)=x/100。种族中间量如下：

| 种族 | 力量 P | 运动 V | 精细控制 D | 感知 S | 身体供能折损 U |
| --- | --- | --- | --- | --- | --- |
| human | norm(muscle) | sqrt(norm(muscle)×norm(endurance)) | norm(coordination) | norm(senses) | 1-0.5×fatigue |
| robot | norm(actuator_output) | norm(drive_efficiency) | norm(servo_precision) | norm(sensor_quality) | energy_gate×(1-0.7×heat_penalty)×(1-electronic_fault) |
| android | norm(muscle_fiber_output) | norm(neural_speed) | norm(fine_control) | norm(senses) | artificial_blood×(1-0.5×metabolic_load)×(1-circulation_fault) |

robot heat_penalty=clamp(heat/max(0.1,norm(cooling)),0,1)，energy_gate=clamp(energy/0.1,0,1)。
android 的循环效率、组织稳定性转换为第三层的恢复/稳定系数，由状态系统用于代谢/循环恢复与损伤后状态推进，不再次乘入当前 U。
robot 电磁防护、控制安全性转换为第三层防护系数，EMP/入侵状态流程只读取该输出，不绕过第三层查询内部属性。

控制状态折损 C=clamp(1-0.4×stress/max(0.1,norm(resolve))-0.4×pain,0,1)。
自主角色采用自身意识；SIA 采用机师意识，机师身体力量/腿部功能不参与。
resolve 必须来自该控制者已经解析固有来源与 controller 修正后的意识属性；机器人属性表中不存在 resolve，不能从机体缺省取值。
关闭意识不销毁其属性或来源，只停止其作为当前控制者参与求值；第 5.2 节规定的肌肉记忆渠道保持有效。
SIA 额外控制系数 Q=(0.5+0.025×E_sia_control)×link_quality×sync_current，link_quality 与 sync_current 范围 [0,1]；自主模式 Q=1。
链路延迟独立输出，不再通过 Q 重复扣减。反馈首先按 sync_current 换算一次；得到的 pain 不再被 Q 或意志减少，C 只是受痛后的表现折损。
所有中间量是规则内部局部值，不存档、不向游戏系统提供可写入口。

## 8. 第三层能力字段与公式

快照根字段为 actor_id、revision、evaluated_at、values、permissions、reason_codes。
第三层没有角色属性点或 XP；快照重算后替换，调用者不得原地修改。

定义 K(s)=0.5+0.05×E_s；射击 K_shoot=K(shooting)。
定义精细执行 H=D×U×f_hand×C×Q。下面公式先得到原始输出，再接受本字段的 capability 修正，最后门控。
防止除零：当分母为零时该动作 unavailable，输出误差采用上限、速率为零；不能用一个极小正数伪装可行动。

| values 字段 | 单位与范围 | 原始输出 |
| --- | --- | --- |
| force_n | N，>=0 | 1000×P×U×f_hand |
| carry_capacity_kg | kg，>=0 | 18×P×U×f_move |
| move_speed_mps | m/s，>=0 | 2×V×U×f_move |
| acceleration_mps2 | m/s²，>=0 | 10×V×U×f_move |
| turn_speed_radps | rad/s，>=0 | deg_to_rad(240)×D×U |
| manipulation_rate | 无量纲，>=0 | H |
| reload_rate | 无量纲，>=0 | H×K_shoot |
| treatment_rate | 无量纲，>=0 | H×K(medicine) |
| repair_rate | 无量纲，>=0 | H×K(repair) |
| hacking_rate | 无量纲，>=0 | H×K(hacking) |
| aim_gain_per_second | /s，>=0 | 1.25×H×K_shoot |
| aim_unsettled_degrees | [水平°,垂直°]，各轴 [0,45] | [6,5]/(H×K_shoot) |
| aim_settled_degrees | 同上，且不超过未稳定误差 | [0.2,0.2]/(H×K_shoot) |
| recoil_kick_scale | 无量纲，[0.25,4] | 1/(sqrt(P×U×f_hand)×C×Q×K_shoot) |
| recoil_instability_scale | 无量纲，[0.25,4] | 1/(H×K_shoot) |
| recoil_recovery_scale | 无量纲，[0,4] | H×K_shoot |
| view_distance_m | m，>=0 | 12×S×f_sense |
| view_angle_rad | rad，[0,2π] | 当前身体配置的视角，不由技能扩大 |
| identification_rate | 无量纲，>=0 | S×f_sense×C×Q |
| response_delay_seconds | s，>=0 | 0.25/max(0.1,D×C×Q) + SIA 的 link_latency_seconds |
| em_protection | 防护系数，>=0 | robot 为 norm(em_shielding)，其他为 0 |
| control_protection | 防护系数，>=0 | robot 为 norm(control_security)，android SIA 为 1，其他为 0 |
| circulation_recovery_scale | 恢复系数，>=0 | android 为 norm(circulation_efficiency)，其他为 1 |
| tissue_stability_scale | 抗循环损伤系数，>=0 | android 为 norm(tissue_stability)，其他为 1 |
| sync_current | 比例，[0,1] | SIA 模式由第 9.1 节推导，自主/未连接模式为 0 |
| sync_ceiling | 比例，[0,1] | 当前 SIA 配对的成长上限；自主/未连接模式为 0 |
| sia_pain_scale | 比例，[0,1] | 有效 SIA 为受伤时 sync_current，其他为 0 |
| psi_capacity | 无量纲，>=0 | 人类 norm(psi_potential)×(1-psi_load)，其他为 0 |
| psi_execution_rate | 无量纲，>=0 | 人类 C×K(psionics)×(1-psi_load)，其他为 0 |

move_angle_curve 使用身体配置，输入角度 [0,180] 度，输出速度倍率 [0,1]，相邻点按现有 smoothstep 插值。
该曲线是当前身体运动结构的统一能力字段；移动系统不能再去角色定义找种族曲线。
瞄准模型其余参数固定为规则配置：curve_power=2、movement_loss_per_m=0.9、turn_loss_per_degree=0.008、switch_retention=0.35、idle_decay_per_second=0.5、sway_period_seconds=1.7。它们随快照输出，不由射击代码读取第一层。
minimum_fire_progress=0.55 属于射击决策参数，独立于基础属性与技能；测试场手动扳机不受 AI 开火阈值限制。
防护系数 0 表示没有该项防护加成，不表示存在攻击面，也不表示免疫。EMP 是否能作用于某部件由部件电子标签决定；控制权争夺只对有效 SIA 控制关系开放。
circulation_recovery_scale 乘在状态系统声明的基础恢复速率上；tissue_stability_scale 将其声明的基础循环损伤增量除以 max(0.1,该系数)。这两条转换在状态生成处只应用一次。
后坐角色修正分别作用于枪械 kick、instability_per_shot 和 recovery；武器最大角度上限仍由武器定义决定。
枪械与弹药自身的 accuracy_degrees 完全独立，角色能力只影响角色瞄准误差及后坐控制。

权限字段固定为 can_move、can_operate、can_aim、can_use_psionics：

- 身体死亡：全部 false；所有速率、力量、负重和 psi 输出为 0。
- inactive 模式、活动意识失能或被状态系统标记为不能执行主动指令：全部主动权限 false，主动动作速率为 0。此条同时适用于自主模式与 SIA 模式。
- SIA 无有效机师、未授权、失联或控制者失能：全部主动权限 false，速率为 0；身体静态力量/负重值保留用于描述，不能据此发起动作。
- 有效 SIA 但 sync_current=0 或 link_quality=0：主动权限 false；配对熟悉度保留，技能渠道本身不销毁，恢复同步后重算。
- f_move=0 或 move_speed=0：can_move=false。
- H=0：can_operate=false、can_aim=false，操作/瞄准速率为 0。
- can_aim 还要求 f_sense>0、P>0；无视觉时不允许标准视觉瞄准，无出力时不允许执行此射击模型。
- can_use_psionics 只允许人类自身模式、活动且未失能意识、psi_capacity>0；装备加成与机师灵能不能绕过。
- 具体行动除权限外还检查自身需求，如医疗物品、维修工具、弹药；属性模块不替代物品规则。

字段间一致性在最终修正后检查：稳定误差逐轴取 min(稳定误差,未稳定误差)；所有数字必须有限。
误差值为零合法，技能等级为零不等于动作不可用。完整角色数据不能省略零值输出字段。
未实现的灵能行动入口保持禁用并标记 feature_unavailable，不宣称 psi 数值已经提供可玩的超能力。

## 9. 控制模式、SIA 与变更事务

控制模式固定为 self、sia、inactive。human 允许 self；robot 允许 sia/inactive；android 允许 self/sia/inactive。
self 必须引用该身体当前活动意识；sia 必须引用有效人类机师意识和授权链路；inactive 不提供主动行动权限。
SIA 资格同时校验机师身体 species=human、其活动意识与本人生物身体绑定、本人未失能。仿生人中的人类来源意识不满足资格；sia_control 高等级或装备加成也不满足资格。
一具身体同一时刻只允许一个有效控制者；一名机师同一时刻只直接控制一具远程身体。
SIA 机师自身身体保持在基地控制状态，不同时执行另一套战斗移动/射击指令；允许第 9.2 节规定的基地侧自用道具动作。
更换意识或连接必须在合法流程中完成；意识开启/关闭仅在基地执行，不能由修改来源 active 绕过。
控制引用不能成环，不能把远程机体当成另一条 SIA 链的机师。

控制切换为原子事务：停止新输入和扳机 → 中断当前未完成操作 → 结算已完成工作对应经验 → 解除旧控制引用 → 建立新引用 → 清空瞄准进度 → 重算能力。
不转移身体损伤、不转移技能账本、不复制训练成果；休眠意识作为主动控制者及其 controller 修正停止生效，仅保留肌肉记忆的原始技能等级渠道。
未执行的剩余工作不产生经验；中断前实际完成的工作按第 5 节结算一次。已发射子弹保持发射时绑定的学习归属和弹道参数。
控制切换不清除枪械累计后坐、不修复身体、不恢复压力；这些状态按各自恢复规则继续演进。
新控制建立必须通过有效授权/连接状态；不自动提供零延迟完美链路。

SIA 痛苦链路：先记录伤害发生前有效连接的机师与 sync_current → 结算机体损伤并生成基础反馈强度 → 乘记录的 sync_current → 生成一次机师反馈事件 → 刷新受影响能力。
反馈强度 = 基础痛苦反馈 × 受伤时同步率。100% 同步承担全部，50% 同步承担一半；之后对 pain 状态的范围截断不改变事件记录中的真实反馈量。
反馈绑定伤害时的机师与同步率，不因伤害导致断连、之后换机师或使用降同步针剂而重算；事件按唯一 ID 去重。
痛苦强度生成归损伤系统；属性规则不第二次计算伤害或再次减免反馈。
痛苦可能持续，但持续推进归状态系统；读取能力、UI 刷新和存档加载不重新施加同次伤害。
SIA 模式没有机体本地自主决策兜底；安全制动与维持平衡不授予主动战斗许可。

### 9.1 配对同步率与成长

同步率不是基础属性，不是芯片技能，也不是机师对所有身体共用的一项等级。当前同步率也不重分配技能渠道的 30/70 或 70/30 权重；它通过 Q 作用于组合后的控制表现。
持久记录以 (pilot_consciousness_id, body_actor_id) 为唯一键，保存 sync_xp。身体 ID 表示这一具实体，而不是型号、意识或芯片 ID。
同一机师对不同机体、不同机师对同一机体使用不同记录；机器人与 SIA 仿生人遵循同一规则。
换手臂、维修、换芯片不改变机体身份，不清空配对记录；整机报废后以新 actor_id 创建的机体必须重新建立配对，不能通过回收芯片继承旧同步上限。
更换仿生人意识不转移配对记录：同步熟悉度仍属于机师与这具身体，肌肉记忆技能则随本体意识引用切换。

首版参数集中在 skills.json 的 sia_synchronization 中：initial_ceiling=0.60、xp_to_max=10000、xp_per_active_second=1、connect_sync=0.30、recovery_per_second=0.03、quality_loss_per_second=0.05、damage_loss_scale=0.25。
这些是本版实现初值，不是用户不可修改的世界观常量。
sync_ceiling=min(1, initial_ceiling+(1-initial_ceiling)×sqrt(sync_xp/xp_to_max))；sync_xp 限制在 [0,xp_to_max]。
上限由使用经验提高，最高 100%；药剂不改变 sync_xp 或长期上限，不回写基本属性。

有效连接下实际移动、有效瞄准敌人、开火、处理有工作量的任务所占模拟时间，按每秒 1 XP 增加配对经验。重叠行为只计一次 dt。
原地空闲、暂停、无授权、失联、同步率为零、美术试验演示不产生配对经验。该经验不与技能经验池互相扣减或分摊。
配对经验只由统一控制更新时间推进，不能在每次技能查询或多个角色视图中重复增加。

连接状态保存 sync_base；有效连接建立时 sync_base=min(connect_sync,sync_ceiling)，不继承上一条连接的当前同步率。
有效连接期间：sync_base += (recovery_per_second×link_quality - quality_loss_per_second×(1-link_quality))×dt，然后限制在 [0,sync_ceiling]。
同次机体伤害完成痛苦结算后，sync_base -= damage_loss_scale×min(1,本次实际反馈强度)，再按范围截断；痛苦必须先用旧同步率计算，禁止先降同步再减免本次痛苦。
断连、换机师或主动退出将当前连接的 sync_base 清零；配对 sync_xp 保留。战局内保存/读取要保留当前连接状态，不按新连接重新奖励或重置。

道具造成的持续同步变化通过 controller 来源的 capability.sync_current 贡献进入统一加成公式：sync_current=clamp(M(sync_base),0,sync_ceiling)。
sync_current 是受限的控制输出，必须在计算 Q 之前求得。它是通用能力公式执行前的显式控制阶段，不允许其他能力反向引用或修改它。
sync_ceiling 和 sia_pain_scale 禁止直接 capability 加成；前者只由配对经验决定，后者只等于最终 sync_current。
针剂既能增加也能减少当前同步，但不能突破长期上限或 100%。药效结束只撤销来源贡献，不把药效写成经验；该期间造成的伤势、疼痛与真实使用经验仍然保留。
同步率越低，Q 越低且反馈痛苦越少；降低同步率不能同时保持满同步控制表现。链路质量和同步率是独立输入，不能互相覆盖。

### 9.2 道具归属与基地机师自用

所有用物动作明确携带 issuer_id（发起命令者）、executor_actor_id（实际使用者）、item_instance_id、target_id。物品可用性以 executor 的携带库存为准，不以当前选中的远程机体为准。
战场角色只能消耗自己携带的物品。对身边队友使用医疗物品仍由使用者背包扣除，不允许远程调用基地仓库、其他队友或机师的库存。

“机师远程道具”是玩家从战场界面指挥基地机师对本人使用道具，不是机体跨距离取物，也不是把机师针剂注射进机器人。
该动作 executor 和 target 均为基地机师本人，item_instance 必须由机师携带/装入其个人使用槽；基地仓库物品先完成转移，不能直接跨库存扣除。
第一版只开放机师自用的 pilot_self 类型远程动作，不开放机师远程治疗任意战场角色。
例：同步增强针剂产生 owner_id=机师、scope=controller、target=capability.sync_current 的 drug 来源；远程机体的配对同步计算读取这一来源。
减弱同步率针剂使用同一流程。此类药物作用于机师，不改机器人的芯片技能、基础属性或部件耐久。

物品先由 executor 预留；使用成功时同一事务内扣除一次并创建一次效果事件，取消/失败释放预留，不生成加成。
药效定义必须包含作用目标、持续时间、数值贡献与叠加组；同型号增强/抑制剂是否共存由既有 stack_group/stack_policy 明确控制。
机师自用动作使用机师自身能力计算耗时，不使用机器人或仿生人的手部/技能；机师本人失能、没有道具或不能操作时拒绝执行。
每个机师同时最多一个基地自用动作。自用期间暂停其远程主动输入：停止扳机、停止新移动指令和远程工作进度，保持 SIA 连接；反馈痛苦与同步变化继续结算，药效成功后恢复接收新指令，不自动恢复原扳机。
机师在用药中断连，不改变物品执行者和目标；药效成功后继续留在该机师身上，重连或换机体时应用于新连接，但受到新配对上限约束。
远程身体被接管或换机师后，不继承旧机师药效。禁止将来源 scope 自动从 controller 改为 body。

## 10. 更新、存档与来源解释

能力求值是纯函数：同一输入得出同一输出，不使用随机数，不产生事件，不改变来源/状态/XP。
复用现有模拟 tick，先推进状态和处理变更事件，再发布能力快照，再消费能力执行行动。
本 tick 内受伤、换件或控制变更后，在下一项相关行动之前重新求值，不使用过期快照。
revision 每次发布递增。第一版不建立依赖图缓存；UI 只读最近快照，不触发模拟。
操作按基准工作量累计 progress += rate×dt；受伤或增益只改变之后的工作速度，不重新计算已经完成的工作。
换弹等操作期间 rate=0 时暂停进度，失去控制关系时按第 9 节中断；是否消耗物品仍归对应行动系统。
正式场景与测试场使用同一求值和技能读取入口。测试场默认禁止写入持久 XP，演示中的来源/状态仅作用于测试实例。

存档保存基础来源实例、账本 XP、来源记录、部件实例/槽位、控制关系、配对 sync_xp、连接 sync_base、机师自用物品预留及即时状态；不保存派生等级、同步上限、最终同步率或能力作为权威值。
读档先恢复实例和引用，校验后重新计算；缺少必需字段直接报告数据错误，不通过兼容分支补默认值。
回收芯片保留其 ID 与账本，安装新机体后引用该芯片；不读取已报废机体的能力快照来继承技能。

每次计算必须能按需给出来源明细：来源 ID、持有者、原始值、有效/失效原因、叠加选择、作用阶段、中间结果、最终结果。
运行时使用稳定 reason_code；界面才把它翻译为中文。无效原因至少涵盖 expired、unequipped、inactive_controller、suppressed_by、destroyed_part、missing_controller、link_lost、feature_unavailable。
不只显示“力量 +20”，必须能定位到具体装备/部件实例。界面不自己复算结果。
详细说明只在查询详情时生成，不在每 tick 拼接文本。

## 11. 文件职责与现有代码迁移

新增且仅新增以下两个计算模块，不为每种族复制角色类：

- simulation/ability_rules.gd：SCAbilityRules，完成来源解析、属性转换、种族公式、门控及明细；evaluate(inputs) 返回能力快照，explain(inputs,target) 返回同一算法的来源解释。
- simulation/skills.gd：SCSkills，负责 XP/等级、持有者有效技能、渠道组合、经验事件结算及配对同步经验到上限的转换；两种 XP 使用不同命名记录，不能混入同一技能。

SCActor 保留实体、部件与行为状态，持有身体来源和能力快照，并引用意识/芯片对象。
SCWorld 持有意识、芯片及机师—机体配对记录的实例注册表，并负责控制时间推进、物品执行者校验；测试场通过同一初始化函数建立本地注册表，不复制注册/成长逻辑。
注册表是 ID 到实例的存储，不新增服务框架；意识与芯片记录使用结构确定的字典，不新建种族继承树。
SCData 继续承担配置加载、字段和引用校验。

| 文件 | 确定职责 |
| --- | --- |
| characters.json | 种族/型号、属性 schema、recipe、基础模板、身体/外观引用、规则参数 |
| bodies.json | 部件类型、槽位、额定 base/bonus 定义、耐久、区域功能权重、致死条件 |
| 新增 skills.json | 技能目录、等级曲线、渠道权重、经验规则、第 9.1 节同步成长参数和禁用的灵能奖励策略声明 |
| 新增 attribute_sources.json | training/equipment/drug/trait 的来源定义与贡献；运行实例另行保存 |
| units.json | 个体生成模板、意识/芯片初始 XP、来源引用和装备；不保存最终能力 |
| weapons.json / ammunition.json | 保留装备固有精度、后坐、弹道定义 |
| presentation.json | 模型、骨架、动画与视觉效果；不承载角色能力公式 |

属性和经验模板只在生成实例时复制；后续不每帧从模板覆盖个体状态。
units 中初始技能 XP 必须逐项显式填写，不能因字段缺失自动获得等级 10；用于对齐原有人类射击与治疗表现的现有模板将 shooting、medicine 各设置为 10000 XP，其余技能设置为 0。
来源定义仅允许数值、白名单操作符、声明式时间/装配条件和有限曲线；禁止任意公式字符串或可执行脚本路径。
分段曲线点按横轴严格递增，区间内线性插值，超出区间取端点；移动角度曲线保留第 8 节指定的 smoothstep。

迁移时一次性替换旧数据，不保留旧配置读取分支：

1. SCActor 的 speed、turn_speed、capacity、view_distance 改为能力快照的只读访问，不保留可写副本。
2. 旧 capability_efficiency 保留其区域功能计算，用作规则内部输入；movement_efficiency、manipulation_efficiency、vision_efficiency 的外部调用全部迁移后移除。
3. SCMovement 使用最终 move_speed，不再乘旧伤势效率；SCCombat 使用最终瞄准和后坐能力，不再读取 definition.aim。
4. SCWorld 的换弹/物品操作使用对应 rate，不再重复除以 manipulation_efficiency；感知读取统一输出。
5. 测试场使用相同快照、来源解释和技能模块；不添加 test_human/test_robot 独立公式。
6. 配置无效时启动失败；切换来源时事务验证失败则保持原状态，不发布半更新结果。

## 12. 实施交付与验收要求

架构与数值契约已经确定。以下是实施顺序，不是待选方案：

A. 建立来源记录、稳定持有者、独立技能账本、配置校验及等级/叠加计算。
B. 实现三类规则与当前移动/瞄准/后坐/操作/感知消费者，替换旧双重计算。
C. 接入仅人类机师、芯片/肌肉记忆渠道、配对同步成长、战局同步、比例痛苦反馈及机师自用道具；在未完成 C 前机器人演示必须明确使用测试机师实例，不能虚构正式 SIA 已完成。
D. 压力事件、EMP、入侵、人造血和灵能玩法按各自功能任务实现，向本架构提供状态和合法事件；不能另建属性公式。

各阶段必须满足以下可自动验证的条件：

1. 相同输入多次求值结果一致，输入完全不变。
2. 改变来源遍历顺序不改变结果；同一来源的重复引用不重复加成。
3. 人类和机器人通过不同内部数据达到相同输出时，同条件同装备下行为一致。
4. 技能增长只改变 XP/派生等级，基础来源值不变；药剂到期不删除经验。
5. 同一训练项目升级不重复叠旧奖励，exclusive 来源胜出和撤下行为确定。
6. 换部件同时撤销其 base/bonus；拆除部件功能正确归零；装回原部件恢复其额定来源而非旧损伤前状态。
7. 芯片移到新机体后 XP 与 ID 不变，原机体不能继续读取；机师技能不随芯片转移。
8. 机器人技能按机师 30%/芯片 70% 组合，缺芯片不归一化；仿生人 SIA 按机师 70%/本体肌肉记忆 30%，休眠意识不提供主动判断和心理状态。
9. 控制切换不把旧行动经验发给新持有者，不清后坐，不复制意识训练来源。
10. SIA 一次伤害只按受伤时同步率生成一次比例反馈；受伤后降同步、断连、换机师和反复查询不能更改或重复本次反馈。
11. 零操作能力不能以极小值兜底继续执行；机师灵能或装备加成不能给机器人/仿生人解锁灵能。
12. 正式场景和测试场对同一输入输出一致，测试场不写入持久 XP。
13. 读档恢复来源和持有者后重算，不依赖保存的派生值；失效引用和非法字段明确报错。
14. UI 的每项贡献能定位到持有者及物品/部件/意识实例，最终值与行为读取值一致。
15. 配对同步经验互相隔离、上限不超过 100%；换芯片不带走配对经验，整机更换不继承旧上限，同一 dt 不重复增长。
16. 0%、50%、100% 同步分别对应 0、0.5、1 倍反馈；降低同步同时降低 Q，同步针剂不能改经验或突破配对上限。
17. 非人类机师与仿生人承载的人类来源意识均被拒绝；高技能或装备加成不能绕过资格。
18. 战场单位不能使用别人背包或基地道具；机师针剂扣机师个人库存且只生成 controller 来源，不能加给旧机体或新机师。
19. 远程用药失败/取消不重复扣道具，机师用药期间远程主动输入暂停但疼痛反馈继续；读档不会再次扣除或复制药效。
20. 灵能规划记录区分实际消耗、施放 ID 和崩溃因果；策略禁用时不发 XP，不残留按次数 +1 的实现。

文档、新增测试、验证记录按仓库约定仅保留本地。后续代码提交不包含这些辅助文件。

## 13. 冲量后坐与主动补偿（试验版已实现）

每发先读取发射时实际枪口并生成子弹，然后增加角速度冲量；本发不受自己的后坐影响。下一发继承前一发留下的角度与角速度。不得在发射时重新随机生成“连射不稳定角”。

运行状态随当前武器保存：角度 θ、角速度 v、补偿建立程度 α、连射经过时间、距上次开火时间、预期单发冲量。换枪使用新武器状态；普通停止射击不清除运动，恢复由时间推进。测试场重置显式清空这些状态。

- 武器提供 impulse_degrees_per_second [水平随机冲量上限, 垂直冲量]、passive_return_frequency、max_offset_degrees。
- 角色能力提供 recoil_kick_scale、recoil_recovery_scale、recoil_response_delay_seconds、recoil_compensation_build_seconds、recoil_control_acceleration。
- 初始冲量倍率为 1/grip，延迟为 0.25/max(0.1,precision) 秒，建立时间为 0.35/max(0.1,precision) 秒，控制加速度上限为 180×grip 度/秒²；基准常量配置在 characters.rules.recoil_control，最终来源修正仍走统一能力规则。
- 无瞄准权限时主动控制加速度为零。基础支撑频率 w=武器 passive_return_frequency×max(0.25,recoil_recovery_scale)。其作用为 -w²θ-2wv，不会主动产生周期振荡。
- 经过反应延迟后，α 以配置时间常数指数趋近 1。主动纠正加速度为 α×clamp(-f²θ-2fv-预期冲量/射击间隔, ±控制上限)，f 由 return_frequency 配置。
- 预期冲量的水平分量为零，垂直分量使用当前单发冲量；只在距上发时间小于射击间隔时应用预期抵消。既抵消后续射击趋势，也追回已经积累的偏移。
- 超过 max(burst_gap_seconds,射击间隔×1.5) 未射击后，补偿记忆以 memory_decay_seconds 为时间常数衰减；新连射重新计反应时间，同时保留尚未消退的部分适应。
- 单次积分步长不超过 1/480 秒，基础临界阻尼用解析式推进，主动作用在每个小步内限幅。角度达到武器界限时截断向外角速度，禁止无界积累。

当前试验卡宾枪每发冲量 [3.6,13] 度/秒，频率 4/秒，偏移界限 [12,18] 度。射速、弹速未改。默认技能 10 的基准测试中，前几发上跳，建立补偿后接近目标高度；控制能力不足或武器冲量过强时不保证压回。

原来的正弦瞄准摆动、recoil_instability 状态及其额外散布已删除。普通瞄准误差使用有界、连续、不规则的目标漂移，drift_interval_seconds 控制变化尺度，不产生固定左右周期。枪械与弹药仍独立抽样；所有持枪偏差仍通过实际枪与双臂姿态表现。

准星中心固定目标。范围覆盖当前后坐偏移、瞄准误差和机械散布，不把瞬时枪口位置当成意图目标。测试场 K 键循环射击技能 0/10/20，清空试射状态后比较，不启用经验写入。屏幕“补偿”表示 α 建立程度，不表示已经消除了多少误差。

## 15. 持枪姿态与弹道接入（已实现）

能力层仍提供瞄准和后坐能力，不包含骨架或渲染规则。射击层将误差分为连续持枪偏移与枪械/弹药独立散布：前者驱动实际枪口，后者在发射时叠加。测试场骨架与帧内开火共用同一个姿态约束求解；上下瞄准、累计上跳和动作限位都反映到枪口三维轴线。达到限位后，弹道服从实际枪口方向。

姿态层与第 13 节的冲量后坐状态共用枪口方向；基础技能与来源权重保持不变。

持枪动作修正：目标准星固定在意图目标；范围覆盖所有持枪相位与机械散布，不跟随单个瞬时枪口。持枪误差仅由双臂与枪承担，稳定躯干和头部不参与周期晃动；瞄准待机动画固定取样。射击受力动作和技能/能力推导保持原职责。
