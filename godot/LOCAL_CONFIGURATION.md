# 配置与扩展说明

运行入口：根目录 Open Tactical Preview.cmd / Start Godot.cmd。
两个入口均进入角色与射击测试场；共用本工程的 data 目录与 SCData。战斗模拟逻辑仍保留，正式场景和界面尚待接入。
所有配置在启动时读取，编辑后重启生效。

当前美学目标集中于 [美学方向](../docs/art-direction.md)：方案 A、外层应用画布 2560×1440、内部画面依实体 CRT 比例、中文像素字体、内含采样与低强度动态干扰的 CRT 与完全无滤镜对照；严格纯顶视、丰富光影与按格占位服务叙事。独立维护站工具的 2K 干净场景进入 960×540 CRT 信号采样；舱室内嵌版本使用下节的 4:3 尺寸，中文像素文字避开场景低分辨率采样，再共享屏幕效果，字体按整数倍绘制。下述角色测试场参数记录当前实现，不作为最终美术约束。

本文记录当前运行版本。角色系统后续实现必须遵循 [角色属性、技能与能力架构规范 v4](LOCAL_CHARACTER_ARCHITECTURE.md)；来源、独立技能、统一能力和现有行为消费者已经接入。完整 SIA 生命周期、配对同步成长和痛苦反馈留待下一阶段；灵能经验策略明确禁用。

## 舱室显示器与嵌套画面（2026-10-02）

分层术语统一见 [美学方向第 3 节](../docs/art-direction.md#3-制作路线方案-a)。应用窗口／舱室画布是外层 2560×1440（16:9）；实体 CRT 玻璃是模型中约 4:3 的有效显示面；游戏源画面及 CRT 合成纹理为 1920×1440；CRT 场景信号为 720×540。不得把这些尺寸统称为“屏幕分辨率”。

`presentation/cabin/cabin.tscn` 保持实体玻璃和少量边框，通过相机靠近实现聚焦；内部画面填满玻璃，不加上下黑边、不拉伸物体。曲率由模型几何提供，复用维护站 CRT shader 时仅将曲率设为 0，并按 4:3 调整合成纹理与信号宽度，其他效果参数不变。鼠标经真实玻璃三角形和 UV 映射到游戏画面。

维护站嵌入视图按 4:3 调整相机渲染目标和文字位置；射击测试场使用 4:3 逻辑布局并等比缩放，工具文字暂随场景信号采样。独立维护站、独立射击测试场的原有 16:9 工具入口保持各自实现条件。

启动 `Open CRT Cabin.command`／`.cmd`。1 切换实时画面、2 开关 CRT、Enter／点击玻璃聚焦、Esc 返回桌前、F8 开关显示器电源。

## 最常调的参数

- 曳光长度：presentation.json → tracers.warm_tracer.length_m，目前 2.0 米。
- 曳光亮度/余迹：同一项的 brightness（0–1）与 fade_seconds（秒）。
- 弹速：ammunition.json → rifle_ammo.speed_mps，目前 300 m/s。
- 曳光频率：tracer_every_n_shots，1 是每发，3 是每三发；不影响命中。
- 射速：weapons.json → 对应型号 → fire_interval，每发间隔秒数；0.1 即每秒 10 发。
- 换弹：reload_time 秒；正式战斗与试验场均按当前 reload_rate 推进，试验场动画同步缩放。
- 移速：characters.json → rules.base.move_speed_mps 是基准；profiles 中各类型属性、状态和身体功能共同推导最终移速。
- 移动减速：characters.json → profiles → 对应类型 → movement_angle_curve，每个点为 [夹角度数, 速度倍率]。
  角度从 0 到 180 严格递增，相邻点间平滑插值。倍率为 0–1。
- 扭转限制：presentation.json → characters.humanoid，角度单位为度。
  运动曲线与骨架限制分别配置。

世界距离按 1 格 = 1 米，质量 kg，时间秒，角度字段用度；运行计算自行转换弧度。
只有 casing_socket_source_units 使用导入模型的源坐标单位，属于素材校准数据。

## 增加型号

1. 在 weapons.json 复制一个完整型号，修改字典键和 item.id，两者必须一致。
2. 配置名称、重量、射速等，并引用现有 ammunition 与 presentation ID。
3. 加入 tactical_study.json.weapon_choices，即可在试验场按 V 切换。
4. 在 units.json 的武器引用中选该型号，正式游戏生成对应单位时也会使用它。

武器物品条目、换弹用途与拾取名称/重量由武器定义生成；无需在 catalog.json 再填一份。
同类型号可以共用 rig 与 clips。新的外形/武器类别仍需要相应素材和握枪校准；
当前素材的武器节点名为 Rifle，枪管沿源模型 +Y，枪口由最前端顶点确定。
模型/动画引用并不意味着能自动把任意骨架转成兼容动画。

## 身体与能力

characters.profiles.<类型>.body 引用 bodies.json。身体定义包括：

- regions：分区及显示名称；各 parts 定义耐久、命中权重、伤害倍率、标签、额定 attributes 与 bonus_sources。
- fatal_parts / fatal_regions：任一列出的部件或区域耗尽，即判定死亡/失效。
- capabilities：movement、manipulation、vision 分别指定区域功能权重；功能归零即不可执行，不再保留能力下限。
- hit_bands：按角色高度比例从高到低排列，选择命中区域；最后一档必须从 0 开始。

人类使用生物部件；仿生人示例使用处理器和能源核心；机器人示例使用传感器、
机体、操作器和驱动器。能力计算和致命判断不再指定必须存在心脏、大脑、双腿。

## 定义与运行状态

定义是模板。SCActor 与 SCData.weapon 创建独立状态及定义副本，当前耐久、余弹、
冷却和后坐不写回共享 catalog。修改某个实例不会影响另一名同型号角色或另一把枪。

弹药的基础速度 × 枪械的 muzzle_velocity_multiplier = 最终弹速。
伤害来自弹药，射速/散布/后坐规则来自枪械；曳光和火焰等绘制参数来自 presentation。
正式战斗的子弹保存发射时参数，随后切换装备或角色状态不会重定向在途子弹。
启动时检查关键字段、数值区间和引用关系；配置不合法时报告路径并退出，不兼容旧格式。

## 当前范围

正式战斗已使用共用枪械、弹药、角色、身体和移动减速配置。
正式战斗改为有限速度直线子弹；逐步检测墙壁和角色，命中时结算。
试验场使用同一弹速、散布采样和碰撞几何函数，目标是静态圆靶，保留无限弹药便于美术观察。
试验场与正式战斗使用相同的瞄准进度、不规则连续瞄准偏差、枪械/弹药散布和冲量后坐规则。
白模与风格化外观共享每一发的散布采样，B 切换可见外观，重置后重复同一序列，便于比较。
每发子弹按帧内发射时刻推进；前后帧的基础动画姿态插值后，使用发射时保存的持枪偏移，通过与可见骨架相同的约束求解器计算枪口。
这不是逐发重算完整骨骼动画；急转、移动和受力位移仍使用帧间基础姿态插值近似，瞄准晃动与累计后坐不再通过最终弹道的隐藏偏角实现。
300 m/s 不变；近距离可能一帧内命中，命中后的尾迹按实际命中时间淡出。

## 射击数值

角度对统一为 `[水平, 垂直]`，单位度。accuracy_degrees 表示硬边界半宽，越小越精确；
不是直径、标准差或命中率。逐发散布采用有界三角分布，中心较密、边缘较少。

1. weapons.json 的 accuracy_degrees 为枪械固有散布。
2. weapons.json 的 attachments 为配件 ID 列表；attachments.json 的 accuracy_multiplier
   逐项乘到枪械精度，例 precision_barrel 为 [0.7, 0.7]。不缩放弹药误差或瞄准误差。
   当前仅配置精度修正，尚无配件装备界面；默认武器没有装备配件。
3. ammunition.json 的 accuracy_degrees 为弹药的独立散布，另外抽样。
4. characters.json 的 rules.base 定义基准瞄准速度与误差，rules.aim 定义进度损失、衰减和摆动参数；射击技能、身体和控制状态通过统一能力影响瞄准与后坐，不修改枪械/弹药固有精度。
5. weapons.json 的 recoil 为实际弹道后坐；presentation.json 的 recoil 仍只控制动作弹簧。

aim_progress 在运行时取 0–1。稳定瞄准时以当前能力 aim_gain_per_second 增长；移动按 movement_loss_per_m、大幅转向按 turn_loss_per_degree 扣减；
未瞄准或换弹时按 idle_decay_per_second 衰减。切换目标保留 switch_retention 比例。
正式 AI 达到 minimum_fire_progress 且反应时间满足才射击；测试场允许未瞄准就开火。

瞄准半宽 = settled_degrees + (unsettled_degrees - settled_degrees) × (1 - aim_progress)^curve_power。
该半宽内的瞄准偏差使用连续不规则漂移，drift_interval_seconds 控制变化尺度，不再使用正弦周期；逐发不会跳成全新随机瞄准点。
瞄准完成仍保留 settled_degrees，且不会抹除枪械与弹药散布。

recoil.impulse_degrees_per_second：[水平随机角速度冲量上限, 垂直角速度冲量]。当前 [3.6,13] 度/秒。
max_offset_degrees 为角度安全界限，当前 [12,18] 度；support_frequency 为连射中身体支撑频率，当前 4/秒，不用于停火回正。
characters.rules.recoil_control 配置辨识时间、训练各项收益、补偿建立时间、身体控制上限、纠正频率、后坐预估及一次过补偿。
统一力量、精细执行、感知、控制有效性与射击训练分别推导各输出。训练不直接增加身体控制上限。完整函数和状态方程以架构规范第 13、16 节为准。
高力量低训练角色首次补偿时可能下压过头；同一段连射只允许一次，不采用低阻尼振荡。
松开扳机立即结束本段后坐，把可见偏移交给重新瞄准；不保留后坐速度或短暂停顿补偿记忆。重新瞄准按 aim_gain_per_second×rules.aim.realignment_degrees_per_progress 推进，默认后者为 90°；再次提前开火继承剩余偏移。

一次射击先读取旧状态，采样方向并生成子弹，然后向角速度记录后坐冲量；本发不受自身后坐惩罚。
开火不扣除 aim_progress，避免重复惩罚。测试场按帧内发射时刻拆分瞄准与后坐运动。

## 俯仰、高度与括号准星

每发子弹保存三维单位方向（水平角+俯仰角）、实际弹道速度、已飞行距离和当前高度。
当前为无重力直线弹道；300 m/s 指沿弹道的速度，不是水平速度。枪械与弹药精度、瞄准
偏差和后坐都能改变水平角、俯仰角。子弹发射后不追踪目标。

正式战斗从 muzzle_height_m 发射，默认瞄准目标 height × chest_height_fraction。
正式战斗的平面起点为角色中心；测试场读取动画后的实际枪口。
目前角色仍为站立姿态，地面高度为零。以后新增姿态时应提供对应身体与枪口高度。

沿整段路径连续检测地面、掩体侧面/顶面、窗台/窗楣和角色圆柱；高速跨帧仍检测经过的区域。
角色命中区域根据碰撞时真实高度选择，区域内具体部件继续用 bodies.json 权重。

测试场括号是目标距离处的水平角误差包络，不是命中率或保证命中范围；掩体会进一步遮挡。
目标点与括号中心固定在玩家指定的位置，绝不跟随当前持枪晃动。左右括号对称包含完整瞄准误差、累计后坐偏移、枪械/弹药散布以及枪口绕握点转动的位移余量；后坐使范围扩大而不移动目标中心。范围根据不含瞬时晃动的基准持枪姿态求值。垂直偏移与范围显示
在“预计弹高”中，避免在垂直顶视图里把高度误画成地面位移。括号短边只为辨识，不表示高度。

H 循环瞄准高度（默认 1.25 / 0.65 / 1.65 米）；1–8 切换射位，C 下一射位。
靶高、半径和瞄准高度列表在 tactical_study.json.target。
靶子圆环表示实际目标，括号跟随鼠标瞄准位置；右键对准附近靶心，不移动靶子。

## 射击场与轮廓阴影

tactical_study.json.range：

- bounds_m：[左, 上, 宽, 高]，当前固定 28.8 × 10 米、40 像素/米，完整场地显示在 1152 × 400 像素区域。
- lanes：8 个射位，label 为名称，spawn_m 为人物位置，target 引用 targets 的 id。射位切换保留靶子命中次数，Tab 重置清空。
- targets：id、label、position_m；当前共用 target.radius_m 与 height_m。按射线最早接触的目标累计命中。
- obstacles：id、label、kind（cover / wall）、rect_m（左、上、宽、高）、height_m。绘制、人物碰撞与子弹高度检测使用同一份几何。
- impact_lifetime_seconds：弹着点保留秒数；maximum_impacts：数量上限。

默认四个无遮挡距离为 3 / 6 / 10 / 15 米，另四个为 6 米靶的矮掩体、高掩体、实墙和缺口。
距离名称是射位至靶心距离；实际弹道从侧面的枪口发射，靶旁“距你”随人物移动更新。
0.8 米矮掩体可被高弹道越过，1.3 米高掩体可用 H 抬高瞄准越过，2.6 米墙阻挡正常站姿射击。
命中由实际弹高决定，未稳定瞄准或连续射击的误差仍会改变结果。没有新增穿透、攀越或蹲姿。
人物按半径阻挡并沿墙滑动；枪管越过墙面时子弹起点限制到接触处，避免穿墙生成子弹。

presentation.json → characters.humanoid.style.shadow：color 为阴影色，opacity 为 0–1 透明度，
offset_pixels 为 40 像素/米视图上的平移量（默认 [3,4]）。放大视图按三倍缩放。
阴影使用角色当前帧纹理的 alpha 轮廓，包含身体、手臂及枪械，随转身与动作同步更新。
这是平面剪影贴地阴影，不是随灯光投射、接收场景光照的真实阴影。

## 美术尺度与分辨率一致性（全项目规则，2026-09-30）

高分辨率应呈现同一画面的更清晰版本。在相同角色姿态、相机、构图、特效时间和随机种子下，将不同分辨率的内容区域缩到同样大小后，角色轮廓、明暗、纹理颗粒、滤镜和特效的视觉比例及风格应基本一致。观察视图或相机放大场景时，属于角色和场景的美术表现应一起放大。

本规则适用于整条表现链路：模型材质、全部着色器、后处理和滤镜、渲染纹理、描边、阴影、噪声、笔触、网点、像素化、粒子与程序绘制特效。未来新增效果也必须遵循；角色测试场未加入这些效果；独立维护站仅采用 CRT 后处理，保留低强度噪声和滚动干扰，不另加像素化层。

### 尺度定义

- 世界或模型尺度：角色、武器、场景上的纹理密度、火焰、烟雾、阴影等，以米、模型局部坐标或固定的 UV 规则定义，跟随相机或观察倍率。
- 设计画布尺度：界面、图表和画面固定效果，以明确的设计尺寸定义，跟随画布等比缩放。当前角色测试场设计尺寸为 2560×1440，使用 Canvas Items + Keep + Fractional。界面提示可独立于相机放大，但必须明确标记为界面效果。
- 渲染采样尺度：纹理像素、屏幕像素和渲染目标尺寸只用于实现上述尺度的采样换算。提高采样分辨率不能自行改变效果宽度、颗粒疏密、纹理重复次数或滤镜强度。

空间尺寸、模糊半径、描边宽度、光晕范围、颗粒大小需要随其所属尺度换算；空间频率须相应换算，以保持相同区域中的颗粒、网点或笔触数量。颜色、透明度、对比度、色阶档数、明暗阈值、随机种子和以秒定义的动画时序保持原有意义。不得把所有着色器参数统一乘一个分辨率倍率。

### 换算与实现约束

以基准视图设计像素定义的场景效果，最终显示尺寸 = 基准尺寸 × 观察/相机倍率 × 画布倍率。设计为 1 像素的角色描边，在 2K 主视图为 1 像素、3 倍观察为 3 像素；相同构图的 4K 窗口中分别为 1.5 和 4.5 像素。

角色纹理的基准投影边长目前为 104 个设计像素。源纹理边长为 R 时，一个基准设计像素对应 R/104 个源纹理像素；源纹理采样核应保持该换算，观察倍率由显示变换体现。提高 R 只增加采样精度，不抵消观察放大。

使用 TEXTURE_PIXEL_SIZE、SCREEN_PIXEL_SIZE、FRAGCOORD 或硬编码像素半径的效果，必须说明其参数属于哪种尺度，并经过相应坐标换算。随机纹理应固定其锚定空间与种子；调整分辨率不能重新排列图案。共享纹理或效果状态可以复用，各视图的尺度换算不能使同一美术效果出现不同的相对比例。

粗糙感、色块、颗粒和笔触属于美术设计，须保持设计的大小和疏密。提高渲染精度时，应更准确地呈现这些特征。抗锯齿、线性过滤和采样质量的调整，也需要检查它们是否改变了预期的粗糙程度。

### 检查标准

分别检查窗口分辨率变化、源纹理分辨率变化、观察或相机倍率变化。至少覆盖 1920×1080、2560×1440、3840×2160，以及 Keep 下非 16:9 窗口的内容区域；比较时排除留边并统一内容尺寸。固定姿态、时刻和种子，检查相对轮廓宽度、阴影偏移、颗粒密度、滤镜空间周期、特效范围及强度。

允许因采样、抗锯齿和像素对齐产生少量边缘差异，不要求逐像素完全相同。只验证纹理分辨率提高、输入坐标正确或模型尺寸不变，不能证明整套美术表现已符合本规则。

### 当前实现的尺度归属

- 角色描边：主视图与 3 倍观察共用源纹理尺寸 / 104 的设计像素换算。显示变换同时放大角色及描边，窗口倍率再作用于完整画面。
- 角色三档明暗、剪影阴影、测试场火焰/烟雾/曳光/弹壳等沿用此前正确的模型、世界或设计尺度，不新增重复倍率。

## 维护站描边

维护站采用完整物体投影的外轮廓，内部零件、颜色交界、高低变化和封闭孔洞不加线。`object_outline.gd` 复用原网格／骨架生成身份遮罩，`outline.gdshader` 将外边界合成到干净底图，之后进入 CRT。现有表面配色保留。阴影和光照不参与内部边缘提取。

基准线宽为 2K 画布 3 像素，随观察倍率缩放；N 对照描边开关。当前外部区域检测在限定像素距离内排除封闭孔洞，新素材及扩大缩放范围需重验。下述角色测试场的纹理描边参数不控制维护站。

## 已接入的角色架构

种族属性与独立技能账本 → SCAbilityRules → 当前只读能力快照。移动、操作、感知和射击只消费最终能力；不再在消费者中重复乘伤势系数。

- 基础来源保持不变；成长写入意识/芯片的技能 XP，训练、药物和装备以独立来源贡献数值。
- 技能等级为 min(20, sqrt(XP / 100))。现有单位显式配置射击和医疗各 10000 XP，以保留原有射击与包扎速度；其他技能为 0。
- 机器人工作技能由机师 30% / 芯片 70% 提供；仿生人 SIA 为机师 70% / 本体原始技能 30%。只有人类可成为机师。
- 单一来源按 source_id 去重；贡献先加算，再百分比加算，再倍率连乘；互斥组按优先级和稳定 ID 决定胜者。
- 部件替换同时撤销旧部件的基础值与加成；运行中的操作按最新能力推进剩余工作量。
- 正式射击和治疗结算经验，取消治疗只按已完成的工作量计经验；测试场禁止经验写入。
- 测试场按 F2，或正式游戏“伤势与携带详情 → 属性、技能与来源”，可查看当前快照与来源持有者。查看测试场面板时暂停，关闭后恢复此前状态。

测试场机器人使用独立的人类测试机师，连接质量 100%、同步率及上限 60%。这些是验证输入；尚未实现基地分配机师、完整连接切换、同步经验成长、伤害痛苦反馈和远程针剂。配置中 sia_synchronization 参数为下一阶段的确定契约，目前不推进其状态。

## 实际持枪晃动与弹道一致性

SCCombat.holding_error 汇总随时间连续变化的瞄准晃动、累计后坐；其结果只驱动双臂和枪；躯干与头部仅对准指定目标，不参与周期持枪误差。SCCombat.mechanical_error 只抽样枪械与弹药本身的误差。两种外观共用同一次采样。

测试场从约束后的三维枪管轴线发射，再叠加 mechanical_error。水平、俯仰都来自实际姿态；到达动作限位后不会通过隐藏弹道偏移补足。目标高度也参与姿态解算。枪口焰跟随可见枪口，弹壳从相应发射姿态的抛壳口生成。

presentation.characters.humanoid.aim_pitch_limit_degrees 控制枪口相对水平面的上下瞄准限位，当前 ±35°；waist_limit_degrees 与 aim_limit_degrees 约束水平动作。开火受力使用位置后坐弹簧，角度偏移由武器角速度冲量与主动补偿处理。瞄准基础动画固定取样，避免素材待机变化带动身体。双臂使用两段骨骼求解，先限制共用握持变换的可达范围，再保持双手握点与臂长；无法达到的角度不转嫁给子弹。

正式战斗尚未使用此骨架，使用共享 holding_error 与 mechanical_error 计算概念枪口朝向，平面起点为角色中心。主动压枪共用角色规则与射击状态。

准星范围指未受掩体截断的弹道在目标距离平面上的横向区间，高度区间单独显示；碰到掩体、地面或其他物体可以提前结束弹道。目标位于当前可发射方向的侧后方、误差锥横跨目标平面平行方向时，不显示虚假的有限括号，仍保留固定目标标记。

测试场按 K 循环射击技能 0 / 10 / 20，保留其他属性并清空当前试射状态；可按住左键观察起跳与持续射击后的收敛。补偿百分比是控制建立进度，不是命中率或误差消除比例。
按 J 循环标准 / 强 / 弱力量条件（当前身体力量的 1 / 2 / 0.3 倍），通过现有通用 force_n 来源修正生效，不改种族基础属性或经验。可与 K 组合观察弱力量高手、强力量新手；F2 显示反应时间、力度上限、纠正速度、预估比例和一次过补偿目标。测试条件不属于正式装备。

测试场使用 2560×1440 设计尺寸，Canvas Items + Keep + Fractional 等比缩放；非 16:9 窗口留边。此设置只在测试场运行时应用。三个侧栏为角色能力、武器与弹药、弹着与统计，参数栏可滚动。场地保持 40 个设计像素/米，动作观察为 3 倍；鼠标坐标由 Godot 的窗口变换统一换算。
