# 铁眼：美学方向

更新日期：2026-10-10。

本文是场景、角色、光影、滤镜和 UI 的统一美学依据。目标是硬核俯视角战术射击游戏。设计变更直接覆盖相关要求，不并列保留被替代的方案。本文记录设计目标及待验证路线，不表示运行版本已经实现，也不直接授权修改代码。

## 1. 整体目标与参考作品

采用三维建模与动画，最终呈现复古、粗糙的二维像素画质感。人物与物体保留可信的比例、结构、重量和用途，整体气质严肃，具有具体的生活、工作与事件痕迹。不要玩具比例、可爱模型陈列感或无厘头的夸张气质。工业设计体现在功能与构造中，场景主题不限于机房或工厂。

大部分实体应有描边，形体和部件颜色经过归纳。场景需要丰富的光影，通过局部照明、明暗分区、投影和颜色关系建立空间与气氛。表面材质可以简单，光影仍应有丰富的变化和明确的视觉主次。

外层应用窗口的设计画布为 2560×1440；CRT 内部画面的比例由实体玻璃决定，分层定义见第 3 节。以干净、类似矢量画的三维渲染为底图，直接叠加老显像管电视效果，由 CRT 自身的信号采样、扫描线与荧光栅格形成像素感，不另加像素化层。物体边缘应锐利、描边连续，避免毛刺、闪烁和文字糊化。CRT 包含轻微颜色偏移与暗角；舱室内的曲面效果由实体玻璃几何产生，CRT shader 不再叠加曲率，并随时允许完全关闭所有后处理查看原图。

### 参考的整合方式

以下作品用于参考最终画面及场景表达，不据此推断它们使用相同的三维渲染技术。参考作品不限制视角，本项目的战斗视角仍遵循第 2 节。

| 参考作品 | 本项目借鉴的方向 | 使用边界 |
| --- | --- | --- |
| [Holstin](https://store.steampowered.com/app/2235430/Holstin/) | 像素画观感与丰富光影的结合；可信的生活空间、受光形体与环境气氛。 | 参考公开画面与演示，不照搬其旋转视角，不预设其技术方案适用于本项目。 |
| [SIGNALIS](https://store.steampowered.com/app/1262350/SIGNALIS/) | 严肃的工业科幻与复古技术气氛；归纳的形体、局部照明以及场景、角色和设备界面的统一。 | 不照搬世界观或剧情；具体像素化与描边方法由本项目小样决定。 |
| [The Last Night](https://store.steampowered.com/app/612400/The_Last_Night/) | 像素形体与丰富彩色照明共存，光源及亮暗层次塑造空间。 | 仅参考公开预告和截图，不据此认定完整关卡或叙事效果；不把所有场景限定为霓虹夜景。 |

整合目标是：以 SIGNALIS 的严肃复古科幻气氛建立基调，以 Holstin 和 The Last Night 的光影表现探索画面层次，以 CONSCRIPT 的用途与事件痕迹帮助组织叙事性场景。具体配色、颗粒和描边由统一小样协调，不把各作品的效果直接堆叠。

## 2. 视角与共同资产基础

本节的纯顶视约束作用于 CRT 内部的战场相机。外层舱室使用坐在桌前的透视视角，可以看到显示器侧面与机壳；聚焦仍使用该舱室相机。

战斗画面采用严格的正交纯顶视：相机垂直向下，视线与地面垂直，不使用透视或倾斜视角。战斗场景及用于验证的美术小样不得露出物体侧面；墙体只显示俯视截面，家具、设备和角色按正上方观察的轮廓与顶面表现。参考作品采用其他视角，不改变此规则。

采用的方案 A 以三维模型为基础，角色复用现有骨骼与动作。二维观感是最终呈现目标；是否需要中间渲染纹理、预渲染资产或局部手绘修整，属于待验证的制作细节。

环境道具使用其他作者已经完成、具有明确来源和完整结构细节的现成模型，不以程序组合基础体块代替柜体、控制台、箱子、车、凳子等成品模型。可按部件自行归纳上色，保留原始几何、内部建模细节、比例及部件关系。墙体俯视截面、地面、占格底板与门槛标记仍作为游戏空间和规则的基础几何。不同来源的素材需要统一比例、材质尺度、轮廓、光照和落地关系。风格化不改变真实占地、掩体高度、通行与遮挡事实；纯顶视不取消战斗模拟中的高度信息。

现有角色的细节密度可作为小样起点，最终细节取舍以正常游戏倍率及滤镜后的结果为准。放大观察用于辅助检查，不能代替正常倍率判断。

## 3. 制作路线：方案 A

已确认采用方案 A：先用三维模型、材质与光照形成干净、类似矢量画的底图，再通过后处理建立像素观感。“矢量画感”描述最终外观，不要求使用矢量文件。底图保留清楚的轮廓、按真实部件归纳的色块和丰富光影。

### 场景名称与设备内容

默认入口为**舱室主场景**。左、中 CRT 承载**CRT 内部场景**，当前包含**地下维护站预览场景**和**角色与射击测试场景**；右侧 **AEON 实体设备**显示独立的 **AEON 终端界面**。名称、实现位置与架构职责集中定义在 [设计第 16 节](../combat_demo/docs/demo_design.md#16-项目职责与实现边界)。

舱室采用桌前透视视角；CRT 内部场景遵循正交纯顶视。AEON 终端界面采用黑绿信息显示，其内容布局与命令待确认。实体设备的玻璃、仪表和旋钮属于舱室中的三维对象，终端界面是其屏幕内容。

### 嵌套视角与“屏幕”的分层定义

文档、参数和讨论不得单独使用“屏幕分辨率”指代以下不同对象，必须写明层级。

| 名称 | 指代对象 | 比例、分辨率与职责 |
| --- | --- | --- |
| 应用窗口／舱室画布 | 玩家电脑上的整个游戏窗口，呈现舱室、桌面与显示器模型。 | 设计画布 2560×1440（16:9）；本次不修改外层窗口比例。实际窗口像素尺寸可变化。 |
| 实体 CRT 玻璃／有效显示区 | 舱室内显示器模型的可显示弧面，不含机壳、边框、按钮和扬声器。 | 当前模型约 4:3。它决定内部游戏画面的目标比例；圆角和物理弧面保留。聚焦保持玩家坐姿，仅通过转头和取景完成，三台显示器固定在桌面，保留实体边框，不切换全屏覆盖画面。 |
| 游戏源画面 | 战场相机和游戏 UI 生成、送入显示器的干净画面。 | 左、中 CRT 默认显示地下维护站预览场景，可手动切入角色与射击测试场景；两种游戏源画面均为 1920×1440（4:3）。相机和 UI 按这个比例构图，不拉伸 16:9 内容，不以裁掉操作界面或上下黑边适配玻璃。战场本身仍为严格正交纯顶视。 |
| CRT 场景信号 | CRT shader 对游戏场景的低分辨率采样网格。 | 保持 540 行密度，随当前 4:3 有效显示区使用 720×540。它不决定应用窗口大小，也不改变物体比例。 |
| CRT 合成纹理 | 重建后的信号与独立文字层合成、最终贴到实体玻璃上的纹理。 | 1920×1440（4:3），填满有效显示区；它不是一张覆盖应用窗口的全屏图片。 |

CRT 管线为：4:3 地下维护站预览场景／角色与射击测试场景的源画面 → 720×540 场景信号采样与扫描线重建 → 1920×1440 CRT 合成纹理 → 实体弧面玻璃 → 舱室相机 → 应用窗口。外层窗口可保持 16:9；CRT 内部不得再为 16:9 源画面保留上下黑边。

中文像素文字和 UI 的目标仍是独立透明合成层，避开场景的 540 行采样，再共享通道分离、栅格、暗角与动态干扰。关闭 CRT 时，干净游戏源画面与文字直接合成，实体玻璃和边框仍然存在。鼠标依次经过窗口坐标、玻璃三角形相交、玻璃 UV、信号偏移和游戏源画面坐标换算。

舱室显示器的 shader 曲率为 0：曲面来自模型，不重复弯曲内容。独立维护站预览仍以 2560×1440／960×540／shader 曲率 0.30 运行，作为现有独立工具的实现条件，不代表舱室显示器的尺寸要求。原验证数据只适用于各自记录的条件。

## 4. 物体、描边与丰富光影

### 形体与颜色

物体保留可辨认的轮廓、主要结构和固有色。主体、动力组件、框架、管线、仪表与控制件按真实部件边界分配颜色；同类部件可共用颜色，少量关键细节使用强调色。禁止按世界高度或局部高度机械切分配色。

上色从原物体的用途、材质和涂装提取主体色与部件色，保留主要色相及配色关系。例如黄棕色罐体归纳后仍保留相近的黄棕色，污损和照片光影不逐处复制。有意改变原有涂装配色时单独讨论；场景灯光对表观颜色的影响应与固有色区分。

减少照片纹理、密集划痕、锈斑和写实材质响应，不依赖精细法线与高频反光表达结构。地面保留有助于叙事和空间辨识的接缝、边界与使用痕迹，避免均匀铺满颗粒。滤镜后的抽象程度应让类别、用途和关键部件仍可辨。

### 描边：只标出投影外轮廓

每件物体按当前视角下的完整投影处理，只在投影外边界描线。同一物体的零件接缝、颜色交界、内部高低变化及封闭孔洞均不新增描边；内部细节依靠现有部件配色和正常光影区分。保留当前按部件上色的成果。

角色的身体与武器作为一个整体投影，环境道具按完整物体分组。外轮廓保持接近的可见宽度，观察放大时随场景一起变粗，不受模型导入缩放影响。物体之间的遮挡必须正确，不能把被遮住的轮廓画到前景上。

维护站以物体标识图识别投影边界，表面颜色与光照独立绘制；标识图复用原网格和骨架并同步可见性。当前合成只检查不同物体的边界，排除封闭的内部空隙，不提取法线、材质或内部高度边缘；表面高度仅用于遮挡排序。基准线宽为 2K 画布 3 像素，随观察倍率变化。现行孔洞检测已针对当前素材和正常游玩缩放验证；新素材或更大孔洞仍需重新验看，不能把有限的邻域检测当作任意形状的通用保证。

N 用于同一画面描边开关对照。验看重点是外轮廓连续、内部颜色与细节完整，以及角色动作和缩放时的轮廓一致性。描边线宽与最终观感仍待用户验看。

### 光影

场景应有丰富且有主次的光影。光源应属于具体的空间用途或事件状态，例如工作灯、走廊灯、窗外光或仍在运行的设备。明亮操作区、昏暗通道、被物体切开的光区和投影共同组织视觉重点。

表面细节归纳不限制场景的光影丰富度；局部明暗可以简化，但不同光源、投影、遮挡与亮暗区域需要构成完整空间。彩色照明、柔硬阴影和亮部处理的具体程度通过小样确定，不预设固定的明暗层数，也不把所有区域均匀照亮。

角色与场景共享协调的受光和阴影关系，确保人物有重量、物件落地。纯顶视下重点利用顶面的受光、地面光区与投影表现体积，不用倾斜相机增加侧面信息。此处是美术目标，不新增明暗影响潜行或感知的玩法规则。

## 5. 场景搭建服务于叙事

每个场景先明确原本的用途、使用者及发生过的事件，再决定物件、布局、损坏与照明。玩家应能从空间关系推测这里曾经怎样运作，以及现在什么事情发生了变化。

物件围绕具体活动形成有主次的组合：工具依附工作面，零件围绕检修对象，物料靠近存放或使用位置，管线接入设备，生活用品对应使用者。避免无目的地松散摆放、逐格陈列模型，或用增加杂物数量代替叙事设计。

密集区与留白都需要理由。人的操作空间、运输路线、临时封堵和撤离方向共同决定通道。废弃与破坏从正常使用关系推导，例如未完成的维修、被搬空的储位或中断的工作；不要靠随机旋转、均匀散布垃圾制造气氛。灯光也应参与叙事，帮助玩家先注意到有意义的区域。

搭建前用简短文字说明场景用途、事件及预期可见线索，并据此组织少量道具组合。具体场景主题和故事尚未定案，不把参考作品的题材或讨论中的例子自动变成关卡设定。

### 房间布局与寻路网格

沿用 1 格 = 1 米。环境物品尽可能落在一个格子或明确的整数格矩形内部，设备组合、桌面与储物区的可见占位和移动阻挡使用同一组格坐标。小零件依附所属桌面或底座，不单独割碎通道。保持物体比例，优先选择合适尺寸或等比例规格，禁止为填格单轴拉伸。

较小设备可通过合理的底座、配套部件或成组储存明确填满其占格范围；留白仍服务用途与叙事，不把物品变成逐格展品。地面网格与占用区边缘协调，使玩家能识别完整可通行格和已占用格。

门也按格组织，门洞、门槛和门格宽度一致；门打开时门格通行，关闭时可见门扇与阻挡状态一致。不能出现半格缝隙看似可走、实际却被整格阻挡的布局。维护站小样使用现成三米卷帘门模型，门洞与门槛为三格宽，关闭时阻挡对应的三个门格；开启时隐藏收起的门扇并开放门格。角色位于任一门格内时不允许关闭。

房间布局与叙事表达单独验看，通路检查通过不能替代美术认可。新增物体的表现不得与实际通行、掩体和弹道几何矛盾。

## 6. 角色与动作

角色使用可信的身体和装备比例，保留现有三维骨骼、移动、开火和操作动作的成果。轮廓、部件色块、受光与阴影和场景统一，人物在最终画面里应自然融入环境。

不通过夸大的头身比、玩具般的圆润造型或无厘头动作建立风格。细节取舍围绕姿态、朝向、武器类别与动作辨识，不增加密集衣料纹理迎合写实材质。CRT 处理后，枪口、肢体姿态、移动与操作的区别及战斗反馈仍须清楚。

## 7. CRT 效果与无滤镜对照

参考并适配 [c64cosmin 的 Realistic CRT shader](https://godotshaders.com/shader/realistic-crt-shader/)（CC0）。来源与原作者署名保存在 shader 和素材许可中。后处理只保留这一条 CRT 管线，不在其前面另加像素化。

当前包含以下效果：

| 效果 | 表现与约束 |
| --- | --- |
| 信号采样与横向柔化 | 舱室内按 720×540 信号网格取样，通过横向高斯滤波重建到 1920×1440 CRT 合成纹理；应用窗口尺寸独立。 |
| 扫描线 | 三行高斯重建模拟电子束亮度，保持中间区域和文字可读。 |
| RGB 荧光栅格 | 显像管的红绿蓝子像素纹理，强度较低。 |
| RGB 通道分离 | 红蓝通道向相反方向偏移，绿通道轻微纵向偏移；应能看到彩边，不再把分离结果弱混合回原通道。 |
| 曲面 | 使用实体玻璃几何；舱室 CRT shader 曲率为 0，鼠标按实际玻璃求交映射。 |
| 暗角 | 边缘逐渐变暗，中央信息保持清楚。 |
| 动态噪声 | 保留低强度信号颗粒；默认幅度参数 0.012，随 CRT 强度调整。 |
| 滚动与行干扰 | 保留低强度移动亮带和轻微横向偏移；默认滚动幅度 0.035、行干扰参数 0.02，避免大幅撕裂。 |

默认总强度为 0.4，RGB 分离为 1.5 个 CRT 合成纹理像素，滚动带经过时略有变化；横向高斯参数为 -4，扫描线参数为 -8，滚动速度为 0.65。除本次明确调整的内部比例、信号宽度与 shader 曲率外，其他 CRT 参数沿用此前测试值。

舱室实验按 1 在测试房间与射击预览间切换共用画面来源、2 开关 CRT，失焦时鼠标转头、左键聚焦视野中心设备，F1／F2／F3 保留三屏快捷聚焦，Esc 返回观察或释放鼠标、F8 控制当前显示器电源。独立维护站工具仍使用 V／F／方括号。空格暂停角色与信号时间，噪声和滚动效果一起冻结。关闭 CRT 必须绕过信号采样、柔化、扫描线、栅格、色偏、曲率、暗角及动态干扰，恢复干净合成画面。

观看质感尚未确认世界观身份，不据此新增监控或通讯玩法。表现不得泄露隐藏单位或虚构战术状态，信息来源遵循既有规则。

## 8. UI：两千年代的复古科幻

UI 沿用两千年代对于未来科技的想象，与严肃工业科幻气氛和粗糙画面协调。任务、队员、身体、武器、装备与操作状态是内容来源；分区、边框、标签、编号、状态栏和设备示意图形成可信的设备界面。

文字采用支持中文的像素字体，按字体基础像素尺寸的整数倍绘制，避免文字额外降采样或过度模糊；面板、强调色与动效仍需设计。颜色与战场和战术标记协调，关键状态同时依靠文字、形状或状态变化表达。不添加无意义的随机数字、虚假追踪框或伪雷达目标。

高频空间操作继续直接在战场完成，界面帮助玩家找到信息、区分状态和理解操作后果。本次美学更新不改变操作与指挥规则。

## 9. 制作与验证

直接在引擎内使用实际模型搭建，不生成 AI 模拟场景图，也不以程序拼绘设备图标作为成品美术。先验证代表性模型、现有角色、叙事性布局与光影，再扩大制作。

共同资产归纳部件固有色、移除干扰结构的照片纹理与密集材质噪声，保留建模结构。制作干净底图后，分别验看干净原图和 CRT 合成结果，同时检查动态噪声与滚动干扰。

在 2K 目标分辨率及正常倍率下检查：

- 物体边缘锐利，描边连续；移动与缩放时没有明显毛刺或闪烁。
- 中文与英文像素文字清楚，不经过额外像素化；曲面状态下的鼠标位置与画面目标一致。
- 设备、家具、组合底座及门的占格可辨；可通行格连续，门开闭与碰撞一致。
- 丰富光影、严肃比例与叙事情境共同成立，CRT 不掩盖场景的结构问题。
- 一键无滤镜模式确实绕过全部后处理；关闭和恢复状态一致，暂停能够冻结动态干扰。

遵循 [美术尺度与分辨率一致性规则](../godot/LOCAL_CONFIGURATION.md#美术尺度与分辨率一致性全项目规则2026-09-30)。CRT 信号密度以 2K 设计画布为依据；场景内容随观察倍率变化，文字在合成层按像素字体的整数倍尺寸呈现。不同窗口尺寸应保持相同场景构图与交互坐标，优先验证整数缩放下的锐度。

桌面手机采用用户提供的 Field Terminal V5 灰色直板手机（`field_phone_v5/field_phone.glb`），由 Blender 源文件导出并保留原图像材质、独立实体按键、四向导航环、屏框和保护镜片。外廓约 52.33×125×23.31 mm，底部贴合原桌面位置；聚焦镜头保持正上方垂直俯视。`field_phone.gd` 绑定模型和 128×96 彩色液晶界面，复用 `retro_phone.gd` 的按键、音频和通话接口。绿色电话键、OK 和左软键负责呼叫／接听，右软键负责清除／拒接，红色电话键负责挂断；数字键和导航环保留实体压下动画，菜单方向操作待玩法接入。键盘数字及 *／# 输入号码，Enter 呼叫／接听，Backspace 清除／拒接，End 挂断，Esc 返回观察，I 触发演示来电。旧 Nokia 模型、贴图和去标识材质已清理。

`retro_phone.gd` 管理液晶界面、实体命中、按键音、呼叫回铃、来电铃声和 3D 声音。`phone_call.gd` 管理空闲、呼叫、响铃、接通中和通话状态，以及通话时长和会话编号。默认舱室演示在拨号两秒后接通、接听后短暂等待接通；这是本地预览适配器。玩法接入时关闭 `preview_backend`，监听 `call.outgoing_requested`／`call.answer_requested`／`call.ended`，通过 `receive_call`、`connect_call(session_id)`、`remote_end(session_id)` 驱动真实游戏事件，通过 `play_voice(AudioStream)` 播放游戏内通话音频。退出焦点保持通话／响铃；挂断后迟到的接通事件不能恢复旧会话。联系人、剧情路由、通话内容和世界事件仍待游戏系统接入。

桌面右前方保留弹簧橡皮鸭，牛顿摆已移除。用户授权整件玩具直接改造，以 Kin Chen 的 Toy Duck（CC0）形体为基础，鸭身细分并调整曲面，加入浅压痕和贴合表面的分模线；现行鸭体资源为 14,952 个三角面，原颜色贴图仅保留面部、嘴部等区域识别。塑料、底座旧漆和钢丝采用新的不透明材质与分区贴图，旧透明磨损层已移除。塑料有明显褪色、污渍和擦伤；黑色眼部的光泽来自实际场景照明，去掉原贴图中的白色假高光。底座为带压边与凹台的旧漆金属盘，包含接头、紧固件和底部橡胶垫；弹簧采用圆滑钢丝及接近闭合的端圈，表现暗钢、磨亮区和局部氧化。底座固定，鸭身与上接头一起小幅摆动，弹簧通过两骨骼权重随之弯曲；两端与固定底座和移动接头保持贴合。模型正面仍朝向固定玩家眼位。失焦对准模型按左键施加有限摆动，重复拨弄限制幅度，随后阻尼回到静止；它不能进入设备焦点。摆动为视觉近似，不参与玩法物理结算。

舱体小样位于 `godot/presentation/cabin/cabin_shell.gd`。当前净空间约 2.16×2.50×1.715 米，左右内壁分别位于 x=±1.08 米；两侧各内收约 0.20 米。桌板宽度为 2.10 米，桌沿到壁面留约 30 mm，深度与高度、桌面设备的安装空间保留。摄像头底座随右壁内移，并稍向玩家方向调整，初始画面仍处于右上方。近处左右舱壁与顶部的检修框和小面板采用圆润边缘，紧固件具有垫圈和六角头；线束由带橡胶衬垫的折边压条固定，两端接入带螺母和护套的接头；冷却管线采用直段与圆弯、带衬垫的管箍、壁面支座和端部箱体。竖向回管布置在桌板前沿之后，上方管段避开 CRT 顶部；顶部线束经支架承接，摄像头保留独立引线，穿过结构肋、露出碎段的多余角部支线已移除。项目曲线、支架和面板与现有 CC0 配电箱及阀件组合，钢板和旧漆继续使用 Metal Plate 02 原始 1K 材质；橡胶护套、旧布绝缘层、氧化铜件和暗色绝缘衬板使用 imagegen 生成的四区纹理。六种材质全部绑定颜色纹理并按物理尺度采样，细划痕起伏与粗糙度／金属度通过材质响应估计。布绝缘线按积灰、暗旧的低反射表面标定，颜色乘数 0.17、去饱和比例 0.35；保留织物细节，避免浅色线材在昏暗背景中持续突出。线束沿运输截面的垂直方向排列，竖向支路保持分离，接头附近适度散开；短线控制点随面板高度调整，截面保持圆滑，闭合边单独展开纹理坐标。外围装饰承担视觉作用，舱室仍采用固定坐姿观察和现有设备焦点操作。

玩家正面的深处设备墙采用较低的静态几何细节：保留骨架、百叶、箱体和线束的大轮廓，管线截面降为 12 边、曲线采样间距约 40 mm；省去小面板倒角、螺栓垫圈与凹槽，用简化接头承接线缆。左右舱壁与顶部继续采用近处细节，全部纹理及现有照明保留；此分级在生成几何时固定，不随视角切换。

当前照明小样：左、中 CRT 的面光源为 `#8daac6` 淡蓝色、强度 5.0、范围 1.1 米、衰减 1.5；阴影偏移 0.01、法线偏移 0.2、柔化光源尺寸 0.06 米，使小型桌面物件保留投影。环境光能量保持 0.25，`RoomBounce` 与 `ServiceBounce` 均已删除；SSAO 半径 0.18 米、强度 0.6、细节 0.25；室内反射探针强度 0.55、箱体投影和反射阴影开启，覆盖当前舱室并持续更新。LED 光学光晕位于单独渲染层，反射探针只采集实际场景层。尚未引入 SDFGI、SSIL 或 SSR。以上参数是本轮试验实现，最终光影强度仍待用户验看。
