# Scarlet Contract：美学方向

更新日期：2026-09-30。

本文集中记录当前美学方向，供场景、角色、界面和画面处理共同使用。目标是硬核俯视角战术射击游戏。测试场目前可继续发展的基础主要是角色及其动作；场景和界面的最终外观需要按本文设计。

本文是场景、角色、滤镜和 UI 的统一美学依据。设计变更直接更新相关文档中的要求，不并列保留已被替代的设计。本文描述设计目标，不表示这些目标已在运行版本中实现，也不直接授权修改代码。

## 1. 已确认的整体方向

整体采用克制的工业设计。战场处于写实与抽象之间：物品有可信的用途、结构、颜色和材质，细节围绕俯视角下的实际可读性取舍。整体画面通过滤镜，让人感觉正在透过复古终端观察战场。

场景与角色追求二维美术的画面感；角色可以使用三维模型与骨骼动画，并以微妙的三渲二方式融入场景。界面采用复古科幻风格，年代想象接近两千年代对于未来科技的设想。

场景、角色、滤镜和 UI 必须形成统一画面，同时清楚表达位置、朝向、遮挡、动作和战斗状态。

## 2. 视角与素材制作

战斗画面采用严格的正交纯顶视：相机垂直向下，视线与地面垂直，不使用透视或倾斜视角。场景及用于验证战斗画面的美术小样不得露出物体侧面；墙体只显示俯视截面，家具、设备和角色按正上方观察的轮廓与顶面表现。二维素材与三维渲染必须遵循同一投影规则。

场景可以直接用静态二维美术搭建。三维建模是方便的制作手段，用户仍可提供模型，但场景没有必须使用三维模型的要求。二维绘制、三维模型渲染出的静态素材，以及直接使用模型的方案，都应按最终画面与制作便利性选择；当前不指定唯一技术路线。

不同来源的素材需要统一比例、光照观感、材质尺度、轮廓处理和落地关系。素材形式不改变物体的真实占地、掩体高度、通行与遮挡事实；纯顶视也不取消战斗模拟中的高度信息。

俯视角下，大部分物品显示很小。重点投入可辨认的轮廓、主要结构与材质差异，细节量以正常游戏距离为依据。放大观察可以辅助检查，但不能代替正常倍率下的判断。

## 3. 场景：克制的工业设计

工业设计体现在物品的功能和构造中：结构关系清楚，体块有秩序，装饰与用途协调。不同空间可以有不同的生活、工作与使用痕迹，不把工业风限定为单一种类的设施。

场景颜色首先来自物体自身的材料与表面处理，再由共同光照联系起来。混凝土、涂漆金属、裸露钢材、塑料与木饰面保留各自的自然颜色、粗糙度和反光差异；不先选定统一色系，再把所有物品染成同一倾向。克制体现在构造、信息量和装饰上，不等同于统一压低饱和度或套灰绿色调。

材质可以略微抽象，但不能消失。可信度优先来自真实比例、可解释的结构、材质响应和接触阴影，不能用带描边的几何图标或不断增加微小装饰代替。

具体色表、饱和度、纹理细度和磨损程度需要通过样板画面确定，当前不规定唯一配色，也不以微小纹理数量衡量完成度。

门的开闭、低掩体与全高障碍、可互动对象和角色应在正常倍率下可辨。颜色可以辅助表达，轮廓、结构、标识或状态变化也要承担信息。

## 4. 角色：微妙的三渲二

现有角色仍可使用三维模型、骨骼与动作系统。移动、开火、操作等动作目前是可继续发展的基础，应保留其可信度和姿态信息。

角色最终呈现更接近二维美术：轮廓清楚，颜色有组织，明暗经过简化，材质与场景协调。三维体积用于支持姿态、朝向和动作，画面中保留适量体积线索，让角色既有实体感，也能融入静态二维场景。

“微妙的三渲二”不预设粗黑描边、强烈卡通分层、像素化、纸片化或某一种现成滤镜。现有少量色阶与细描边可作为试验起点，具体手法和参数尚未确定。二维观感需要从角色本身的轮廓、明暗与材质建立，再与整体终端滤镜协调。

角色与静态场景需要共享合适的光照观感与阴影关系，避免角色像单独贴上的素材。枪械方向、肢体姿态、移动与操作的区别、枪口与战斗反馈，在风格化后仍须清楚。

## 5. 画面滤镜：透过复古终端观察

整体画面具有复古终端的观看质感，同时保留场景的颜色与材质区别。滤镜不能把场景压成单一颜色，也不能依靠遮盖物体细节来制造风格。

滤镜服务于战术阅读。门缝、角色轮廓、枪械朝向、掩体边缘、动作和命中反馈，应在正常游戏倍率下保持可读。UI 文字、交互目标和光标也应保持清楚。

扫描纹理、颗粒、色彩压缩与亮部处理可以作为探索手段；采用哪些效果、强度多大、覆盖哪些层，仍需试画。

“终端”目前是画面体验的描述。尚未确认它是否对应世界观中真实的远程观察或指挥设备，不据此新增监控、通讯或其他玩法。

装饰效果不提供额外感知能力。敌情、历史记录和声音线索必须来自游戏规则允许的信息，滤镜不能泄露隐藏单位或伪造战术状态。

## 6. UI：两千年代的复古科幻

UI 采用两千年代对于未来科技的想象，与克制的工业设计共同形成一套可信的设备界面。任务、队员、身体、武器、装备与操作状态是界面内容的主要来源。

分区、边框、标签、编号、状态栏和设备示意图可以承担视觉语言；具体面板形态、字体和强调色仍需设计。UI 可以有自己的颜色体系，须与场景和战术标记协调。

界面风格应帮助玩家找到信息、区分状态和理解操作后果。专业感来自准确的信息与清楚的组织；不添加没有意义的随机数字、追踪框或伪雷达目标。

场景色彩与选中、敌情、警告、禁用等状态表达需要协调，关键信息不能只靠相近颜色区分。高频空间操作直接在战场上完成的现有交互原则继续保留；本次美学更新不改变操作与指挥规则。

## 7. 制作与验证原则

当前场景验证直接在引擎内使用实际模型或美术资产搭建，不再生成 AI 模拟场景图，也不以程序拼绘设备图标作为成品美术。先验证可信物体、真实尺度、材质与光照，再通过明暗归纳、反光控制和画面处理建立微妙的二维观感。具体素材仍可采用二维或三维形式。

优先验证少量代表性素材与现有角色能否共处，再扩大资产制作。动画继续使用现有可用成果；新美术不能削弱动作、姿态与射击方向的可读性。

现行[美术尺度与分辨率一致性规则](../godot/LOCAL_CONFIGURATION.md#美术尺度与分辨率一致性全项目规则2026-09-30)继续适用：提高分辨率主要增加采样清晰度，不擅自改变纹理密度、轮廓比例、颗粒、滤镜或特效的相对风格。属于世界或角色的美术表现应随观察倍率一起变化。

验看时覆盖正常倍率、放大观察、静止、移动、开火与操作。检查场景颜色和材质、角色与场景的一致性、轮廓与朝向、掩体和门的辨识、滤镜可读性及 UI 状态表达。

## 8. 尚未定案的设计与实施

以下内容仍需讨论或通过小样验证，不能当作已确认的实现要求：

- 场景的具体色表、材质简化程度与表面细节密度。
- 角色明暗、反光、描边和阴影的具体处理。
- 终端滤镜的主要效果、参数、覆盖范围与世界观身份。
- UI 的具体面板、字体、强调色与动效。
- 正交纯顶视下的画面尺度、二维与三维素材的实际组合流程。

当前验证对象是一台具有具体结构与材质的设备、混凝土地面、墙体和现有角色组成的小场景。先在不加终端滤镜的实际运行画面中检查可信度，再决定是否扩大到完整房间。该小样的具体资产、配色与光照不是最终美术定案。
