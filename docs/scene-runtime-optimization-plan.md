# 大规模场景统一算法与性能设计方案

日期：2026-11-02。

本方案面向 500×500 米、约 70 个角色的持续运行场景，将寻路、感知、身体能力、战斗、远近模拟和画面更新组织成同一条计算链。核心做法是保存唯一的世界状态，按依赖复用计算结果，并把耗时规划与需要当步完成的战斗结算分开调度。

本方案已经进入实施。当前工作树接入 500×500 米、70 人场景和四人受控小队，A–F 的主要运行链已落地；正常舱室入口与基础指挥已完成本轮实操，完整边界负载继续按第 18 节验收。工程初值由实现方测量和调整，玩法边界保持一致。实现状态与实测结果分别记录，不把目标帧率当作已覆盖全部负载。

## 1 目标和交付边界

| 项目 | 本轮设计 |
| --- | --- |
| 地图 | 500×500 米，沿用 1 米逻辑格，共 250000 格 |
| 人口 | 约 70 个持续存在的角色，包含受控小队、敌人和路人 |
| 玩家指挥 | 首轮沿用现有四人小队，指挥名单独立保存；70 人不等于 70 个受控队员 |
| 输出 | 2560×1440 目标，保留实体 CRT、独立文字层与现有画面比例 |
| 迷雾 | 当前可见、已探索不可见、未探索不可见三态 |
| 玩家移动 | 目标、整条路线及对角涉及的侧格都必须属于已知区域 |
| 远方敌人 | 无精确交互时按小队抽象推进，保留成员身份和真实状态 |
| 远方交战 | 在交战地点启用同一套精细战斗规则，不另建抽象伤亡公式 |
| 路人 | 独立行为类别，按活动任务推进；中立角色不自动进入敌人选敌开火流程 |
| 暂停 | 精细模拟与抽象模拟共同停止推进；切回舱室的冻结语义沿用现有入口规则 |
| 交付 | 完成整条运行链的重组与大规模实操验收，按阶段推进，不以某一个热点变快作为整体完成 |

性能目标为目标机接电、2K 输出、普通游玩视角下的常规 60 FPS，单帧预算约 16.7 ms。CPU、GPU 和输入响应分别记录，不能把暂停画面的 60 FPS 当作 GPU 已用满或已有性能余量的证据。

首轮真实负载采用四名受控队员、24 名敌人和 42 名路人，共 70 人。24 名敌人可按六个四人队配置，场景关系允许其中不同小队发生局部交战。人数分配是验收初始配置，算法不以这组身份或编号写死。

常规负载覆盖全员活动、玩家附近交战和远方交战同时发生。70 人聚集可见与多处交战分别作为边界负载。系统不能通过漏算伤害、隐藏合法可见单位或限制真实单位数量来维持帧率；超出已验证战斗密度时应明确报告实际边界。

## 3 状态所有权和模块职责

| 状态 | 唯一负责人 | 主要消费者 |
| --- | --- | --- |
| 真实位置、地形、门、身体、装备、任务和世界时间 | SCWorld、SCGrid、SCActor、SCEntity | 模拟、碰撞、伤害、感知 |
| 当前可见、已探索、最后观察到的地图状态及合法记忆 | SCPerception | 玩家规划、目标选择、地图与 UI |
| 落点分配、路线、成本、请求状态及依赖 | SCPlanner，使用 SCGrid 查询 | 预览、命令入队、执行、房间行动、物资和 AI |
| 角色模型、动画、轮廓、标签和纹理 | field、tactical、rendering、cabin | 显示与输入反馈 |

表现层读取已经算出的结果，不在绘制函数中寻路，也不依据可见模型反推碰撞或敌情。玩家知识记录观察结果，不复制出第二个独立运行的世界。

一个局内场景只有一个权威 SCWorld。远方小队、局部交战区和角色效果都引用这份世界中的成员。独立射击工具可以拥有自己的世界，但同一场景内不能为每个角色再创建一份射场。

首轮继续使用现有 GDScript 模块。内部纯查询与数据依赖整理完成后，若实测仍超预算，再把明确的纯计算边界移到工作线程或原生实现；场景树、UI 和伤害提交保持其统一执行顺序。

## 4 角色身份与关系

角色身份、阵营关系、指挥权限和模拟方式分别保存。

- 受控名单决定哪些角色进入队员卡、编组和玩家命令入口，不从阵营颜色或身体控制模式推断。
- 友好、中立、敌对关系决定自动选敌和友军挡线等行为。看得见一个人，不等于应该攻击这个人。
- 路人共用位置、身体、装备、碰撞和感知基础，常规行为只消费自己的活动任务。报警、武装反抗等额外玩法不作为性能改造的隐含新增功能。
- 抽象与精细只是更新方式；成员 ID、伤情、弹药、经验、任务和控制关系不随切换改变。

当前分散的 `team ==` 与 `team !=` 判断需要按用途梳理，分别归入关系、知识共享、受控权限或统计。保留现有敌我默认关系，并为中立角色补齐明确的数据表达。

## 5 地图分块和基础数据

### 5.1 逻辑存储

存储和更新以 32×32 米块为初值，500 米地图约为 16×16 个块，边缘尾块只包含有效格。存储块不直接等同于房间、道路或导航区域。

地形采用共享默认值、紧凑格数组与稀疏例外。普通格保存地形类型或少量标志；高度、特殊地形、墙边和实体结构按其实际需要保存。不能将当前每格复制完整地形字典的方式扩大到 25 万格。

相机边界、全图取景、地板、网格、地图标签和迷雾坐标统一读取场景 bounds。坐标换算显式使用地图原点，移除表现代码中散落的 50、25 和固定全图视距。

### 5.2 逻辑驻留和表现驻留

全图逻辑保留可以查询的紧凑数据；角色身份与任务持续存在。模型、骨骼、轮廓代理和细致材质只按镜头和精细交互需要驻留。

模型卸载不会删除实体、释放真实占位、抹掉探索记录或停止远方任务。加载新的表现块时，先使用已知的简化表达，资源准备好后替换，避免可见区域出现空洞。

### 5.3 长距离连接

道路、房门和通道建立粗层连接，用于快速判断已知连通关系、提供搜索下界和候选路线。玩家粗图只能来自玩家知识；世界内部通行使用真实数据。

当前粗层采用 32 米块之间的真实或已知连接，提供可采纳的距离下界与连通快速拒绝；底层继续精确搜索完整合法空间，不锁定单一走廊。近距离请求跳过粗图准备。命名道路与房间门户的候选上界预搜索、精确门户距离缓存按长路线实测收益再增加。

### 5.4 首轮可玩地图组织

500 米区域沿用机修物流片区主题：西侧车间与整备区、北侧装卸堆场、东侧仓储与设备区、南侧服务与入口区，通过运输环路、横向主路和次级巷道连接。建筑群之间保留装卸空地，室内包含房门、家具和可破坏遮挡。关键区域至少提供两条可探索连接，另放置少量窄路与单入口房间，分别覆盖绕路、拥挤和入口行动。

首轮按 12–16 个建筑或堆场组团组织美术，复用现有授权模型与结构件，避免机械重复同一组团。组团数量是制作初值，细节密度随实际画面验看调整；全图通行、实体与视线数据从开始就完整，资源分批显示不会凭空生成或移除真实障碍。

小队从南侧入口集结，初始只揭露其有效视野。路人分布在服务、装卸与车间活动路线；敌方按不同任务巡逻。为承载远方敌人交战，验收配置将 24 名敌人分属两个彼此敌对且均敌对玩家的阵营，每方 12 人；42 名路人初始中立。阵营关系写入场景数据，画面和选敌规则共用同一关系定义。

## 6 真实地图与玩家知识

### 6.1 三态显示与命令权限

| 状态 | 地图显示 | 移动与经过 |
| --- | --- | --- |
| 当前可见 | 正常颜色和亮度，显示合法实时信息 | 允许 |
| 已探索但当前不可见 | 灰暗、低饱和的静态记忆 | 允许 |
| 从未探索且不可见 | 全黑 | 禁止 |

玩家共享己方队员的有效视野。镜头平移、缩放、全图和模型加载不揭图。已探索集合在本局保留；当前可见集合随观察者位置、朝向、能力、震撼和遮挡变化。

已探索灰区保存最后观察到的地形、门和障碍状态。视野外真实变化不提前改写玩家地图或路线。角色接近后观察到、亲自操作或实际遇阻，才根据获得的信息更新知识并重新规划。

### 6.2 信息一致性

命令先检查知识权限，再检查已知通行和路径。黑区无论真实是墙还是空地，都提供一致的“区域未探索”反馈，不能泄露隐藏地形的错误原因。

目标、沿途格和对角涉及的侧格都必须已知。两片已探索区若没有已知连接，返回“没有已知可达路线”。声音或最后目击信息不会自动授予该区域的探索状态和移动权限。

地图中的门、房间名、物品标签和命中提示遵守同一知识边界。已经看到的入口可以用于门外集结、开门和观察；未知室内不预排具体落点或精确路线，显露后才生成后续计划。房间任务对未揭露部分使用“观察后再规划”的阶段状态。

### 6.3 显示信息的裁剪

隐藏单位的模型、轮廓代理、姓名、血条、悬停对象、阴影、动态灯光和独立挂在世界中的特效一起退出当前显示集合。灰区使用固定光照的记忆表达，不把实时场景整体乘灰；隐藏门运动、单位投影和灯光不能进入这份记忆画面。

已识别敌人的最后目击标记沿用现有 5 秒记忆期限，明确表现为过时信息，不跟随真实角色移动。听见黑区事件时，固定 UI 可以提示声音类型与粗略方向；不在黑区展示精确事件格，不揭地形。已探索区域内可沿用现有粗略声音区域标记，标记范围按知识裁剪，不涂入相邻黑区。

迷雾 CPU 数据与 SCPerception 共用。GPU 初版使用 500×500 双通道纹理表达当前可见和已探索，原始大小约 0.5 MB，变化后上传；不随 2K 输出扩大知识纹理。先保证同一版本一致发布，再根据测量决定是否拆分区域上传。

场景和 mask 先按知识筛选；CRT 重构、色散后将未知地形清黑，噪声仅作用于已知地形，再保留清晰 UI。地形、区域标签、敌人、路线和声音标记均受知识裁剪；已知己方位置的编号与小队计数允许作为 UI 伸出其锚点附近，保证全图可点击，不揭露周围地形。固定 HUD 和鼠标反馈保留。迷雾坐标与现有地图投影、玻璃 UV、CRT 变换共用换算。

## 7 模拟时间和运行层级

### 7.1 同一个世界时间

精细与抽象模拟都使用 world.time。固定引信、等待和状态期限保存世界时间截止点；换弹、治疗、穿脱等可变速动作保存实际完成量与剩余工作量，按当前操作能力推进。它们的预计截止点随能力变化重算，不能把开始时的预测冻结成完成时刻。暂停不会让远方任务按现实时间继续前进；恢复或切换模拟方式保留实际进度。

保留精细模拟的 60 Hz 固定步。显示帧可以包含多个模拟步；一次模拟步仍按稳定顺序提交状态。慢帧治理依靠减少同步重活和限制规划预算，不提高追赶上限来补偿长时间搜索阻塞。

### 7.2 运行层级

| 层级 | 工作 |
| --- | --- |
| 精细角色 | 连续移动、局部避让、感知、识别、动作、身体状态、弹道和伤害 |
| 远方敌方小队 | 共用小队任务和粗路线，按行程及事件推进；保留廉价成员位置与状态 |
| 远方路人 | 按个人任务、路径进度和到达事件推进，不为每个人运行完整战术选敌流程 |
| 暂停 | 两种模拟均停止推进；已有画面和合法交互继续响应 |

抽象化由可能发生的精确交互决定。距离是主要筛选条件，还要检查双方感知、身体碰撞、瓶颈通行、已有目标、在途弹道、爆炸、近战、受袭和所有可能改变逻辑的合法声音。检查距离取相关作用范围，加上检查间隔内的相对移动余量和队形半径；初值由实际视距、武器与速度推导。

进入与退出使用不同边界，并设置驻留条件。阈值属于工程参数，不向玩家暴露；长射程攻击或声音可以提前唤醒远方局部角色，不能为了维持抽象状态缩短其真实作用范围。

### 7.3 局部交战区

保守范围查询发现远方小队可能发生接触时，先将有关成员和必要邻近对象转入精细模拟，再用原有视线与识别规则判断有效接触，沿用同一套命中、弹药、身体伤害和死亡规则。遮挡后的潜在接触可以只触发精细化，不产生敌情。多处交战可以同时存在，仍属于一个世界。

交战区不是独立 SCWorld，也不是独立伤害公式。不同区域的声音、子弹或成员移动建立联系时，相关模拟范围随之扩展。跨区域状态仍在同一模拟步内按稳定顺序提交。

### 7.4 抽象小队的推进

小队保存成员列表、任务、路线段、沿路线进度、队形槽位与更新时间。转入抽象后不把成员吸附到队长位置，不清空伤情、弹药、识别记忆或任务。

首轮抽象推进只覆盖合法路线行进、巡逻和等待，以及可精确更新的状态期限。攻击、投掷、治疗、换弹、穿脱、精确门口操作等动作开始前转入局部精细模拟，动作及相关交互结束后再评估退出。这让远方规则继续复用现有实现，避免为每种复杂动作另造近似结算。

门口、窄道和路口使用通行预约。遇到关门、占位或无法合法展开时等待或重新规划，不能跳过瓶颈。远方小队到达目的地、相关通路变化、声音到达或下一步可能发生接触时进入事件队列，无需每步重做全部决策。

### 7.5 切换流程

常规步边界进入精细模拟时依次完成：推进到当前世界时间，确定成员位置，校验门和占位，注册精确空间数据，保证身体能力最新，再在正常检查点计算感知与行动，最后开放合法角色显示。

子弹扫掠、爆炸或声音在模拟步中途触及抽象成员时，先交接该成员本步的运动起点、终点和必要分段，再进行精确命中或听觉判断；previous_position 不能直接设成当前点。抽象与精细控制器记录本步已完成阶段，交接后不重复移动、武器计时或资源提交。在当前触发点处理声音与伤害，后续决策等到下一个正常检查点；不回放已经过去的阶段。

接触前预热可以提前创建表现，但不会给角色新增玩家坐标或敌情。退出发生在完整模拟步末；确认当前精确动作、来弹、受袭、近战、待处理接触和资源提交均已完成，整队满足退出条件后保存进度，再交回抽象控制。同一成员不能被两个控制器同时推进，也不能用一个超大 dt 补算整段战斗。

### 7.6 调度初值

| 工作 | 首轮调度 |
| --- | --- |
| 精细移动、弹道、伤害与动作 | 60 Hz 固定步，保留现有检查点 |
| 战术选择 | 沿用现有约 10 Hz 决策节奏；当步受击、识别与开火检查保持原时序 |
| 潜在接触范围检查 | 10 Hz，包含下一次检查前的运动余量；来弹、声音及通路事件即时处理；感官、武器范围、震撼、控制和关系变化当步重评估 |
| 抽象行程位置 | 从世界时间和路线进度廉价求值，为范围索引提供保守位置与本步运动区间 |
| 远方任务重新决策 | 事件优先，普通活动兜底每 1 秒检查一次；不延迟预定到达、状态期限或危险接触 |
| 退出防抖 | 至少连续 2 秒满足退出条件，退出距离另加两个接触检查间隔的相对移动余量 |

已知的定时恢复可预先加入下次检查前的保守作用范围，保证震撼结束或控制恢复不会留下检查空窗。这些是工程初值。调整时记录接触响应与计算开销；已有身体动作、射击反应和识别时间不跟随后台任务频率降采样。

## 8 共享空间查询

SCGrid 统一维护静态分块索引、活动门和动态角色索引。移动角色只更新旧位置和新位置涉及的桶。候选范围由实际查询决定，不遍历整张地图或全部实体。

| 查询 | 候选范围 | 保留的精确行为 |
| --- | --- | --- |
| 移动碰撞 | 移动扫掠范围加身体半径 | 高度、实体形状、轴向滑动和最近阻挡 |
| 最近射线 | 射线穿过的块与格 | 最近部件命中、高度、忽略部件和稳定同距选择 |
| 全命中射线 | 沿途候选 | 全部有效命中、去重与顺序，供声音和特殊操作使用 |
| 视野候选 | 观察者视距邻域 | 视角和真实遮挡；必要时保留尸体作为感知对象 |
| 活体弹道候选 | 子弹与角色运动的保守扫掠包围范围 | previous_position 到 position 的连续碰撞 |
| 拥挤和到达 | 邻域角色、目标格与预约格 | 途中穿行、终点占位和既有顺序更新 |

多个算法共享候选索引，精确判断各自保留。最近命中不能代替声音需要的全命中；单位相邻也不意味着成为永久导航障碍。

同一步内角色按现有稳定顺序移动后，立即更新其占位索引。后更新角色必须能看到前者刚完成的占位变化。门的关门阻挡也通过局部候选查询，保持有人或掉落物挡门时停止关闭的规则。

## 9 统一寻路和计划结果

### 9.1 搜索算法

继续使用八方向、地形加权最短成本。每次查询明确指定数据来源：玩家规划读取稳定的玩家知识图；世界 NPC、远方小队和真实碰撞读取各自规则允许的真实数据及版本。统一搜索过程不把 NPC 限制在玩家已揭露区域，也不把真实隐藏变化带入玩家知识查询。

玩家查询的对角目标和两个侧格均须已知；所有查询的两条侧路格与边都必须满足相应地图的通行条件。动态角色占位按途中与终点用途分别处理；玩家规划只消费合法已知的占位信息，实际执行仍接受真实碰撞。

单目标使用 A*。同一起点需要比较多个落点时，运行一次多目标成本搜索，保留成本和父节点，不为每个候选立即回溯整条路线。最终落点选定后，只还原被采用的路线。

四名队员起点不同，通常仍需要四个搜索过程；相同起点与依赖可以共享。候选区域直接枚举点击格附近 5×5 范围，再过滤半径 2 米、区域和通行，不扫描整个房间。

单人明确移动仍要求原目标格，不擅自改成邻格；多人落点和现有允许替代的任务才使用候选分配。

沿用按队员 ID 分配，以及距点击点、路径成本、y、x 的稳定排序。更换搜索组织后，等成本路线的具体转折可能变化，但可达性、最小成本和落点排序必须遵守同一契约。

启发值按地图最低单位通行成本缩放，保证不会高估。地形倍率大于 1 时仍可正确搜索；不能把普通地面 1.0 隐含成所有数据的固定条件。

### 9.2 一份计划贯通各环节

SCPlanner 保存请求、完整结果与依赖：受控名单、有效追加模式、起点或前序终点锚点、请求次序、候选分配、路线、成本、失败原因、查询地图快照及版本、相关占位。

整次小队请求共享同一地图快照与候选规则，保证各成员的成本比较建立在同一信息基础上。

替换请求以当前移动段的合法终点为规划起点，站定时使用当前位置。追加使用稳定前序命令的预期终点；前序终点尚不可推导时先保留请求与次序，待锚点确定再搜索，不假定角色会回到提交时的位置。

预览消费结果；提交验证结果；队列保存可复用的路线；执行激活时再检查起点、通路与命令依赖。依赖未变就采用已有结果，变化后重算。远期队列不承诺路线始终有效。

绘制函数只读取路线和标记，不调用 planner.path。房间入口、搜索槽位、物资接近格和 AI 位置候选统一使用同一搜索过程，不能各自再建立一套候选循环和缓存。

### 9.3 有界任务调度

规划是可以让出执行的任务。工程初值如下：

| 参数 | 初值及用途 |
| --- | --- |
| 每显示帧规划总预算 | 2 ms，全部角色和请求共同使用 |
| 活动重搜索 | 最多 4 个，其余排队；不为每个 NPC 分配一棵全图成本树 |
| 预算检查批次 | 每 64 个展开节点检查一次，同时约束准备、回溯与发布工作 |
| 规划缓存 | 初始 64 MiB，按内存与最近使用情况淘汰 |
| 活动搜索暂存 | 独立初始 64 MiB，包含请求持有的地图快照；取消和完成后归还 |

预算值用于首轮实现，最终按目标机真实场景测量调整。一次不可抢占的整图建索引、深哈希或长数组复制不能藏在 2 ms 预算之外。

成本、父节点、访问标记和搜索堆使用紧凑结构；共享或按块写时复制地图快照，避免每个请求复制完整字典。内存竞争时降低并发、排队或淘汰缓存，必须保证至少一个合法的 500×500 搜索能够完成。若单任务仍超过暂存预算，采用可继续的分块求解；不能反复回收重启形成活锁，也不能将资源不足谎报为不可达。

优先级依次照顾正式玩家命令、当前交战的必要重规划、可见预览、普通角色活动和远方小队；等待时间提升后台任务优先级，防止永久饥饿。停止与取消不进入耗时规划队列，立即撤销旧请求。

新预览目标替换旧请求。请求带代次，取消后不能发布。分配结果整体发布，不先显示两个人的落点、随后再悄悄补另外两人。未完成不能显示“不可达”，旧路线不能冒充新目标的结果。

### 9.4 正式命令等待期间

预览不改变世界。正式替换命令若当帧未就绪，所选队员完成当前移动段后等待，界面显示“规划中”，其他角色照常活动。等待门控同时约束旧任务推进和 SCMovement 的新段启动，不能只停规划器而让保留的旧 route 继续行走。正在进行的动作仍遵循现有中断和已释放效果规则；伤害、碰撞、身体状态时钟和必要感知照常运行。

旧队列和资源预约保留到新计划校验通过后，再整体替换并解除等待门控。涉及关联宏观行动的成员按现有接管范围挂起，阻止旧任务继续生成动作或资源提交；不能只暂停一个人而让关联任务继续推进。已经发生的伤害或投掷不回滚。

失败或取消后保留挂起门控，清楚标明保留计划的状态，恢复经过既有继续或重新下令流程。X 停止会取消待计算计划、按停止规则清理旧行动并更新请求代次；队员停稳后解除规划等待，晚到的结果不能恢复已停止行动。

Shift 追加不暂停正在执行的前序动作；先按现有接管规则得到 effective_append，宏观接管若规范化成替换，就进入上述替换等待流程。追加请求预留队列容量，沿用最多 8 个节点的限制，取消时释放预留容量。

同一角色连续追加使用稳定命令 token、预期前序终点和输入次序。后一个请求依赖前一个请求的目标，不能按搜索完成顺序入队；前序自然完成出队不会撤销后续请求。前序被替换、删除或停止时才取消对应依赖链，释放预约并提示结果。多人追加仍整体发布。

### 9.5 完成时校验

每个请求读取稳定地图快照，最短成本针对该快照定义。完成时校验本请求的起点或前序锚点、命令依赖、目标预约及所用通路是否仍合法。不能因为 70 人中任意一个人移动，就让全部搜索从头开始。

路线仍可通行与路线仍为最新整图最短是不同结论。无关新增探索不取消正在计算的请求；新请求使用新快照，相关堵路、起点或命令依赖变化才使旧请求重算。结果可在标明快照依赖后安装，后台有预算时再考虑新捷径，不要求每次揭图都中断当前行动。

跨请求复用精确候选成本时，首轮使用同一地图的导航版本；远处已知新通路也可能降低最短成本。已安装路线只需按所经块检查当前合法性，正常执行不被无关揭图反复打断。真实世界查询使用真实版本，与玩家知识版本独立。

## 10 感知与识别

### 10.1 邻域先筛选

每个精细观察者先从空间索引获取视距内候选，再做视角与精确遮挡判断。中立、敌对和尸体按查询用途区分，不做所有角色两两全扫，也不把感知对象一律限定成活敌人。

玩家地图视野只由具有共享观察资格的角色贡献。敌人看见哪里不会揭开玩家地图，普通路人也不为玩家生成全图可见格。

### 10.2 保留两个语义检查点

规划前的感知检查推进一次识别时间；移动和观察转向后的检查使用零 dt，立即反映新看见、失去视线和接触变化。两个检查点继续存在，其间未变化的纯几何结果可以复用。

识别、记忆期限、门知识和首次接触事件按原有顺序递进。不能把两次调用合并后累计两次识别时间，也不能因复用结果漏掉失去视线时的进度清除。

观察者位置、朝向、感官、震撼或相关遮挡变化才使其地图视野失效。目标移动只影响相关观察者与目标配对，不使整个地图视野重建。地图可见集合可维护观察者贡献计数，批量提交本检查点的增减，避免多名队员重叠观察时出现瞬时黑闪。

### 10.3 声音与知识

声音按事件传播。先筛潜在听者，再计算沿途墙门衰减。一次事件只处理一次，不因 UI 标记寿命结束而漏掉逻辑接收。

抽象小队可能接收会改变逻辑的合法声音时先做必要精细化，再准确判断能否听见；候选筛选不额外发明“重要声音”类别来省略事件。激活不等于听见，也不会直接让它知道玩家位置。敌情仍来自自身观察、声音、合法报告和记忆。

## 11 身体和能力快照

身体派生值由 SCActor 统一保存：部位索引、区域成员、区域最大生命值、当前完整度、死亡条件和功能比例。换身体或换部件重建结构；受击和治疗只更新受影响区域及其依赖。

能力仍由 SCAbilityRules 按唯一公式计算，分为来源结构、来源有效性与技能、最终数值与权限三层。来源分组和稳定贡献尽量复用，详细解释按需生成。保持来源优先级、排他规则和数值累计顺序。

下列变化必须通知依赖：部件 HP、装备完成、来源增减、来源开始或结束时间、技能与经验、控制关系、共享控制者状态、身体状态和震撼跨零。共享同一控制者的多个角色都要收到相关失效。

弹量、普通武器冷却和热量优先由武器规则直接消费，不让它们无条件触发整个身体能力重建。纯时间递减只在影响权限或贡献的边界到达时重建对应快照。

refresh_capabilities 保留为现有入口，内部保证相关输入最新。按阶段保证最新，输入没变就复用；受击、治疗、状态结束等写点立即标记。不能把当前每次求值自增的输出版本直接当成输入变化标志。

## 12 战斗和状态提交顺序

精细模拟按以下顺序组织，每个阶段保证其依赖快照有效：

1. 推进世界时间、门和到时事件，处理装备、武器与状态时效。
2. 处理当前动作完成、中断、震撼与爆炸等即时变化。
3. 执行规划前感知、一次识别时间递进、物资可见与战术决策。
4. 推进计划和角色移动，更新局部占位，再执行移动后感知。
5. 推进旧子弹与连续碰撞，依次提交部件、角色和结构伤害。
6. 按稳定角色顺序执行当前战斗判断，创建新的射击或即时攻击事件。
7. 完成死亡、掉落、暂停请求与模拟层级交接。

这表示依赖契约，实施时须核对现有动作、闪光、近战与装备在阶段中的准确先后，不能以重排消除重复调用而改变结果。

子弹先按扫掠包围范围筛选目标，再保留精确连续碰撞。角色运动使用 previous_position 到 position；贯穿按原部件 contact_key 记账。一颗子弹破坏遮挡或伤害角色后，后续子弹和战斗必须读取新状态，伤害不延迟到下一显示帧。

第 5 阶段的来弹和第 6 阶段的声音若触发中途精细化，按第 7.5 节交接本步运动区间与已完成阶段；处理当前事件后，不追补本步已错过的决策，也不重复扣减计时或提交动作。

射击场的 manual_control 和 weapon_clock_external 继续保留各自入口，避免世界与射击工具重复推进武器。角色效果只生成枪口、曳光、弹壳和命中表现，不另行决定真实命中或建立独立角色世界。

## 13 变更通知和缓存失效

| 变化 | 必须更新 | 可以继续复用 |
| --- | --- | --- |
| 门连续开合 | 门的碰撞形状、相关视线与弹道几何 | 未改变实际通行条件的导航结构 |
| 通路或地形成本改变 | 相关导航块、连接与依赖计划 | 无关联区域的固定数据 |
| 玩家新发现道路或门状态 | 玩家知识图、新请求快照与地图显示；相关堵路使计划重算 | 真实地图固定结构、无关在算请求及仍合法的已装路线 |
| 角色移动或转向 | 动态索引、相关感知、姿态和标记 | 未变化的身体能力与静态地形 |
| HP、部件或控制者变化 | 身体与能力；必要的死亡或尺寸几何 | 无关导航与环境数据 |
| 武器冷却、弹量变化 | 武器状态和对应 UI | 与之无关的身体、地形和路径 |
| 队列、选择或目的格变化 | 对应请求、预览与 UI | 其他单位的规划结果 |
| 相机或窗口变化 | 投影、驻留表现、mask 与 UI 布局 | 世界事实和已有合法路径 |

导航、几何、知识、动态占位、身体能力、命令和显示采用各自的版本或变化标记。变更由拥有数据的模块发布，调用者不再各自猜测是否需要清缓存。

结构损毁、门与实体变更通过统一失效入口通知相关导航与几何块。原普通弹道的损毁通知已迁入该入口，后续写点继续遵守同一契约。

首轮先把失效责任完整列出并接通，再逐步缩小到块或相关对象。缓存按条数和字节双重限制，释放取消请求的暂存，避免旧地图、旧队列和已卸载代理继续被引用。

## 14 表现与渲染调度

### 14.1 按变化更新

| 输出 | 更新条件 |
| --- | --- |
| 角色骨骼与枪口 | 姿态、动作、位置、朝向、后坐力或相关状态变化 |
| 静态物体 mask | 配置、块驻留、物体、知识状态或显示资格变化 |
| 动态 mask | 对应角色姿态或可见性变化 |
| 地图投影与固定标签 | 相机、窗口、知识或标签内容变化 |

| 场景与 outline 视口 | 场景、相机、姿态或可见集变化 |
| UI 合成视口 | 内容、悬停、焦点、按钮状态或 UI 动画变化 |
| CRT 合成 | 任一输入、CRT 时间或设置变化 |

场景、知识纹理、可显示对象集合和 mask 使用同一发布版本，并校验姿态与相机版本，再提交 outline，避免轮廓拖尾或视野变化残影。暂停无交互时保留纹理；鼠标悬停、点击、拖选和焦点变化仍立即进入 GUI 输入和重绘。

既有 CRT 暂停时间规则保持：场景暂停后干扰时间不继续推进；启动页或其他仍有动态时间的内容按其实际输入更新。舱室摄像头、电话和玩具是否仍运动，由各自状态决定。

### 14.2 远近画面表达

镜头近时保留选中小队与交战角色的完整模型、动作和关键装备。低屏幕占比的普通角色使用简化表现，远方抽象小队不维持无用骨骼与轮廓代理。

全图视角以分块的已知环境概览和合法单位标记为主，不为几像素高的角色求完整手部 IK。相邻受控队员聚合为带人数的小队标记，单击选择该组、双击进入近看；队员卡始终保留逐人选择入口。标记绘制和命中共用布局，编号与身体都可点击。全图继续显示合法目标和路线；标记仍受玩家知识约束，不能显示全部抽象小队的真实位置。

动画与表现精度变化不改变命中用的逻辑身体和武器时钟。近处射击的枪口、手部、后坐力与弹道起点保持一致，恢复完整表现前完成姿态初始化。

### 14.3 物体描边容量

对象只按当前驻留集合注册和注销，保留逻辑物件身份。现有一字节 ID 上限不足以覆盖大图驻留物件，首轮改为同一张 mask 中 RG 两字节对象 ID、B 高度，容量扩至 65535 个非零 ID。

0 保留为空背景。ID 字节使用无损数据通道、最近邻读取，禁用 MSAA；颜色转换、曝光与色调映射不得改变字节，读取后解码为整数比较。不能只将 ID 写进普通 ALBEDO 颜色链后假定精确；实现时沿现有 mask 通路建立可保存字节的数据输出配置。

编码、读取、同物体比较、同距遮挡与对象释放一起迁移。一个物体的零件继续共用 ID，不增加新的全屏场景 pass。验收覆盖超过 254 个驻留物件、低字节跨界、分块边界与反复卸载后的 ID 复用。

### 14.4 舱室附属工作

设备命中在加载时缓存局部三角形及包围块，观察相机和设备都没变化时复用中心命中结果。实际 CRT 输入仍保留凸面三角形和现有 UV 反变换。

时钟、电话 LCD 在显示内容变化时刷新，复用已有状态变化信号。玩具运动收敛后停止重复写骨骼，点击再次唤醒。保留已实现的暗背景轻量材质、桌面 2K 导入、无光照玻璃、反射缓存和外层 2K 上限。

描边、CRT 重构、SSAO 与灯光的算法替换须基于当前同条件隔离结果。源码中存在长循环，只能说明需要关注，不能直接换算成未经测量的 GPU 毫秒数。

## 15 交互细节

### 15.1 视野和界面布局

中央 16:10 与左侧 4:3 CRT 使用同一套布局规则。默认关闭右侧详情，顶部保留暂停、速度、移动、警戒、换弹、停止及视图控制，底部四张紧凑队员卡显示行动、实际伤情、弹药和已安装队列数；伤情来自身体部位，不生成总血量百分比。单选详情按需展开，显示武器、伤处和真实队列；多选显示共同下令信息。

固定 HUD 位于地图矩形之外，避开未知区黑色裁剪。源画面水平安全边距 56 像素、顶部 40 像素、队员卡高 92 像素且底缘距源画面底部 60 像素，底部提示从 x=96、距底 52 像素处绘制；默认地图约占 75–76% 源画面，展开详情后地图同步收窄。维持现有青灰面板、暖金选择色与清晰像素文字，状态同时用文字表达。

### 15.2 缩放与定位

滚轮按实际滚动量缩放，触控板捏合、顶部 −／＋ 和键盘 ± 共用缩放入口。缩放在约 140 ms 内平滑完成，以指针所在地图位置为锚；指针在 HUD 上时使用地图中心。可见地图纵向范围显示为米数，范围为 10–575 米。Home／全图取景，定位居中当前选择，近看回到 18 米；无选择时以当前视图中心近看。

WASD、中键拖动和触控板双指平移共用相机入口。相机根据可见范围钳制到地图边界，视图大于地图时居中。每次相机变化立即重算指针世界坐标，保持预览和实际落点一致；缩放、平移、详情开合都不探索地图。框选或右键方向拖动期间锁定镜头，避免编辑中目标漂移。

物理玻璃输入与地图共用当前 CRT 映射。触控板平移保留 GUI 的原生滚动量，另将地图位移换算为源画面像素。指针离开玻璃时清除未提交交互，玻璃外释放送到画面外，防止边框松开时误下令或误点按钮。

### 15.3 选择与命令反馈

近景编号采用避让布局，绘制和拾取使用相同矩形；全图聚合遵守 14.2。己方标记以已知位置为锚，不要求其整个点击矩形落在已探索地形内。死亡队员自动退出可下令选择，数字键和队员卡仍能定位尸体。多选中其余存活成员继续接受指令。

指针移动和目标标记先响应，耗时查询在预算内推进，超过 100 ms 才显示“规划中”。状态明确区分可执行、未探索、没有已知路线及具体失败原因。预览离开完成状态时立即撤下旧路线；当前可见路线用实线，灰区用较淡虚线。多人分配整体出现、整体入队。

右键按下时锁定执行者、目标格和追加／替换意图，拖动只编辑朝向。反馈同时显示真实接管结果、已安装队列项数和等待计算人数；界面不把全局查询队列当成玩家命令数。旧计划挂起与新指令计算分别说明。警戒位置吸附格中心，再在至少 0.25 米之外选择方向；右键移动拖出至少 0.5 米才指定路段朝向。

取消未提交工具或预览不撤销已接收命令；停止沿用正式计划链路。恢复焦点不重复提交松开事件。遇到新发现堵路时更新知识和计划，并说明原因；不暴露视野外变化。远近切换保留位置与任务连续性，模拟层级与查询统计只放在本地调试显示。电话、闹钟等舱室物件不参与地图规划队列。

## 16 接口和数据迁移

继续以 SCWorld、SCGrid、SCPlanner、SCPerception、SCActor 为职责边界，不新增通用事件总线或平行导航框架。

必要的内部调整集中在以下四处：

1. SCGrid 提供紧凑格数据与带明确语义的查询入口，区分玩家知识快照查询和真实世界查询，迁移直接读取 cells 字典的调用点；nearest ray、全命中和移动扫掠的结果契约保留。
2. SCPlanner 使用统一请求和结果状态，明确区分规划中、完成、不可达、取消和失效。现有 submit、队列和执行入口接上同一请求生命周期，不用空路线同时表达多种状态。
3. SCActor 与 SCEntity 收拢身体、能力及空间变更通知，所有写点使用同一失效规则。
4. 角色效果接受外部世界或真实事件；射场靶标适配留在射击工具，不继续藏在通用角色构造中。

数据和调用点在同一阶段迁移到当前契约。正式设计不保留旧结构兜底、双套缓存或只供旧数据使用的兼容入口。

## 18 实操验收与性能观察

### 18.1 运行条件

使用当前默认舱室入口、目标机接电和 2560×1440 预算，记录实际窗口和 Retina 渲染条件。场景包含道路、建筑、房门、家具、可破坏遮挡和窄路，不能用空白 500 米平面与 70 个静止模型代表目标负载。

常规帧时间以未开启函数采样的运行记录为准；函数采样用于定位热点，单项临时关闭用于渲染归因。内部直接改状态的观察注明条件，不替代正常玩家流程。

### 18.2 验收场景

| 场景 | 必须观察的结果 |
| --- | --- |
| 70 人分散活动，附近和远方各有交战 | 所有角色任务持续，只有相关地点精细化，声音和伤亡不依赖玩家镜头 |
| 70 人聚集可见，多数未交战 | 可见人物不丢失，指挥名单不混入NPC，拥挤和到达正常 |

| 大面积探索与灰区返回 | 记忆正确，隐藏门变化不提前影响路线，实际发现后更新 |

首轮常规交战负载固定为：玩家附近 4 名受控队员对 4 名敌人，远方另有 4 对 4 的交战，共两处、16 名交战角色，其余 54 人继续活动。连续观察 120 秒，记录实际精细人数、武器配置、活动子弹量和建筑遮挡条件。多处交战合并与 70 人密集可见另记边界结果，不与常规负载混报；每次调整场景配置都保留实际条件。

### 18.3 首轮工程指标

- 常规负载目标为 60 FPS；记录帧时间分布与最长停顿，不只报平均 FPS。
- 普通局部预览以 100 ms 内完成为目标，典型跨区正式规划以 500 ms 内完成为目标；等待期间保持可取消、可响应。
- 游戏交互的单帧超过 50 ms 时记录触发原因。搜索、缓存构建、回溯和发布都在观察范围内。
- 初始主线程常规预算按 8 ms、GPU 按 12 ms 分别观察；两项存在流水并行，不直接相加推导最终帧率。
- 统计查询请求、实际搜索、展开节点、结果复用、失效原因、待处理年龄、精细人数、活动子弹、块驻留和缓存字节。
- 记录每显示帧模拟步数、discarded_time，以及扣除暂停后的世界时间与实际经过时间之比。当前更新最多追赶 5 步并丢弃超时，优化验收须确认常规负载没有持续丢时或模拟慢放；显示 60 FPS 不能单独证明世界正常推进。
- 未完成搜索不能因时间目标到达而报告不可达；超过目标应优化计算或明确实际边界，不能省略合法结果。

完整 demo 完成前，验收以正常入口运行、实际操作与画面验看为准。不新增自动断言套件、模拟夹具、批量数值回归或旧版本对照来替代实操。尚无正常入口的规则明确列为未验证。

## 19 风险与实现约束

1. **知识泄漏**：真实图、隐藏门状态、未见角色占位、轮廓和标签不能经规划或显示泄露。
2. **局部失效不完整**：门、损毁、移动与新增移除的入口都须审计；路线可通行与仍最短使用不同校验。
3. **请求饥饿**：无关角色移动不能不停重启长搜索；过期结果也不能安装到新队列。
4. **远近交接重复执行**：世界时钟、控制器所有权与资源提交必须一次交接。
5. **显示与逻辑错位**：迷雾、人物、mask 和输入映射使用同一版本与坐标。
6. **大规模密集退化**：70 人聚集和多处战斗要实际量测；空间索引不能消除所有同地交互成本。
7. **工具入口分叉**：射场的外部武器时钟和临时调参写点都要纳入快照失效，不能只优化默认场景。
