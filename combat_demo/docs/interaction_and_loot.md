# 通用交互、物品搜索与现场转移规则

日期：2026-09-07。用途：交互与现场物品转移规范。1.5 已实现的范围和参数见第 11、12 节；涉及撤离、仓库、直接队内交接和存回容器的条款属于后续阶段。

用户已确认：Pygame 只承担功能演示，后续转向 Godot；保留多角色指挥、战术暂停、永久阵亡、装备损失与分批撤离。宏观指令和微操均支持搜索物品；搜索读条完成后自动暂停并打开携带分配界面。指定谁拿取，就必须由谁到现场完成拿取。

本文件替代 `player_experience_review.md` 中关于“第一版只做单容器微操搜索”的建议，并细化其对象、携带与颜色规则。已确认原则与未定参数分别记录，避免把设计当作运行现状。

## 1.7.1 地图编排修订（2026-09-08）

遵循用户确认的原则：右侧按键栏仅承载低频设置或重要操作，高频空间操作直接在地图完成。本节替代下述 1.7 的站位/朝向输入方式。

- 左键点击队员、计划编号，或数字键选择编辑对象。左键拖动不再移动计划标记。
- 门外准备和进门就位均复用普通移动的 `move_drag` 与松开事件：右键按下的位置是该阶段的新站位；拖出半格则以按下点到松开点的方向指定朝向，松开后一次性校验并修改位置和朝向。
- 不拖动时移除该队员在当前阶段的自定义朝向，使用原规划器的默认朝向。在原计划位置右键拖动可原地调整朝向。
- Esc、地图外松开、切换队员或阶段会取消当前拖动；拖动期间暂不平移/缩放地图。其他队员和另一阶段站位不受影响，实际指令在点击下达前不变。
- 地图指针附近直接预览目标、路径、朝向和非法原因。一次放置或拖动是一次撤销操作。
- 删除右栏位置/朝向按钮及其专用选点工具。阶段、顺序、同步、下达和退出等继续使用现有入口。

## 1.7 编排交互修订（2026-09-08）

本节按用户确认的 UI 改造实施，替代 1.6 的全局快速/编排开关、点真人退出草稿和长滚动编辑面板。

- 门与房间行动统一显示在右栏：先选择动作，再选择明确的“立即下令”或“编排站位”。房间操作增加地图左上入口，保留 Ctrl＋右键；房间名称仍不拦截普通移动。
- 编排自动暂停、聚焦入口。门外准备、进门就位、闪光落点分别编辑；当前阶段编号保持可读。四名队员和提交区固定可见，同步、入口、方式等放入计划设置。
- 点行、真人、队员卡或数字键只选择编辑对象，不改变参与者或顺序；↑/↓ 独立排序。位置/朝向可直接拖动或显式选点。无工具时普通空地点按不丢草稿，工具中右键仅取消当前选点。
- Ctrl+Z 撤销草稿调整；退出保留一份本局草稿，恢复前调用原规划器重新验证。新关卡清空草稿。退出编排恢复原视野；编排内也可随时返回原视野或聚焦入口。
- 非法编辑不改变原草稿，反馈明确“修改未生效，保留原设置”；提交区显示当前替换/追加、同步、后续行动及影响成员。编辑期间 Shift 不覆盖面板中明确的追加设置。
- 编排中恢复时间和个人命令快捷键不会绕过草稿；先下达或退出。下达后仍暂停，空格执行。快速命令保留运行中的即时下令；快速闪光选择合法落点后下令。
- 事件/设置往返保留草稿，待处理物资通知不会自动替换正在编辑的草稿。物资自身的现场拿取、指挥权接管和资源规则沿用原实现。
- 本次只编辑未提交草稿；已执行任务仍使用现有取消/继续机制。

## 1. 三种不同的结果

| 行为 | 改变什么 | 不产生什么 |
|---|---|---|
| 搜索完成 | 小队获得对象内容的情报 | 不自动把物品放进搜索者背包 |
| 玩家双击物品或右键选择拾取者 | 建立拿取计划，预约物品与接收者容量 | 不改变实物归属、当前负重或武器状态 |
| 现场拿取完成 | 物品从来源转入实际执行者的携带清单 | 不自动装备新武器，不替其他人远程搬运 |

示例：A 搜索柜子后发现一把武器，玩家分配给 B。此时柜子仍持有武器，界面写“待 B 拿取”。恢复模拟后，B 走到柜子的合法交互位置，完成拿取动作，武器才归 B。A 不会先得到一份武器，也不需要通过虚构的队内交接把它传给 B。

若 B 在抵达或拿取完成前阵亡，武器仍在柜子；若 B 已完成拿取后阵亡，武器进入 B 的尸体容器。前后顺序依据模拟实际完成时刻，不根据分配界面的最终意图推定。

## 2. 物品与对象的共同约束

1. 每件非堆叠装备有唯一身份，保留其实际状态。两把步枪不是同一份装备记录。消耗品可以按同类、同状态合并数量，转移时不得产生或丢失数量。
2. 物品在任一时刻只归属一处：角色、固定容器、尸体容器、地面物品堆或局外仓库。
3. “可交互”表示对象提供动作；是否阻挡移动、视线和弹道分别由对象的环境属性决定。搜空柜子不会让其实体消失，打开背包界面不会改变门的碰撞。
4. 固定容器从一条直边相邻的合法站位操作；尸体与地面物品堆还允许同格操作。墙和关闭门阻止隔边交互。八方向移动不赋予隔斜角取物能力。
5. 角色必须活着、能执行当前动作、位于合法交互位置，才能开始并完成搜索和转移。无法接近时显示原因，不生成远程取物结果。
6. 指令引用具体对象和物品。对象位置、门状态或站位占用变化后重新求合法接近位置；不能仅凭一份旧坐标完成交互。
7. 同一角色同时只执行一个占用身体的动作。翻找与拿取期间不能同时射击、换弹或操作另一个对象。
8. 所有物理动作消耗模拟时间。暂停只允许查看已有情报、编排和预约，不推进搜索、拿取、交换、放下、装备或撤离。

## 3. 统一动作

| 动作 | 前提 | 完成结果 |
|---|---|---|
| 接近对象 | 存在到合法交互站位的路径 | 角色到场，物品不转移 |
| 打开 / 开始翻查 | 对象允许此动作，角色在场 | 对象记录曾被打开或翻查，内容尚未必揭露 |
| 搜索 | 角色在场且目标仍有未知内容 | 读条完成，内容情报揭露，产生等待分配事件 |
| 从对象拿取 | 角色在场，来源有指定物品，容量足够 | 指定物品由来源转入该角色 |
| 放入对象 | 角色在场，自己持有物品，目标可接收 | 指定物品由角色转入对象 |
| 放下 | 角色位于有效地面 | 物品进入脚下地面物品堆，同格已有物品堆则合并清单 |
| 队内交接 | 交接双方到达相邻且无阻挡的位置，双方可完成交接动作 | 物品从交出者转入接收者 |
| 装备 | 角色已携带装备，装备槽条件满足 | 切换实际装备状态；不会把尚在远处柜子里的枪装备到手上 |

这些动作是现场约束的组合。宏观任务负责分工与顺序，不能直接改库存来跳过动作。复杂策略由位置、容量、耗时、知识、伤亡和命令优先级共同产生；具体执行者与目标仍由确定的指挥规则选择，不能以“涌现”为由省略规则。

## 4. 黄色标识

黄色只表示可搜刮对象，门和撤离点继续使用各自的标识，不能因为门也能打开就混入战利品配色。

| 对象状态 | 地图颜色 | 额外信息 |
|---|---|---|
| 已发现、从未打开的固定容器 | 亮黄色 `#FFE45C` | 容器轮廓；悬停显示未搜索 |
| 已打开过的固定容器 | 暗黄色 `#927A2C` | 显示未搜完、已搜索或已取空；关闭后也不恢复亮黄 |
| 已发现、尚未翻查的尸体 | 亮黄色 `#FFE45C` | 尸体轮廓；身份按小队已知信息显示 |
| 已开始翻查的尸体 | 暗黄色 `#927A2C` | 搜索进度及已知内容状态独立显示 |
| 有可见散落物品的地面物品堆 | 亮黄色 `#FFE45C` | 物品堆符号；没有“打开”动作 |
| 已取空的容器或尸体 | 暗黄色 `#927A2C` | 加“空”标记；尸体减速、家具阻挡保持 |
| 已取空的地面物品堆 | 不绘制 | 对象移除，不留下可点击的空物品堆 |

颜色表示是否打开或翻查过，不表示是否安全，也不等于是否还有物品。搜索开始后被中断的容器仍保持暗黄，并明确标注“未搜完”，不能仅凭颜色让玩家误以为搜索完成。

亮黄、暗黄是对象轮廓和图标的固定色。被选中和被悬停时另加外框，不覆盖这一状态色。常规文字保持可读的文本色。

以上只绘制小队已发现的对象及其已知状态。不能通过隐藏容器变色、实时数量或按钮可用性获知视野外新事件。远处记录必须标成“上次查看”，内容变化只有再次合法观察或搜索后才更新。

## 5. 微操搜索

流程：选定角色 → 右键容器或尸体 → 搜索 → 接近 → 读条 → 自动暂停 → 分配界面。

微操明确一名搜索者；多人选择时先在菜单中指定执行者，不能暗中让全队都围过去翻查。搜索者原有宏观行动按既有微操接管规则取消整组，提交前显示受影响成员；未关联的队员保留原计划。

搜索不要求搜索者有剩余携带容量，因为物品可稍后交给另一名到场者拿取。空背包不是翻找柜子的前提。

已搜索且没有新增未知内容的对象不重复读条，直接打开已知清单。远处打开清单只查看记录；现场拿取仍需接近。可见散落物品没有翻找读条，右键查看后可安排拿取，并在打开分配界面时暂停。

## 6. 宏观搜索

新增独立的“搜索区域物资”宏观；原有房间检查命名为“检查威胁”，不能继续用同一“搜索”标签混指两种行为。

玩家指定区域、参与者和各自的搜索或警戒职责。系统在该区域内组织既有的接近、观察、搜索与拿取动作；只能从小队已发现对象中挑选目标。尚有未检查位置时，可通过现有区域观察点移动来发现对象，不得读取隐藏容器列表来提前挑选最值钱目标或宣称物资已全部搜空。

同一容器只安排一名搜索者；不同容器允许不同参与者同时搜索。候选按该角色到合法交互位置的预计耗时排序，同耗时按对象 ID 排序。共享目标用预约避免重复分工。警戒者的职责明确显示，不被自动借用为搜索者。

宏观中的每次搜索完成，使用与微操相同的自动暂停与分配界面。宏观进入“等待物资分配”正常阶段，不能显示成受袭导致的“已挂起”。该对象未处理的分配决定保留，不自动拿走，也不跳过它继续为同一搜索者安排下一对象。

关闭当前容器窗口并恢复时间后：有拿取任务的成员执行接近与拿取；没有后续动作的搜索成员可继续下一目标；独立的其他成员无需等整组搬完才工作。下一次搜索完成仍触发暂停。警戒者被分配拿取前，界面必须显示该人将离开警戒位。

### 分配与微操接管的边界

同一宏观内部给本任务参与者安排拿取，属于编辑这个任务的下一阶段，保留任务归属。它不能走一条“新微操接管”路径而取消自身。

为任务外成员安排拿取，属于向该人下达新的微操。分配界面显示“另行派人”及接管影响；若他参加另一宏观，成功提交时取消那个关联宏观。不能暂时借人、藏起取消后果，或事后自动恢复已经取消的行动。

若使用独立微操搜索结果给某人安排拿取，也遵循同一微操接管规则。界面形式不决定优先级，命令属于哪个计划决定优先级。

## 7. 搜索完成后的地图容器窗口

1. 搜索完成请求自动暂停。窗口直接出现在地图内，不遮暗全屏，以引线连接目标容器；目标在画面外时引线端点限制在地图边缘。窗口避开顶栏、队员卡和侧栏，最多显示五行，更多物品滚轮翻页。
2. 标题显示容器名称和当前交互角色。搜索结果使用实际搜索者；重新查看已知容器时，在对象菜单选择查看者。多人选择不暗中指定全队或第一人。角色阵亡不自动更换执行者，可右键选择其他存活角色。
3. 物品逐行显示名称、数量和重量，不铺设四个角色按钮。左键单击没有指令副作用；同一行、相距不超过 6 屏幕像素、300 现实毫秒内左键双击，立即安排当前交互角色拿取整件或整堆。
4. 右键物品使用原有上下文列表选择其他角色；显示拿取后预计负重（包含已有预约），容量、可达性、阵亡、重复预约失败原因，以及当前条目的指令接管／离开警戒位提示。取消角色菜单不下令，且不改变原小队选择或当前交互角色。
5. 每次下令即进行校验并建立物品与容量预约，无二次“确认安排”按钮。实物仍在来源，行内显示“已安排 N 号”；已预约行仍可双击改派给当前交互角色，或右键选择另一人覆盖拿取者；行内提示可改派。重复选择同一人不增加预约、不重建节点、不重置正在执行的拿取读条。
6. 连续为同一角色安排同一来源的物品时追加拿取，不覆盖前面预约，个人队列仍最多八项。首次外部拿取沿用整组宏观接管；宏观内部逐项分配保留本任务归属。
7. 关闭按钮或 Esc 关闭当前窗口，完成该来源的分配决定；未安排的物品留在容器，已安排的指令保留，仍保持暂停。玩家按空格后执行。窗口开启时空格不推进时间，地图点击不会穿透下令。角色菜单开启时 Esc 先关闭角色列表。
8. 同一步多个搜索仍只有一次暂停；“下一个”按完成时间、对象 ID 切换待处理来源，不清空已有预约。未关闭的其他来源保留等待，可通过 L 返回。已关闭来源可再次右键查看，关闭一个来源不结束其他来源的决定。
9. 终局处理仍优先于搜索弹窗；不因窗口产生库存转移、模拟进度或隐藏情报。

### 更换拿取者（1.5.2）

改派仅适用于实物仍在来源的物品。先校验新角色的存活、路径、容量和队列限制，全部通过才替换旧预约；失败保留旧角色的节点、动作进度和物品预约。同一角色的预计负重不重复计入已有预约。

改派只移除这件物品对应的旧拿取节点和容量预约，其他物品继续原安排。若旧角色正在拿取，取消该读条；若正在接近，停止旧后续路线，已经开始的单格移动沿用既有完成规则。新角色按完整动作耗时到场拿取，不继承旧人的读条进度。

宏观内部更换角色保留原搜索任务，即使容器窗口已经关闭、再次打开，也从原拿取节点识别任务归属。任务外新角色仍按现有微操接管规则处理其旧宏观；不能借改派绕过指挥权规则。已经完成现场转移的物品不能用容器记录改派。

### 指挥与分配信息（1.5.3）

本轮获用户同意后落实操作清晰度建议，不加入撤离或局外系统。

- 原“关闭”明确为“完成此处分配”，Esc 保持同样行为。新增“仅查看下一处”和“完成此处并处理下一处”：前者保留当前等待，后者结束当前来源决定并打开下一待处理来源，最后一处完成后关闭窗口。所有路径保持暂停，已有拿取预约保留，未安排物品留在来源。
- 首次给搜索者本人安排拿取，允许替换旧搜索微操，但不能提前清除当前来源的待决定记录。窗口显示全局等待来源数。
- 已预约行右键增加“撤销此件拿取安排”，复用改派已有的单件转移取消逻辑：仅移除该转移的节点、动作和容量预约，保留其他物品预约与所属搜索宏观。物品仍在来源，不撤销已完成转移。此入口属于分配编辑，普通微操接管和宏观节点删除仍取消整组。
- 容器右侧为只读分配参考。悬停物品和拿取候选人，显示当前职责、伤势、到来源的直线距离（不作路径或可达承诺）、实际负重、已有预约和本次预计负重、当前武器与待拿武器、接管或离开警戒位的影响。人选菜单限制在地图区域，避免遮住参考信息。
- 可从分配参考或常规指挥打开独立“伤势与携带详情”。详情中可只读切换四人、滚动携带清单，不改变原小队选择、当前交互者或预约；关闭返回原分配窗口。打开详情暂停，从指挥打开时返回原时间状态，从分配打开时保持暂停。
- 指挥右栏优先显示任务、挂起原因及继续入口；无待同步行动时隐藏对应放行行。任务区域可滚动，挂起宏观排在前面。身体详情入口固定存在，不受八项队列影响。队员卡区分前往警戒位和已就位，伤势标出部位；换弹／包扎按钮标出符合条件人数。
- 容量拒绝显示缺少空间并解释必须先完成放下动作。整堆转移、不可拆分、现场执行与18 kg参数保持现行规则。

## 8. 预约、执行失败与中断

### 1.6 快速／编排计划与地图尺度

日期：2026-09-08。用户确认两种计划、站位编辑和地图／屏幕尺寸边界。

- 房间与门的操作侧栏提供快速模式、编排模式；首次默认快速。突入后行动明确为“就位警戒”或“检查威胁”，界面首次默认就位警戒。前者到达进门后的站位和朝向后结束宏观，留在现场观察；后者继续原观察点检查流程，只有检查通过才更新威胁检查记录。
- 快速模式选择门口行动方式后直接提交，闪光突入在合法落点点击后提交；暂停时只下令，不推进动作或消耗道具。道具落点选完不再要求额外确认。
- 编排模式保留独立草稿和统一提交。可以在地图点击连接目标房间的入口，或明确选择“反向进入：某房间”；更换入口／进入侧会重置站位与朝向编辑、清空投掷落点。不可突入的一侧禁用。改变突入方式、进入顺序、同步和后续行动不静默丢弃自定义站位；校验失败保留上一份有效草稿并提示。
- 门外集结位用橙色方框，进门后就位点用青色菱形。左键拖动标记修改位置，右键拖动修改朝向；侧栏也提供逐人选位置／朝向入口。普通点击真实队员仍选择队员并退出未提交草稿，框选和数字键沿用原选择逻辑。右键拖动计划标记不下达普通移动命令。
- 自定集结位须在入口外侧区域且可从角色起点到达；进门后就位点须在目标区域、从入口内部可达且不占入口格；同阶段站位不可重叠。投掷从自定义投掷者集结位重新校验。第一名仍需到门前执行开门／踹门，再进入。提交复核后保留自定义站位和朝向，校验前不取消旧计划。
- 自定义站位被占用时不自动换位；沿用既有行进停滞检测与挂起／手动恢复。自动分配的站位仍沿用已有近邻避让。就位后的自动交战继续遵守原规则。
- “在房间内警戒”复用选位置→选朝向流程，不再硬编码房间中心。选点阶段校验房间与多人目标范围，障碍物不能作为站位。
- 角色、物资、计划标记、选择框、朝向箭头、家具内边距按世界尺寸投影；箭头长1格、箭头翼长0.25格，计划标记半径0.34格。普通移动定向拖动阈值为世界距离0.5格。鼠标位置转换为世界坐标后用于站位／朝向编辑；拖动期间不缩放或平移地图，窗口改变取消拖动。
- 文字、线宽、HUD、菜单、进度信息保持屏幕可读尺寸。缩小到每格20像素以下，非悬停计划标记省略文字；不改变标记实际位置。小目标保留6屏幕像素的点选容差（门为至少4像素），这是输入便利，不改变角色碰撞体或计划站位。

### 1.5.4 焦点与房间输入修订

用户确认采用 Ctrl 房间操作与基于焦点的右栏。本节替代此前右键房间名称的入口规则。

- 名称只显示，不参与命中判定，也不绘制遮挡格子的背景。普通左／右键继续命中队员、门、物资或地面；鼠标接近名称时隐藏，Ctrl 期间显示目标房间名称与边界高亮。
- 战局地图中 Ctrl＋右键按鼠标所在格确定区域，优先于该格队员、门或物资，打开该房间右栏。地图外或没有区域的格不打开房间；物资分配与模态详情期间保持输入隔离。Ctrl+A、Ctrl+F1/F2 原功能保持。
- 无选择时右栏仅显示战局概况与固定入口；有队员焦点时显示个人／批量操作，右键个人菜单的侧栏与快捷键都使用该人，不改变原多选。房间焦点显示房间信息、行动及原所选参与者；物资和门菜单复用原有动作作为对应对象的侧栏。突入草稿优先显示编排与下达。
- 焦点由点击对象、打开操作或选择队员决定；鼠标悬停不改变主焦点。关闭房间操作返回原选择；选择其他队员清除房间焦点。悬停分配人选仅更新物资参考。
- 待分配和近期事件入口常驻右栏底部，草稿提交区上移避免覆盖。事件使用只读暂停窗口，返回恢复原菜单／房间／草稿和先前暂停状态；分配中查看事件返回仍暂停，保留分配预约。

每次双击或右键选人成功时预约来源的具体物品或数量，同时预约接收者所需容量。预约只限制重复安排，不改变实物归属。武器保留身份、弹药与装备状态；拾枪不能仅给步枪数量加一。

开始拿取和完成拿取时均检查：执行者存活、当前动作合法、现场距离与遮挡合法、来源仍持有该物品、预约属于此计划、接收者容量足够。全部成立后，一次性从来源扣除并加入接收者；不存在先删物品再发现背包装不下的中间结果。

一次拿取动作处理一件独立装备或一条指定数量的堆叠物品。同一角色拿多件物品按逐项下令顺序执行；已经拿到的物品不因后续动作失败而回滚。

| 事件 | 结果 |
|---|---|
| A 搜索后离开 | 已知内容保留，物品仍在原容器，B 可继续到场拿取 |
| B 途中被玩家接管 | 按原有计划归属取消关联动作，释放未完成预约，物品留在来源 |
| B 途中阵亡 | 释放该人未完成预约；尚未拿到的物品留在来源，已经携带的物品进入其尸体 |
| 门关闭、交互位被占 | 重新检查合法站位和路径；无法继续则显示原因，不隔墙取物 |
| 拿取时受到导致中断的伤害 | 该次未完成转移不生效，计划按现有受击中断规则处理 |
| 来源物品已不存在或状态不匹配 | 本次拿取失败并显示具体原因，不自动用别处的同类物品替换 |
| 容量变得不足 | 不执行转移，显示缺少容量；不自动丢弃已有物品 |
| 取消计划 | 释放未完成预约，保留已发生的开门、搜索情报和物品转移 |
| 暂时挂起 | 不推进动作，保留仍有效的预约；恢复前重新检查条件 |

同样的检查用于柜子拿取、尸体回收、地面拾取、放下和队内交接。宏观命令不能放宽条件。场内物品只有随携带者完成撤离才进入仓库，分配界面不能把物品直接送回局外。

## 9. 用于验证规则组合的场景

- A 搜到武器，B 从另一房间来拿：暂停确认时来源和 B 的真实负重均不变；B 到场完成动作才增加负重。
- A 背包已满仍能搜索，分配给有空间的 B；B 的空间同时被另一份已确认计划占用时，后提交的安排必须被拒绝。
- B 途中阵亡，C 可以重新预约柜子里的武器；没有复制、丢失或自动转交。
- A 已搜索但未取空的柜子保持暗黄，能直接查看并再次安排拿取。
- 玩家先放下弹药腾出空间，再拿武器：空间必须由放下动作实际完成产生，不能在编辑草稿时凭空腾出。
- 同一步两人完成不同容器搜索，只有一次暂停，但两个来源都能分配。
- 同一搜刮宏观把拿取交给自身成员，不取消自身；指派任务外队员时明确显示其旧宏观将被取消。
- 尸体落格、尸体减速、八方向墙角规则与物品交互距离分别生效，不因尸体可跨过就允许隔墙搜身。
- 第一批队员带物资撤离，仓库接收他们实际携带的物品；留场成员继续搜索时，已经撤离者不能再被选作携带者。

## 10. Pygame 演示与 Godot 迁移

根据当前项目结构，迁移属于可控的移植工作，并非直接转换文件。现有 `simulation` 未依赖 Pygame 绘制接口，已分开的规则、数据概念和行为测试场景有保留价值；界面、输入、音效、场景组织和发布流程需要在 Godot 中重新实现。

Godot 官方支持 GDScript、C#、C++，Python 并非内建脚本语言。因此不把“原 Python 代码直接嵌进 Godot”作为默认路线；实际选择 Godot 开发语言时再确定移植方式。[官方语言说明](https://docs.godotengine.org/en/stable/about/faq.html#which-programming-languages-are-supported-in-godot)

建议 Pygame 后续只证明规则和关键操作，不投入大量美术或自制复杂 UI 框架。移植时先做同样的一间房、两名队员、一个容器，验证 A 搜索、B 到场拿取、受击中断与尸体回收，再扩展完整循环。

规则边界继续保持：界面提交意图 → 计划组织动作 → 世界验证并执行 → 结果事件通知界面。搜索完成请求暂停的事件由世界发出，物资分配面板负责响应；模拟规则不直接创建 Pygame 窗口。Godot 可配置暂停时继续处理 UI，这能承接相同流程。[官方暂停说明](https://docs.godotengine.org/en/stable/tutorials/scripting/pausing_games.html)

复用现有命令、身体动作、可交互对象和库存预约结构。新功能确实需要补充对象库存、可转移装备身份和来源／接收者信息；这是一组共同的数据能力，不为柜子、尸体、散落枪支分别做一套库存。无需预先引入通用自主规划框架或重写全部模拟架构。

迁移验收以相同场景下的行为规则为准，不承诺跨语言随机数与浮点运算生成逐帧完全相同的轨迹。需要可复现随机战斗时，必须单独规定随机算法和调用顺序。

## 11. 1.5 实现参数

| 参数 | 实现值 |
|---|---|
| 固定柜子与地面补给箱搜索 | 3 秒 |
| 尸体搜索 | 2 秒 |
| 每件装备或每条堆叠的拿取、放下、装备 | 各 0.6 秒 |
| 伤势影响 | 上述时长除以执行者当前操作效率 |
| 每名队员携带容量 | 18 kg；计算装备中主武器、全部弹药、耗材和携带物 |
| 步枪空枪／每发步枪弹 | 3.8 kg／0.012 kg；枪内子弹仍计入负重 |
| 每枚闪光／每份包扎／每份零件／每份档案 | 0.4／0.2／2.0／0.3 kg |
| 尸体格移动速度 | 正常地面的 60%；仅角色中心所在格生效，同格不叠加 |
| 尸体摆放半径 | 从死亡锚点按八方向几何路径距离最多 2 格，同距按 y、x；没有空位则原锚点叠放 |

移动寻路成本为每段几何长度乘以起点、终点速度倒数的平均值。它估计角色中心在两格各走半段的耗时，不改变八方向几何距离及墙角判断。

## 12. 1.5 可运行范围与操作

- `simulation/loot.py` 管理固定容器、地面补给箱、尸体、地面物品堆的实物与小队记录。全高家具柜子只能相邻直边操作；补给箱占用地面格但不阻挡，可同格或直边操作。尸体、地面物品堆沿用同格或直边操作。
- S 区 `(35,31)` 有补给箱，包含弹匣 17 发的独立步枪、2 份包扎和 30 发弹药；`(37,31)` 有散落闪光。R、O、A、M、W、L、U、N 各有一个附着于原有家具的物资点，须合法发现后才绘制黄色标识。物资不随机刷新。
- 微操入口为右键黄色对象，选择一名搜索者；已知清单直接打开。重叠对象先列目标，避免尸体、活人、地面物相互遮住点击入口。搜索微操和拿取微操的接近阶段服从微操移动优先级；搜索／拿取身体动作受袭可中断。
- 宏观入口为右键区域名称 → 搜索区域物资 → 全员搜索，或编号最大的所选成员原地警戒、其他成员搜索。所选参与者须已经在该区域。警戒者不分配观察点和自动搜索目标；手动分配其拿取会离开原位，拿取后在到达位置警戒。系统沿用观察点分工，并从当前已发现对象中按路径成本、对象 ID 挑选目标。结束表示本次路线与决定已完成，不表示隐藏物资永久搜空。
- 搜索结果使用第 7 节的地图容器小窗口：引线定位、双击当前角色、右键选择其他角色、逐项预约、关闭后恢复执行。
- 宏观内部逐项拿取保留任务，外部首次拿取接管旧任务；同来源连续拿取追加。关闭处理当前来源，其他待处理来源仍可按 L 返回。
- `I` 或个人菜单“携带物品”可查看、放下、装备。换枪交换装备中武器和携带中武器，保留各自弹匣；角色原有储备弹药跟随角色。主武器不能直接丢弃；先装备另一把后可放下旧枪。耗材沿用原有数量与使用预约，放下只处理未被使用动作预约的数量。
- 取消和死亡释放未完成拿取预约。死亡仅生成一次尸体；实际携带的枪、弹药、耗材进入尸体，尚未拿到的留在来源。搜空尸体仍减速，搜空地面堆移除。
- 原有威胁检查阶段与记录已改名。修复菜单开启时暂停按钮无效、个人菜单快捷键作用错人、混用鼠标键盘时失效子菜单崩溃、批量换弹／包扎因不需要动作的人而整组失败。多人移动预览与提交共用落点分配；卡片常显负重及最低身体部位状态；近期事件可展开最近 11 条。
- 战斗目标仍为消灭 10 名敌人。成功结果页可选“继续搜索物资”，返回暂停状态；恢复后场内动作继续，可搜索最后阵亡敌人。后续“查看战斗结果”返回结果页。重开关卡重置本局。

未实现功能：分批撤离、局外持久仓库、永久人员档案、招募／成长、存回容器、直接队内交接、拆分堆叠、背包网格和容量装备更换。这些边界不改变本版已实现的现场距离、唯一归属、动作耗时和预约约束。
