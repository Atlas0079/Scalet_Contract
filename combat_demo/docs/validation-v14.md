# Demo 1.4：指挥与 AI 修订验证

日期：2026-09-06。当前规则为 `demo_design.md` 1.4 与 `command_and_ai.md`。本节是新版结论；下方 1.3 的通关、性能和稳定性数字保留为历史证据，不能当作 1.4 复验结果。

## 本轮交付

- 微操成功提交取消整组关联宏观行动，Shift 也执行接管；无效提交原子保留旧计划。独立行动不受影响，删除未来宏观不打断前置行动。
- 明确取消、挂起、计划内应对；未知来弹挂起关联计划，手动继续执行资源／人员／路径检查。自动换弹中断不误挂起正常交战。
- 听声观察与来弹方向搜索接通，禁止用隐藏攻击者坐标锁定；禁火保留观察反应。
- 普通移动结束不回初始方向；右键拖出至少 16 像素保存本段固定朝向；每段独立方向、Shift 按下锁定、松开提交、Esc 与越界取消。
- 队员卡分开显示宏观／微操状态及听声、受袭、交战反馈；菜单与选点显示整组接管影响。

## 自动化与实际渲染

59 项行为／界面检查通过，其中 25 项为本轮指挥、声音、来弹、恢复和拖拽专项。19 项原有场景检查通过，共 **78 项**。记录为 `artifacts/tests-command-ai-v14.txt` 与 `artifacts/legacy-command-ai-v14.txt`；最后界面调整后的 8 项复验为 `artifacts/interface-command-ai-v14.txt`。

`tools/capture_command_ai.py` 生成 `v14-drag.png` 和 `v14-suspended.png`，已人工查看图像，确认全组取消提示、方向箭头、挂起原因与队员卡反应文字可见。受袭截图使用明确设置的测试出生位置和禁火状态，随后通过真实模拟推进；不是原关卡通关截图。

# 1.3 历史验证记录（不代表当前版本）

日期：2026-09-06。实现依据为 `demo_design.md` 1.3。以下结果区分自动化、实际渲染与外部人工验收，不将脚本通关称为真人试玩。

## 已交付

- Windows 文件夹发布包：项目根目录 `release/ScarletContract/`，入口 `ScarletContract.exe`。根目录 `Start Demo.cmd` 可直接启动。
- 标题、配置选择、任务简报、开局暂停、完整战斗、歼灭结算、失败重试、设置与操作提示。
- 四人选择与编组、移动与朝向、8 节点队列、替换与追加、逐人接管、A/B 手动同步放行。
- 门的两层悬停菜单、可修改的行动草稿、入口与进入顺序、个人物品菜单、资源预约与无效提交保护。
- 集结、开门／踹门、闪光、依次进入、观察点搜索、已知威胁处理和受阻恢复。单人有独立开门、踹门、移动、射击和物品能力。
- 固定灰港地图及 A/B/C 敌情；视野、身份识别、历史目击、声音区域、敌人状态机、身体损伤和友军碰撞。

## 自动化检查

现有 19 项场景检查和新增 34 项行为／界面检查通过，共 53 项。原始输出在 `artifacts/legacy-checks.txt` 与 `artifacts/tests.txt`。

重点覆盖暂停冻结、唯一停靠点、原子替换、预留回滚、队列上限、格间取消、双入口同步、成员死亡恢复、单人继续作战、友军挡线、闪光遮挡与朝向、同种子重放、无状态泄露、菜单悬停与取消、个人执行者、扩展物品、最低分辨率提交按钮。

额外增加的成员死亡检查专门覆盖“第一名队员已进入、随后死亡”的恢复，防止旧进入索引和死亡成员残留阻止其余人完成搜索。转向检查确保计划、移动与交火共用每步转向额度，不叠加超过 240°/秒。行为测试不是对所有规格条目的逐像素或穷举证明。

## 通关记录

没有修改敌人 HP、装备数量、种子、胜负条件，没有跳过世界物理执行。驱动程序通过玩家 Planner 提交命令，在伤亡后显式继续或取消；最后一人使用单人移动、警戒和门操作。

## 渲染与性能

环境：Windows 11 build 26200，AMD Ryzen 9 8945HX，系统报告物理内存 49,078,083,584 字节；Python 3.12.14，pygame-ce 2.5.7。

测试使用真实 Pygame CPU 渲染和 SDL dummy 显示驱动，没有真实显示器交换链。标准特效、1440×900、配置 A、1 倍速；四名队员周期性移动，敌人感知和巡逻运行。结束其他验证进程后独立运行，排除 10 秒预热后采样 119.994 秒、7208 帧：

- 平均帧间隔：16.647 ms。
- 第 95 百分位：17.572 ms。
- 测试内丢弃的模拟累计时间：0.050 秒。

该独立离屏测试达到平均≤17 ms、P95≤20 ms 的目标。真实窗口呈现、垂直同步、其他机器与完整激烈交火的帧时上限未由此证明。首次采用不同于游戏主循环的 sleep 节拍测试未达平均目标，其结果保留为 `performance-initial.json`；最终脚本改用与游戏相同的 Pygame Clock 节拍。并行运行多个整关验证进程时曾测得平均 24.152 ms、P95 31.253 ms，不通过，保留在 `performance-loaded.json`。未改测试阈值。

稳定性：标题真实渲染运行 1200.15 秒，再连续重建配置 A 六次。四名队员、十名敌人、零未完成任务和零表现事件检查通过。第一次常驻内存 70.469 MiB，第六次 70.547 MiB，增加 0.078 MiB，低于 10 MiB 限制。记录在 `stability.json`。

## 实现说明与未完成的验收

- 窄屏中的长草稿采用滚动参数区和固定提交区。调整窗口尺寸时，原来处于全图适配的镜头重新适配，已经放大的镜头保留世界中心。
- 路径与菜单查询使用有界缓存。门或环境改变会使寻路缓存失效，视觉随机不消耗战斗随机序列。
- 源码保留旧地图工厂用于底层回归，正式入口只提供灰港三配置；没有恢复已移除的旧 AI 目录或添加旧道具计数兼容层。
- 当前未做外部真人首次体验、人工完整游玩 B/C、其他 Windows 机器兼容性、真实显示器呈现延迟和扬声器听感检查。这些项目仍是设计规格 18.2 的未完成验收项。
- 设置在当前进程内保留，关闭程序后恢复默认值；没有存档、地图编辑器、物品转移、护送或复活。
- 玩家需要根据受阻原因重新安排：例如道具执行者退出后，继续按钮会要求重新下达，不会悄悄更换执行者或省略闪光。

因此本交付是可运行、可通过全部三配置的 Demo；不将上述未执行的人工验收标记为已通过，也不宣称已经完成所有规格的穷举验证。
